# 管控台使用说明

本指南介绍企业管理员如何开通账号、添加团队成员以及查看积分消耗。

---

## 一、企业管理员账号开通 {#admin-account}

您提供的邮箱会收到一封包含管理员账号密码及登录地址的邮件，请根据邮件信息登录企业运营平台。

![企业管理员账号开通邮件](/guide/admin-email.webp)
_企业管理员账号开通邮件_

---

## 二、添加团队成员 {#add-members}

### 方式一：通过邀请链接邀请成员加入 {#invite-link}

复制邀请链接发给团队成员。

![邀请链接](/guide/invite-link.webp)
_邀请链接_

成员通过邀请链接申请加入后，在「待审批」列表中审批通过并选择角色，成员即加入成功。

![待审批列表](/guide/pending-approval.webp)
_待审批列表_

![审批通过并选择角色](/guide/approve-role.webp)
_审批通过并选择角色_

![成员加入成功](/guide/member-joined.webp)
_成员加入成功_

成员在插件中点击欢迎页的「登录」按钮登录即可正常使用。

::: tip 计费说明
管理员和普通成员均为计费用户。
:::

### 方式二：配置 SSO 登录 {#sso-login}

登录信息配置完成后，点击「测试连接」，连接成功即可正常使用。

![配置 SSO 登录](/guide/sso-config.webp)
_配置 SSO 登录_

公司成员在页面输入邮箱地址，点击「SSO 登录」。若邮箱地址符合 SSO 设置的邮箱，该成员即可自动加入团队。

![SSO 登录页面](/guide/sso-login.webp)
_SSO 登录页面_

管理员角色查看的是团队内所有的积分消耗记录；普通成员查看自己的积分消耗。

可按调用次数、日期和成员聚合查看积分消耗。

![查看积分](/guide/credits-view.webp)

## 四、用量统计 {#usage-stats}

「用量统计」页面集中展示企业的套餐产品、API 额度以及使用明细，帮助管理员了解资源消耗情况。

![用量统计](/guide/usage-stats.webp)
_用量统计_

### 套餐产品

展示企业当前生效的套餐，包含有效期、期数与坐席数等信息。

### API 额度

展示已分配额度、团队共用额度及剩余额度，支持额度分配。

- **额度分配**：给指定成员限制使用额度。
- **团队共用额度**：成员使用额度不限，共用公司剩余所有 API 额度。

点击「额度分配」可为成员分配 API 额度：选择成员并设置新分配额度，可开启额度限制，也支持「快速均分额度」。若本次分配超出团队剩余额度，保存将被拒绝。

![额度分配](/guide/usage-quota.webp)
_额度分配_

### 使用明细

- **套餐调用明细**：按调用次数统计，支持按调用时间范围筛选，可搜索模型、用户邮箱查看各模型的调用情况。
- **API 调用明细**：展示各用户的 Token 用量明细（输入、输出、显式 / 隐式缓存命中、缓存创建）。

### 效能与用量度量：分三层看 {#metrics-layers}

用量报表只能回答一部分问题。评估 AI 辅助研发时通常分三层看，**前两层我们直接供数，第三层需要和企业自己的研发平台打通**：

| 层次       | 回答的问题         | 数据来源                                            |
| ---------- | ------------------ | --------------------------------------------------- |
| 采用度     | 谁在用、用得多深   | 管控台（按成员 / 按时间的调用分布）+ 遥测的会话事件 |
| 用量与成本 | 消耗了多少         | 管控台的用量统计 + SDK 用量回调 / 遥测导出          |
| 交付结果   | 交付变快、变稳了吗 | 需要与企业自己的 Git / CI / 项目管理平台打通        |

- **采用度看的是趋势和阻力，不是考核**：用的人少，先去找原因（缺文档、缺权限、场景不匹配），而不是拿来做排名。
- **交付结果这一层我们不单方面提供**：交付周期、吞吐、稳定性这类指标来自企业自己的 Git / CI / 项目管理数据，需要与用量数据打通后一起看——这也是业界一致做法。

业界共识也支持这个口径：SPACE 框架指出**没有单一指标能刻画生产力**，建议至少跨 3 个维度测量；Google DORA 报告显示 AI 采用与交付吞吐可能正相关，但与**交付稳定性仍呈负相关**——所以 AI 使用指标必须和交付指标一起看。

#### 用量与成本

- **token 明细**：输入 / 输出 / 显式与隐式缓存命中 / 缓存创建，管控台「API 调用明细」按用户与模型展示。
- **按交互追溯**：SDK 中每条助手消息带各自的用量元数据，可追溯到具体一次交互；`onUsagesChange` 回调与 `get usages()` 方法支持把数据推给 / 取给企业自建平台（见下方「用量回调」）。
- **单次会话核对**：CLI 会话退出时按模型打印 token 总量摘要。

> 免责一句：代码行数是活动量指标而非质量指标——业界（含 Anthropic 自己的研究）都指出用它衡量生产力会高估，重构反而会减少行数。我们把它定位成参考，不作为绩效。

### 遥测导出（OpenTelemetry） {#telemetry-export}

除管控台页面之外，企业还可以把 Agent 侧的遥测数据接到自己的监控 / 数据平台，用于统一度量与排障，支持两种落地方式：

- **OTLP 协议**：导出到企业自己的 OTLP 收集器（Grafana Tempo、Jaeger、Datadog 等兼容后端均可），纳入既有的监控与告警体系。
- **本地 JSONL 文件**：写入 `~/.wave/telemetry.jsonl`，每行一条独立 JSON 记录，可直接 `tail` 观察或用 `jq` 解析、转发到下游。

可导出的内容：

| 类别    | 内容                                                                                   |
| ------- | -------------------------------------------------------------------------------------- |
| Traces  | 带 token 计数的 LLM 请求 span、带耗时的工具执行 span（一次用户交互的完整链路）         |
| Metrics | token 用量、延迟直方图、错误计数器                                                     |
| Logs    | `session_start` / `session_end` 等会话生命周期事件，以及工具权限决策、压缩等结构化事件 |

用户提示文本与工具调用内容**默认不导出**，需显式开启（`OTEL_LOG_USER_PROMPTS` / `OTEL_LOG_TOOL_CONTENT`）。导出器选择与完整配置项见[功能规格说明：OpenTelemetry 集成](/specs/enterprise/opentelemetry)。

### 用量回调（SDK 集成） {#usage-callback}

如果企业自建了度量平台或看板，也可以不依赖管控台页面，直接通过 SDK 取用量数据：

- **`onUsagesChange` 回调**：每次 AI 调用与消息压缩完成后触发，推送当前会话累计的用量数组，适合实时同步到自建平台。
- **`get usages()` 方法**：随时按需读取同一份数据，适合定时取数、生成报表或与外部监控系统对接。

接口定义与用法见 [SDK 文档 - 回调系统](/sdk#agent-callbacks-interface)，数据范围与边界见[功能规格说明：用量追踪](/specs/enterprise/usage-tracking-callback)。

### 隐私与治理 {#telemetry-privacy}

三点先说清楚：

- **默认不采集提示内容**：遥测**默认不记录**用户提示文本与工具调用内容，只有显式开启 `OTEL_LOG_USER_PROMPTS=1` / `OTEL_LOG_TOOL_CONTENT=1` 时才会包含。默认配置下 `user_prompt` 事件不含提示原文。
- **按团队聚合呈现，不做个人排行**：用量数据用于容量与成本规划、定位使用阻力，不做个人产出排名。
- **管理员可统一下发遥测配置**：管理员可通过服务端托管配置统一下发遥测参数（托管配置的 `env` 键按同名覆盖成员本机值），无需逐台机器配置。

遥测**默认关闭**：不配置导出器时不会产生任何遥测数据；只有企业自己配了 OTLP 端点或 JSONL 导出器，数据才会流向企业指定的目标（端点为自建时即企业自己的收集器；落文件则留在成员本机 `~/.wave/telemetry.jsonl`）。依据见[功能规格说明：OpenTelemetry 集成](/specs/enterprise/opentelemetry)。

## 五、订单管理 {#orders}

「订单中心」页面展示企业购买的全部套餐订单，可按合同号、产品名、备注搜索。

![订单中心](/guide/orders.webp)
_订单中心_

订单列表包含合同号、类型、产品信息（套餐类型、时长、坐席数）、有效期、金额、状态及备注等信息。
