# 研发知识库：团队知识如何进入 AI {#knowledge-base}

客户常问「你们的知识库是自带还是要接入其他平台」。这一节讲清团队知识进入 AI 工作上下文的四种载体，以及为什么是这个形态。

## 团队知识如何进入 AI 的工作上下文 {#knowledge-carriers}

**不需要把知识搬进某个平台**——AI 直接在你的项目与已有知识平台上按需取用，共四类载体：

| 载体         | 装什么                                   | CodeWave IDE 里的形态                                                |
| ------------ | ---------------------------------------- | -------------------------------------------------------------------- |
| 项目知识     | 构建命令、目录结构、编码约定、团队规范   | `AGENTS.md`：`/init` 分析代码库自动生成，分项目级与用户级            |
| 流程知识     | 部署清单、评审流程、领域工作流           | Agent Skills：插件市场安装，AI 按需自动调用，也可 `/技能名` 显式触发 |
| 外部知识     | 内部 Wiki、Confluence / 语雀 / Notion 等 | MCP 服务器：安装后由 AI 按需调用                                     |
| 企业自有文档 | 员工手册、制度、流程文档                 | 内置检索工具 `kb_search` / `kb_get_doc` / `kb_suggest`，按需检索     |

每类都可以现场演示一句话：

- **项目知识**：在新仓库里执行 `/init`，AI 扫完代码库写出 `AGENTS.md`，下一个会话它就知道构建命令与编码约定。
- **流程知识**：在插件市场装一个技能（如 `commit-skills`），直接说「提交并推送 PR」即触发——技能平时只加载名字与描述，用到时才读全文。
- **外部知识**：接一个语雀 / Confluence 的 MCP server，直接说「按语雀上的《支付模块设计》实现」，AI 会去读那篇文档。
- **企业自有文档**：在企业端「知识库」传一份《员工手册》，直接问「婚假怎么申请」——AI 检索到「员工手册 > 假期制度 > 婚假」，答出「3 个工作日，需提前三个工作日提交申请」，并标出文档名与章节。你也不用帮它纠词：它拿不准公司怎么写时会先看一眼语料里的实际说法（问「带薪假期」能翻出公司写的是「婚假」），换个词再搜。

> 企业知识库默认关闭：在设置页「全局设置」→「基础设置」里打开「企业知识库」即可（也可以手改 `~/.wave/settings.json` 或项目的 `.wave/settings.json` 里的 `"enableKnowledgeBase": true`），保存后下一轮对话生效。开启后 AI 有 `kb_search`（检索）、`kb_get_doc`（读某条命中的全文）、`kb_suggest`（拿语料里出现过的相近词换个写法重搜）三个内置工具。文档由企业管理员在企业端「知识库」页上传 / 删除，成员只能查看列表；AI 只能搜到本企业上传的文档，过滤在服务端做。

## 为什么是这个形态 {#knowledge-rationale}

Claude Code 官方把上下文窗口形容为稀缺资源——「填满得很快，性能随之下降」，所以业界主流做法是**渐进式披露（progressive disclosure）**：启动只加载名字与描述，用到时才读全文（[来源](https://code.claude.com/docs/en/best-practices)）。官方对 Agent Skills 的定位是「**就像给新员工写一份入职指南**」（[来源](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)）。

## 语料很大时：用 MCP 接知识平台 {#knowledge-large-corpus}

企业内部制度 / 流程文档（几十到几百份）用内置的企业知识库就够，不必为此搭知识平台；跨库检索、语义检索、或语料远超上下文时才轮到 MCP。

如果语料大到塞不进上下文（官方给的经验判据：超过约 200,000 token / 约 500 页），或者需要跨库语义检索，推荐**用 MCP 接客户自己的知识平台**——Confluence / 语雀 / Notion 都有成熟 MCP server，装好即用（配置方式见[桌面版文档 - MCP](/desktop/extensions#mcp)）。
