# 代码安全

客户问得最多的是「你们在代码安全上能做什么」，以及「跟静态扫描、依赖扫描是什么关系」。这一节讲清三层按时机分工的自动能力、一条开箱即用的分支审查，以及我们不承担什么。

## 按触发时机分工的几层能力 {#code-security-layers}

| 时机           | 做什么                                                                  | 由谁提供                |
| -------------- | ----------------------------------------------------------------------- | ----------------------- |
| 每次写入文件后 | 与危险模式清单比对，命中即提示正在写代码的 AI                           | Security Guidance 插件  |
| 每一轮回答结束 | 独立复核本轮全部改动（含 Bash 与子代理的改动）                          | Security Guidance 插件  |
| 提交或推送之前 | 读周边调用方与校验点，判断发现真伪                                      | Security Guidance 插件  |
| 需要时手动发起 | 多 agent 深度扫描全库 / 分支 diff / PR / 单个提交，并把选定发现变成补丁 | Security Audit 插件     |
| 随时手动执行   | 一次过完当前分支相对远端默认分支的全部改动                              | 内置 `/security-review` |

**为什么分层而不是一个开关**：这三类问题的发现成本完全不同。危险调用模式是确定性的字符串匹配，可以便宜到每次编辑都跑，但它抓不到语义类漏洞；语义类漏洞（越权、注入、弱加密）需要读懂上下文，只能靠模型复核，于是它被放到回合结束与提交前；而这两层都只能看见 AI 自己改过的东西——**存量清查**只能靠手动发起的深度扫描。三者互补，不互相替代。

## 怎么用 {#code-security-setup}

- **两个插件**：在插件市场安装 `security-guidance`（自动三层）与 `security-audit`（按需扫描与补丁）。装完即生效，不需要改代码或加 CI 配置。
- **自动三层各自可关闭**：在仓库的 `.wave/security-guidance.json` 里按层开关（如 `{"layers":{"edits":true,"turn":true,"commit":false}}`，可只关某一层），关掉的那层完全不介入。
- **内置命令**：`/security-review` 不需要安装任何东西，直接在对话里执行，它只对本批改动负责——**只报本批新引入的问题**，不动既有历史遗留（那属于深度扫描的职责）。
- **深度扫描的产物**：报告落在仓库下的 `WAVE-SECURITY-<时间戳>/`（自带忽略规则，不会被普通 `git add` 误收），人读报告、机器可读结果与 SARIF 三份；选定发现生成的补丁写在 `patches/` 里，**从不自动应用**——`git apply` 由人执行。
- **修正在同一会话内完成**：审查结束后直接说「按报告改一下」，AI 在当前会话里落实修复，不用换工具、不用重述上下文。

## 用项目自己的规则扩展 {#code-security-custom-rules}

通用清单只能覆盖共性，团队真正关心的是本项目特有的约束（多租户查询必须带租户过滤、某类字段不得进日志）。两层都可以用仓库里的规则文件扩展：

- **安全指引文件**：`<仓库>/.wave/security-guidance.md`（另有用户级 `~/.wave/security-guidance.md` 与项目本地 `.wave/security-guidance.local.md`）——用仓库里的指引描述本项目的威胁模型与约定，模型驱动的复核会把它作为附加上下文加载，与内置清单一起使用；三个作用域**全部加载并拼接**。
- **危险模式规则**：`<仓库>/.wave/security-guidance-patterns.json`（另有用户级 `~/.wave/security-guidance-patterns.json`）——自定义的模式与内置模式一同参与逐次编辑的比对，规则名与提示文案随告警给出。

两点口径要注意：指引是**给复核者的指引，不是屏蔽机制**——写「忽略某类漏洞」不会让该类发现消失；这几层也都**不阻断**写入、提交或合并。需要硬性阻断时应当使用能阻断编辑的 hook 或 CI 检查，代码安全审核不承担这个职责。

## 能力边界 {#code-security-limits}

- **只提示不阻断**：发现以提示的形式回到正在写代码的 AI，由它在同一会话内修正。
- **可能漏报**：模型驱动的复核是纵深防御中的一层，不是完整方案。
- **口径不同**：逐次编辑的比对是确定性的字符串匹配，能被它抓到的模式有限。
- **扫描结果具有随机性**：同一份代码扫两次，发现可以不同；它以「定期执行」来补足，而不是以确定性来保证。
- **只覆盖 AI 自己的改动**：自动三层只看得见 AI 产生或发起的改动；同事在你终端里做的改动手动扫描才看得到。
- **面向自有或已获授权的代码**，不用于扫描第三方代码。
