# 功能规格说明：Run Skill Generator Skill

**创建日期**：2026-11-27

## 用户场景与测试 _（必填）_

### 用户故事：为一个可部署单元产出可驱动的 run 技能（优先级：P1）

作为开发者，我希望让 agent 把一个项目（或仓库里的某个应用 / 服务）真正跑起来之后，把「怎么构建、怎么启动、怎么用程序化手段驱动它」写成一份 `run-<unit>` 技能，以便以后任何一个 agent 会话（不熟悉这个项目的）都能直接跑，而不是每次重读 README 重新摸索。

**为什么是这个优先级**：这是技能的全部产出物。没有这份技能，后面的「验证」只能靠冷启动猜测；有了它，`/verify` 这类流程才有 handle 可用。

**独立测试**：在一个没有 run 技能的仓库里运行 `/run-skill-generator`，验证它先真的把应用跑起来并驱动了一次，然后落成 `<unit>/.wave/skills/run-<unit-name>/` 下的 `SKILL.md` 加一份驱动脚本。

**验收场景**：

1. **假设**当前目录是一个自洽的可部署单元（有 `package.json` / `go.mod` / `pyproject.toml` 等清单），**当**用户运行 `/run-skill-generator`，**则**技能把它当作 `<unit>`，产出 `<unit>/.wave/skills/run-<unit-name>/SKILL.md` 与驱动脚本。
2. **假设**当前目录是多应用仓库根（有 `apps/`、`packages/`、`services/`），**当**技能执行时，**则**它列出候选单元并询问用户要哪一个，而不是自己猜。
3. **假设**目标单元有交互式表面（GUI、TUI、长驻服务、REPL），**当**技能交付时，**则**交付物里含一个能程序化驱动该表面的脚本（或内联在 `SKILL.md` 里的脚本），而不只是散文描述。
4. **假设**目标单元只有库 / SDK 形态，**当**技能交付时，**则**驱动脚本走「导入并调用公开入口」的冒烟路径。

### 用户故事：不写完就没法交付（优先级：P1）

作为 agent 的使用者，我希望这个技能只有在「真的跑过、真的驱动过」之后才允许交付，以便产出的技能不是 README 的复述。

**为什么是这个优先级**：这类技能的失败模式几乎全是「照抄文档、没跑过」。把完成定义写死，是唯一有效的约束。

**独立测试**：让技能在一个没跑通过的项目上执行；验证它不会在没启动过应用的情况下交付 `SKILL.md`。

**验收场景**：

1. **假设**技能准备交付，**当**它自查时，**则**四条完成定义全部为真：本会话在本机启动过应用并与之交互过（GUI 要有自己截下的截图文件）；驱动脚本已随技能提交；`SKILL.md` 把驱动脚本作为 agent 的主要入口写在最前面；`SKILL.md` 里每个代码块都是本会话真跑通过的命令。
2. **假设**其中任一条件不满足，**当**技能自查时，**则**它不下笔写 `SKILL.md`，而是回到「跑起来」这一步。
3. **假设**技能把文档里的主张当作事实（例如「只支持 macOS」「需要 GPU」「需要付费账号」），**当**它执行时，**则**它把这些主张当作可反驳的假设去实测，并记录实际成立的绕过办法。
4. **假设**一次交互尝试失败，**当**技能继续时，**则**它把错误与修法记进临时笔记，最终沉淀为 `SKILL.md` 的 Gotchas / Troubleshooting 段。

### 用户故事：精修已有技能而不是重写（优先级：P2）

作为开发者，我希望 `/run-skill-generator` 在项目里已经有一份「怎么跑这个应用」的技能时，去校验、修正、补全它，而不是另起一份。

**为什么是这个优先级**：重复的启动配方会让后续 agent 随机挑一份用；但项目里没有旧技能时，本故事不适用，所以排在 P1 之后。

**独立测试**：放一份内容略有错误的 run 技能，运行 `/run-skill-generator`，验证它改的是那份文件，且名字不变、可用部分保留。

**验收场景**：

1. **假设**项目里已有描述「怎么启动 / 驱动这个应用」的技能（名字各异），**当**技能执行时，**则**它按描述匹配（不按名字），选中后精修而不是新建。
2. **假设**已有技能里某条命令跑不通或记错了，**当**技能执行时，**则**它修掉那一条，保留其余内容，不做风格重写或重排。
3. **假设**项目里只有早期版本留下的单体说明文件（`.wave/run.md` 或 `.claude/run.md`），**当**技能执行时，**则**它把正文迁成技能、被引用的脚本移进技能目录、删掉旧文件。

### 用户故事：按项目类型给对的驱动形状（优先级：P2）

作为开发者，我希望生成器按我的项目类型（Web 服务、CLI、TUI、Electron 桌面、浏览器应用、库）给出对的驱动骨架，以便我不必从零设计交互手段。

**为什么是这个优先级**：骨架本身能省大量时间，但它是 P1 内容的模板化，缺了也能手工凑出来。

**独立测试**：分别对一个 CLI 项目和一个 Web 服务项目运行，验证产出的驱动形状分别是「代表性参数冒烟脚本」与「后台启动 + HTTP 请求脚本」。

**验收场景**：

1. **假设**目标是 Web 服务 / API，**当**技能生成驱动时，**则**形状是后台启动服务加 `curl` 冒烟脚本，且端口是可配置的隔离端口。
2. **假设**目标是 CLI 工具，**当**技能生成驱动时，**则**形状是代表性参数的冒烟脚本，检查退出码与关键输出。
3. **假设**目标是 TUI / 交互式终端，**当**技能生成驱动时，**则**形状是终端复用式抓帧（Unix 用 tmux 的 send-keys / capture-pane，Windows 用 node-pty 起真 ConPTY）。
4. **假设**目标是 Electron / 桌面 GUI 或浏览器应用，**当**技能生成驱动时，**则**形状是 Playwright 驱动（桌面用 `_electron`，浏览器用真 Chromium），并带截图。
5. **假设**目标是库 / SDK，**当**技能生成驱动时，**则**形状是「导入并调用公开入口」的冒烟脚本。

### 用户故事：干净环境里逐行可复现（优先级：P2）

作为下一个 agent，我希望按 `SKILL.md` 逐行照做就能跑起来，以便我不需要任何临场发挥。

**为什么是这个优先级**：这是技能的可用性判据，但它依赖前几条先成立。

**独立测试**：开新 shell，`cd` 进单元目录，逐行照 `SKILL.md` 执行；任何一处需要临场改动都算缺陷。

**验收场景**：

1. **假设**技能即将交付，**当**它自验时，**则**它在新 shell 里逐行照 `SKILL.md` 走一遍，任何 improvisation 都回填进文件。
2. **假设** `SKILL.md` 里的路径，**当**它书写时，**则**路径相对于 `<unit>` 而不是相对技能目录，且文件顶部说明这一点。
3. **假设** `SKILL.md` 结构，**当**它渲染时，**则**依次是：一段总述、Prerequisites、Build、Run（agent 路径，含驱动命令与截图落点）、Run（human 路径）、Gotchas、Troubleshooting。

### 边界情况

- **不知道该以哪个目录为单元**：问用户，不猜。
- **文档说「不支持当前平台」**：先试，不据文档直接放弃；真跑不起来才记录为限制。
- **驱动长成项目测试套件要复用的东西**：移到 `scripts/` 或 `e2e/`，`SKILL.md` 改指向新路径，技能本身留着。
- **项目没有交互表面**（纯库）：驱动就是导入调用冒烟脚本，不需要终端复用或截图。
- **技能放置层级**：单项目仓库放仓库根，多应用仓库放在被改动最频繁的那个单元目录下；目录名与 frontmatter `name` 一致，它就是斜杠命令。
- **Windows 没有 tmux**：TUI / GUI 的抓帧改用 node-pty 真 ConPTY；Linux 无显示服务时 GUI 需要 `xvfb-run`。
- **模型不会自发调用本技能**：CC 的注册对象带 `disableModelInvocation: true`（同一批的 `/run` 不带），本仓用 SKILL.md frontmatter 的 `disable-model-invocation: true` 表达同一意图，只允许用户用 `/run-skill-generator` 触发。

## 范围之外

- **`chromium-cli` 这套内建工具**：CC 示例里的 `chromium-cli` 是 Claude Code 自带的 headless Chromium REPL，本项目没有。示例文件保留 CC 原文命令，只在文件顶部加一段注记说明替代路径（Playwright 脚本）；正文描述处改称 Playwright。
- **自写示例**：6 份 `examples/*.md` 与 `template.md` 一律取 CC 二进制原文（`electron.md` 在 `.zst` 里，其余明文），只做 `.claude`→`.wave` 与上一条注记这两类偏离。CC 的生成器注册时就是 `files = { "template.md": TEMPLATE_MD, ...RUN_EXAMPLE_FILES }`——它直接复用 `/run` 那批示例，所以本项目把内容只存一份（`run-examples.ts`），两个技能按各自目录前缀展开。
