# 功能规格说明：Diff 命令

**创建日期**：2026-11-13

**最近修订**：2026-11-19 —— 详情视图的键位提示改回**钉在面板底边**（与 Claude Code 的 inline 分支一致）：插件自己分页、接住 `ui.scroll`，面板打开时焦点落在第一个文件行（元素的 `autoFocus`）。此前是「提示放表头下一行、整棵树交给 surface 滚」，那是不抢宿主滚动的妥协。

**上一次修订**：2026-11-18 —— 终端的 `/diff` 从 CLI 自带的**全屏覆盖层**改为**内置差异插件**（`diff@builtin`，默认开）画的 mod 面板。改的是实现载体，用户看到的能力（未提交改动 + 按轮看改动）不变；跟着 Claude Code 的形态走，也让「差异」这类展示能力不再占 CLI 的私有代码。

## 用户场景与测试 _（必填）_

### 用户故事：查看未提交改动（优先级：P1）

作为用户，我希望输入 `/diff` 就能看到工作区里还没提交的改动，以便在决定是否提交或继续让 agent 改之前先自己过一遍。

**为什么是这个优先级**：这是日常最常看的那一份差异，也是「agent 到底动了什么」的第一落点；没有它，用户只能离开终端去敲 `git diff`。

**独立测试**：可以在一个 git 仓库里改一个文件、加一个未跟踪文件，然后输入 `/diff`，验证两个文件都出现在列表里、各自带 `+N -M` 统计，选中后能看到逐行 diff。

**验收场景**：

1. **假设** 工作区有 1 个已修改文件和 1 个未跟踪的新文件，**当** 用户输入 `/diff` 时，**则** 输入框上方的差异面板打开并拿到键盘焦点，显示面板标题 `Diff`、来源下拉、合计统计（`2 files changed +3 -1`）与文件列表。
2. **假设** 文件列表可见，**当** 用户按 `Enter`（或直接按文件行的 `hotkey`）时，**则** 面板进入该文件的详情视图，逐行展示 diff：新增行绿色、删除行红色、hunk 头青色。
3. **假设** 处于详情视图，**当** 用户按 `b`（`← Back` 按钮的 hotkey）时，**则** 回到文件列表；**当** 用户按 `Esc` 时，**则** 同样回到文件列表 —— `Esc` 先走 surface 的 `ui.close`，插件在详情视图返回 `{ deny }` 拦下这次关闭（与 Claude Code 同一条语义，见 [plugin-mods](../ecosystem/plugin-mods.md)「`ui.close`：mod 能拦下关闭」）；在列表视图按 `Esc` 才真的收起面板、把键盘还给输入框。
4. **假设** 差异内容超过面板高度，**当** 用户按 `↑` / `↓`（逐行）、`PgUp` / `PgDn`（翻页）或 `Home` / `End`（到顶 / 到底）时，**则** 正文滚动，而底部那行键位提示**钉在面板底边不动** —— 滚的是插件自己的窗口（它接住 surface 的 `ui.scroll`，见 [plugin-mods](../ecosystem/plugin-mods.md)「`ui.scroll`：mod 自己滚」），不是宿主那一层整棵树。

### 用户故事：回看某一轮对话改了哪些文件（优先级：P2）

作为用户，我希望把差异范围收窄到「刚才那一轮」，以便在长会话里确认某个具体需求对应的改动，而不是在一大坨未提交改动里翻找。

**为什么是这个优先级**：未提交改动是累计的；对话轮次是用户脑子里真正的分界线，但只有把「这一轮动了哪些文件」摆出来才好核对。

**独立测试**：可以让 agent 连续两轮各自修改不同的文件，输入 `/diff` 后用面板顶部的来源下拉选到某一轮，验证只列出该轮改过的文件及其 diff。

**验收场景**：

1. **假设** 会话里已有两轮分别修改过文件，**当** 用户在来源下拉里选中 `T2` 时，**则** 面板切到该轮，副标题显示该轮用户请求的摘要（超长截断），并列出该轮改过的文件。
2. **假设** 正在看某一轮的差异，**当** 用户在来源下拉里选回 `Current` 时，**则** 回到未提交改动，选中项重置为第一个文件。
3. **假设** 某一轮只有读取类工具、没有改任何文件，**当** 用户展开来源下拉时，**则** 该轮不出现为可选项（不展示空条目）。
4. **假设** 同一轮里同一个文件被改了两次，**当** 用户查看该文件时，**则** 两次改动按顺序合并展示，`+N -M` 为累计值。

### 用户故事：差异面板在终端里占得下（优先级：P1）

作为终端用户，我希望差异面板能按内容要一个够大的高度，而不是被压在一小块里逐行挤，以便像以前的覆盖层那样一眼看完整段 hunk。

**为什么是这个优先级**：差异是「一块块读」的东西，面板太矮会把每次滚动都变成一次翻找。这是「把覆盖层换成插件面板」能不能成立的前提条件。

**独立测试**：在一个改了几十行的文件上敲 `/diff`、进详情视图，验证面板高度明显大于其它 mod 面板的 12 行，且正文仍能滚动。

**验收场景**：

1. **假设** 终端高度足够，**当** 差异面板打开时，**则** 它按插件申报的行数（`$.ui.open({ rows })`）占位，上限仍是终端高度的 2/3。
2. **假设** 终端很矮（比如 20 行），**当** 差异面板打开时，**则** 面板被压到最低 6 行、正文内部滚动，消息区不被挤没。
3. **假设** 用户切到某个文件、内容变长，**当** 面板重画时，**则** 它按新的行数申报一次（再 `$.ui.open`），不是每帧都改。
4. **假设** 面板拿到键盘，**当** 用户在列表视图按 `↑` / `↓` 时，**则** 焦点在文件行之间移动（`❯` 跟着走）；在详情视图按 `↑` / `↓` 时，**则** 滚动正文、焦点不动。哪一种是哪一种由插件决定：surface 把方向键算出的候选落点经 `ui.focus` 问一遍插件，插件接住就换焦点，不接就归 surface 滚正文 —— 与 Claude Code 的 inline（`/tui classic`）分支一致；`Tab` / `Shift+Tab` 在任何视图里都只管移焦点。
5. **假设** 面板打开，**当** 用户看面板时，**则** 有一行 `dimColor` 的键位提示：列表视图是 `↑/↓ to select · Enter to view · Esc to close`，详情视图是 `↑/↓ to scroll · Esc to back`（两行都与 Claude Code 的 inline 分支逐字一样 —— 它那边详情里的 `Esc` 也是「回列表」。这行是插件自己画进树里的普通 `Text`，不是宿主提供的元素）。两个视图都放**面板底边**（与 Claude Code 的 inline 分支一致）。列表一屏画得下、从不滚动，天然钉得住；详情里靠插件自己分页：它把树裁到「表头 + 一屏正文 + 提示」刚好装满面板正文的行数，所以提示恒在底边、滚动只发生在正文那一段。为此插件要两样东西：一屏几行（`ui.render` 的 `e.props.scroll.bodyRows`，由 surface 实测上报）与滚动键（`ui.scroll` 事件，见第 4 条场景）。
6. **假设** 面板刚打开（用户敲了 `/diff`），**当** 第一帧树画出来时，**则** 焦点环落在**第一个文件行**（文件行元素带 `autoFocus`），不是来源下拉 —— 所以接着按 `↑` / `↓` 就是在文件之间选，`Enter` 直接进详情。

### 用户故事：桌面端用 `/diff` 打开差异面板（优先级：P2）

作为桌面端用户，我手还在输入框里、刚看完 agent 这一轮的改动就想核对文件，希望敲 `/diff` 就能把右侧的「差异」面板打开，而不是先去点面板菜单或记快捷键。

**为什么是这个优先级**：桌面端的差异面板本来只有「空态网格 / ＋ 菜单 / 菜单栏 / 快捷键」几个入口，全都要先离开输入区；斜杠命令是唯一「手不用挪」的入口。反过来，VS Code / JetBrains 用编辑器自己的 diff 视图、手机远控页没有面板，所以这条命令只属于桌面端。

**独立测试**：在桌面端会话里输入 `/diff` 并发送，验证右侧出现「差异」tab、且没有消息被发给模型；面板已经开着时再敲一次，验证仍是同一个 tab。

**验收场景**：

1. **假设** 桌面端会话中右侧面板未打开，**当** 用户输入 `/diff` 并发送，**则** 右侧打开「差异」面板（内容与从菜单打开完全一致，见 `desktop/desktop-diff-panel.md`），这段文本不进对话、也不发给模型。
2. **假设** 「差异」tab 已经存在，**当** 用户再次输入 `/diff`，**则** 激活已有的那个 tab，不出现第二个差异 tab（与 `/tasks` 同样的单实例语义）。
3. **假设** 用户用的是桌面端，**当** 会话装载内置差异插件时，**则** 它不登记自己的面板与命令（插件只在 `terminal` 这一端生效），右侧差异 tab 仍由 webview 自己的 `DiffPane` 画 —— 两套实现不并存、也不打架。

### 边界情况

- **工作区基准**：差异的比对基准是**会话工作根**（会话打开时的目录，只有进入/退出 worktree 时才会变），agent 在会话里 `cd` 过不影响它。
- **不在 git 仓库**：面板显示 "Not a git repository"，而不是空列表或报错。
- **仓库处于变基 / 合并 / 拣选等中间态**：面板明确提示「有 X 正在进行，没有可信的差异」，而不是把半成品状态当成用户的改动。
- **二进制文件**：列表里标 `binary`，详情说明无文本差异，不渲染乱码。
- **超大差异**：单文件 diff 被截断时标注 `(truncated)`；整份差异超过 400 行时按 Claude Code 的同一道闸标 `… diff truncated (exceeded 400 line limit)`。
- **没有终端界面**（`wave -p`）：`$.ui.open` 返回 `isPlaced: false`，命令只回一行说明，不假装打开。
- **插件被关掉**：`enabledPlugins["diff@builtin"] = false` 后 `/diff` 不再存在（终端没有内置兜底），桌面端不受影响。

## 实现载体：内置差异插件

终端这一半的 `/diff` 由内置插件 `diff@builtin` 画，不再是 CLI 自己的组件。这样「差异」这类展示能力与其它 mod 走同一条装载/渲染/键盘/限额通道，CLI 不再为它保留一套私有实现。

**装载**：内置插件表里加一条 `diff`，默认开（`defaultEnabled: true`，见 [plugin-mods](../ecosystem/plugin-mods.md) 的内置插件策略）。它**只在 `terminal` 这一端生效**：`session.start` 里看 `$.session.surfaces()`，含 `terminal` 才注册命令与面板；桌面端 / IDE 端装载它但不登记任何东西，右侧差异 tab 仍由 webview 的 `DiffPane` 画（两套实现不并存）。

**数据来源**（两档，与的覆盖层口径一致）：

| 来源                | 怎么拿                                                                                                                                                                                                                                                                                                                                        |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Current`（未提交） | `$.process.run(["git", "diff", "HEAD", "--no-color", "--no-ext-diff"], { cwd: await $.session.root() })` 拿已跟踪文件的差异，`git status --porcelain -z` 补未跟踪文件（按整份新增渲染），`git diff --numstat` 取 `+N -M` 统计。工作根用 `$.session.root()`（`cd` 不影响它）。先问 `$.session.repo()`：给 `null` 就走「不在 git 仓库」那一档。 |
| `T1`…`Tn`（按轮）   | `$.session.messages()` 里逐轮的 `Edit` / `Write` 工具调用：`Edit` 用 `old_string`/`new_string` 重新算行差异，`Write` 把 `content` 当整份新增 —— 与 CLI 现在 `sessionDiff.ts` 的做法同一份逻辑，只是搬进插件。                                                                                                                                 |

**不用 `structuredPatch`**：Claude Code 的差异插件从 `session.messages()` 的 `tool_result.structuredPatch` 直接取补丁，我们的 `ModSessionMessageBlock` 里 `tool_result` 只有字符串（见 [plugin-mods](../ecosystem/plugin-mods.md)「会话消息」）。所以按轮那一档从**工具入参**重算，代价是同一份文件被改名/移动这类操作只能标成「新增 + 删除」，收益是不用为一个消费者改 mod 面的消息形状。

**面板结构**（自上而下，行数与 Claude Code 的差异插件同一套算法）：

1. 标题行：来源下拉（`Current` / `T1`…`Tn`）+ `N files changed +X -Y`；
2. 有话说时多一行：某一轮的用户请求摘要（超长截断），或来源本身的说明（不在 git 仓库、仓库处于变基/合并中间态）；
3. 文件列表：一行一个 `path +N -M`（`+`/`-` 各自着色）；超过 8 个时上下各用一个翻窗按钮 `↑ N more above` / `↓ N more`，不做滚动条；
4. 详情视图（选中文件后）：`← Back`（`hotkey="b"`）+ 路径，正文是 `Code` 元素带 `format="diff"`，按行首着色；整份被截断时补一行说明；**最后一行**是键位提示 `↑/↓ to scroll · Esc to back`（钉在面板底边，正文在它上面滚）。列表视图同理，提示在列表末尾、也是面板最后一行。

**高度**由插件按内容算出来申报（`$.ui.open({ rows })`）：列表按文件数；详情按「表头 1 行 + 正文一屏 + 底部提示 1 行」（超长文件另有 1 行截断说明），一屏的正文行数取自 surface 报上来的 `e.props.scroll.bodyRows`，还没量到时按 20 行算。切文件/切来源时重算一次 —— 值变了才重新 `open`，因为每次 `open` 都会催一次重拉，每帧都调就成了循环。

**视图状态存在 mod 自己的闭包里**，不进 `$.state`：那里跨 realm 深拷贝，几百行的 diff 正文每存一次就搬一遍不值得。代价是插件重载会丢掉视图位置（回到列表第一页），可以接受。

**CLI 侧删什么、留什么**：

- **删**：`packages/code/src/components/DiffManager.tsx`（覆盖层）、它在 `InputBox` 里的挂载与 `showDiffManager` 状态、`commands.ts` 里的 `/diff` 条目、两处 `command === "diff"` 的分发。
- **留**：`packages/code/src/components/DiffDisplay.tsx` —— 它还被 `ConfirmationDetails`（权限确认里的 diff 预览）与 `ToolDisplay`（对话流里的工具 diff）用，与 `/diff` 无关。
- **留**：桌面端与远端页的差异面板（webview `DiffPane`），它们走自己的入口，与这条命令无关。
