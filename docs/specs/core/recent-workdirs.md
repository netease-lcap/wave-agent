# 功能规格说明：最近工作目录

**创建日期**：2026-10-21

## 澄清

### 2026-10-21 决策

- **载体从「各端自己记」改成「这台机器记一份」**：桌面端原来写自己的 `userData/wave-desktop.json`（按 host 分组），浏览器侧 localStorage 只属于那台手机。两者都不是「这台机器」——远控页把会话全删光后最近目录直接变空，就是这个错位的直接后果。
- **文件**：`~/.wave/recent-workdirs.json`，与 `auth.json` / `remote-settings.json` 同级（用户级，跟机器走）。结构 `{ "dirs": string[] }`，MRU 顺序，上限 10（与桌面端 `MAX_RECENT_WORKDIRS` 对齐），原子写。
- **写**：谁让用户选了目录，谁就向**那台机器**记一条——桌面端在工作目录选择器选定目录时、远控页在新建会话成功后。恢复已有会话、agent 在会话里 `cd` 到别处、只在目录浏览器里翻看，都不写。
- **不在会话创建路径里自动写**：worktree 新建是两步（`createWorktree` → `initialize(workdir=工作树路径)`），服务端拿到的已经是被派生的路径，判断「用户到底选了哪个目录」要靠猜；把写入点放在调用方（它手里就是用户选的那个目录）更准。
- **读**：bridge 新增只读方法 `getRecentWorkdirs`（无入参，回这台机器的 MRU）。
- **worktree**：记仓库根，不记工作树路径（与列表「只列主仓库根」的既有口径一致）。
- **桌面端**：按主机向那台机器读（本机 stdio 子进程 / 远端 daemon），本地那份降为「旧版机器没有这条方法」时的回退缓存。
- **远控页**：活会话派生的目录在前、机器 MRU 在后，跨两段去重合并；读不到就退回现状。
- **白名单**：32 → **34**（读 `getRecentWorkdirs` + 写 `rememberRecentWorkdir`）。写入并没有把「能建会话」之外的能力开出去——页面本来就能在任意目录 `initialize`，这里额外能做的只是让某个路径出现在列表里。

## 用户场景与测试 _（必填）_

### 用户故事：最近目录记在这台机器上（优先级：P1）

作为用手机和桌面端轮着用同一台电脑的用户，我希望「最近打开过的目录」记在这台电脑上，以便换手机、清浏览器数据、甚至把所有会话都删光之后，下次新建会话仍能一键回到最近用过的目录。

**为什么是这个优先级**：它是两端能共用同一份列表的前提。没有它，远控页的最近目录只能从活会话派生（`listDaemonSessions`），会话一删就归零——那正是这个能力被发现的原因。

**独立测试**：向一台机器写几条最近目录，检查 `~/.wave/recent-workdirs.json` 的内容与顺序；重复写同一目录验证只保留一条并置顶；写到第 11 条验证最旧的被挤出；删光会话后验证文件内容不变；把文件内容改成非法 JSON 后验证读取按空列表返回且会话创建不受影响。

**验收场景**：

1. **假设** 用户在某目录选定并新建了会话，**则** 那台机器的 `~/.wave/recent-workdirs.json` 中该目录被置顶；已存在的同名条目只保留一条（比较前去掉尾部分隔符，`/repo` 与 `/repo/` 视为同一个）
2. **假设** 列表已有 10 条，**则** 新的写入把最旧的一条挤掉，文件最多保留 10 条
3. **假设** 用户建的是 worktree 会话，**则** 记入的是**仓库根目录**，工作树路径不进入列表
4. **假设** 用户恢复一条已有会话、在会话里用 bash `cd` 到别处、或只在目录浏览器里翻看而没有选定，**则** 列表不变
5. **假设** 文件不存在、内容不是合法 JSON、或目录不可写，**则** 读取按空列表处理、写入静默失败；会话创建与其余功能不受影响，调用方不因它报错
6. **假设** 同一台机器上多个进程（daemon / 桌面端子进程 / CLI）先后写入，**则** 每次写入都以「读现状 → 合并 → 原子替换」完成；并发下允许丢掉一次最近更新，不允许文件损坏成不可解析

### 用户故事：桌面端按主机读那台机器的列表（优先级：P1）

作为桌面端用户，我希望切换主机时看到的最近打开目录就是**那台机器**自己的记录，以便它和手机端（远控页）看到的是同一份，而不是桌面端在一个本地文件里替所有主机攒出来的副本。

**为什么是这个优先级**：不切的话两边会长期分叉——同一台电脑，桌面端本机组一份、远控页一份，用户会在两端看到不同的「最近打开」。桌面端既有的行为契约（只由用户主动选择更新、启动取首项、切主机取该主机首项、工作树路径不入列表）**一条都不变**，变的只是数据从哪来。

**独立测试**：选一台主机打开工作目录选择器，验证列表与该主机 `~/.wave/recent-workdirs.json` 一致；在同一台机器上用远控页新建一个会话，回到桌面端该主机验证目录已出现；把该主机的方法挡掉（模拟旧版机器）验证回退到本地缓存且仍可继续工作；恢复一条历史会话验证最近打开列表顺序不变。

**验收场景**：

1. **假设** 用户选中某台主机，**则** 最近打开列表来自**那台机器**（`getRecentWorkdirs` 走该主机的通道：本机是 stdio 子进程、远端是隧道里的 daemon）；同一路径在另一台主机上不出现
2. **假设** 用户用远控页在这台机器上新建过会话，**则** 桌面端该主机的最近打开能看到那个目录；反之桌面端选过的目录，远控页新建会话时也能看到（两端同一份）
3. **假设** 该主机的 version 旧到没有 `getRecentWorkdirs`，**则** 桌面端回退到本地 `wave-desktop.json` 里那个主机的分组，**不得**显示空列表或报错；此后该主机的本地分组仍按用户的选择继续更新（否则回退列表再也不长）
4. **假设** 用户在桌面端选定目录（本机 OS 对话框 / 远端目录浏览面板 / worktree 会话用到的仓库根），**则** 向**那台机器**记一条（`rememberRecentWorkdir`），同时继续更新本地缓存那份回退数据
5. **假设** 用户恢复历史会话、或 agent 工作目录在会话中被 bash 改写，**则** 不写入（既有契约不变，见 [desktop-sessions.md](../desktop/desktop-sessions.md) 场景 9）

### 用户故事：远控页新建会话时列出机器侧最近目录（优先级：P1）

作为用手机发起新会话的用户，我希望「新建会话」里除了活会话的目录，还能看到这台电脑最近用过的目录，以便删光了所有会话、或者想开一个之前用过但眼下没有会话的目录时，不必每次都从「浏览…」一级级点进去。

**为什么是这个优先级**：这是这份机器级记录的第一个直接受益者，也是「会话全删光后最近目录变空」这个具体缺陷的修法。

**独立测试**：在机器上先建立过若干目录的会话，把手机端的会话全部删除，再打开「新建会话」，验证最近目录仍列出那些目录；把 `getRecentWorkdirs` 挡掉（模拟旧版电脑）验证退回只列活会话目录且不报错。

**验收场景**：

1. **假设** 用户打开「新建会话」，**则** 最近目录是两段合并的结果：**活会话派生的目录在前**（`repoRoot ?? workdir`，按最近活跃排序，口径见 [remote-control.md](../ui/remote-control.md) 本故事场景 2），**机器 MRU 在后**，两段之间按路径去重
2. **假设** 手机端把会话全部删光（活会话为 0），**则** 最近目录仍列出机器 MRU，不再只剩「浏览…」
3. **假设** 电脑侧是旧版本（`getRecentWorkdirs` 不可用），**则** 退回只列活会话派生的目录（本能力引入前的行为），**不得**因此报错或把弹窗置成空
4. **假设** 列表里的某个目录已经在机器上被删除，**则** 读取时**不过滤**（不逐条 stat）；用户点选后创建失败按既有错误路径提示
5. **假设** 有人问「页面能不能直接改写这份列表」，**则** 不能：写方法 `rememberRecentWorkdir` 只在新建会话成功后由页面调用一次，参数是那次创建用的目录；页面没有其它入口改动它，也不能借它删改已有条目
