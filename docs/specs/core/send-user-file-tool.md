# 功能规格说明：SendUserFile 工具

**创建日期**：2026-11-23

> 对齐 `@anthropic-ai/claude-code@2.1.325` 的内建 `SendUserFile` 工具：模型干完活（写完报告、截完图、构建出产物）时，用一个专门的工具把这些文件"交付"给用户，而不是只在回复正文里提一嘴文件名。
> **简化决定（2026-11-23 拍板）**：CC 那一版很重——它要把文件**上传**成附件对象（`attachments` / `file_uuid` / 缩放缩略图 / `path_validated`）、有 `display: render|attach` 决定前端内联渲染还是下载卡、有 `status: normal|proactive` 表达"用户没要但我现在得给你看"、桌面端还有一整套 `device_stage_files → device_commit_files` 落盘协议与会话文件清单面板。wave 只做其中一件：**工具结果在消息里渲染成每个文件一张可点击卡片**，点击行为复用已有的三档（文本 / 图片 / 其它）。
> 三档的依据来自 CC 两端取证：VS Code 插件**不调系统默认程序**（`openTextDocument` → `showTextDocument` 失败再 `vscode.open`，再失败才 toast），桌面端**调系统默认程序**（扩展名黑名单 + 同意对话框后 `shell.openPath` / `showItemInFolder`）。wave 照这个分工：插件端走 VS Code 自己的打开链，桌面端走系统 opener。
> 实现落点（四处，缺一处行为就断）：分类与黑名单在 SDK `constants/deliverableFiles.ts`（唯一实现，工具/宿主/webview 共用）；工具本体 `tools/sendUserFileTool.ts`；消息渲染 `webview/components/Message.tsx` 的 `SendUserFile` 分支（结构化数据经 `ToolBlock.data.attachments` 下发 —— 形状对齐 Claude Code `SendUserFile` 的 outputSchema，解析在 `utils/deliveredFiles.ts`，老转录的 `ToolBlock.metadata.files` 仍作兜底）；宿主侧闸门在 desktop `handleOpenPath` 与 VS Code `handleOpenFile`。
> 范围：新增一个只读工具 + 消息里的一处渲染。**不做**文件上传、附件对象、`display` / `status` 参数、远端可见性提示（CC 的 `rendered_locally`：`NOT delivered to Remote Control viewers`）、桌面端文件清单面板、缩略图生成、点击以外的任何自动动作（工具执行不得自动拉起系统程序）。

## 用户场景与测试 _（必填）_

### 用户故事：模型把刚做完的文件交付给用户（优先级：P1）

作为用户，我希望模型在写完报告、生成图表或构建出产物后，用一个明确的动作把这些文件交到我手上（而不是在正文里随手写个路径），以便我知道"这就是成品，去看这个"。

**为什么是这个优先级**：这是本工具存在的唯一理由；没有它就没有后续所有点击行为。

**独立测试**：调用 `SendUserFile` 工具（`files: ["/abs/report.md"]`），断言工具返回 `{ files: [{ path, name, kind }] }`，且消息里渲染出一条可点击路径。

**验收场景**：

1. **假设** 模型调用 `SendUserFile` 且 `files` 指向磁盘上已存在的文件，**当** 工具执行时，**则** 返回成功结果（含每个文件的绝对路径、显示名与 `kind`），并由消息层渲染成可点击卡片。
2. **假设** 工具结果已渲染，**当** 工具执行结束时，**则** 不得自动打开任何文件、不得拉起系统程序、不得弹出预览面板——打开只由用户点击触发。
3. **假设** 模型在同一次调用里传多个文件，**当** 工具执行时，**则** 每个文件各占一张可点击卡片（文件类型图标 + 文件名），全部列出，不折叠、不截断（重复路径去重后保留首次出现）。
4. **假设** 模型传了 `caption`，**当** 工具执行时，**则** 该文本作为普通文本渲染在路径附近（不参与路径识别、不可点击）；未传则不渲染空行。
5. **假设** 模型传相对路径 `reports/a.md`，**当** 工具执行时，**则** 以会话当前工作目录为基准解析为绝对路径；卡片上只写**文件名**（与 CC 桌面端的交付卡片同形态），悬停提示与点击都用解析后的绝对路径——路径不占版面，但点击落的一定是磁盘上那一个文件。

### 用户故事：点击文本类文件路径（优先级：P1）

作为用户，我希望点击交付来的文本类文件（`.md` / `.txt` / 代码 / 配置）时，行为和点击消息正文里的同名路径一致（插件端在编辑器打开、桌面端与远控页按现有规则预览或打开），以便不必学两套交互。

**为什么是这个优先级**：文本是交付物里最常见的类型，且"和现在一样"是这一档的全部需求。

**独立测试**：在插件端点击 `SendUserFile` 产出的 `.md` 路径，断言走到与正文路径相同的打开链（`showTextDocument` → `vscode.open` 降级）。

**验收场景**：

1. **假设** 交付的文件按现有文本路径判定属于"可当文本读"，**当** 用户点击该路径时，**则** 调用与消息正文路径点击**完全相同**的那条实现（不新增第二套判定与跳转逻辑）。
2. **假设** 会话在 SSH 远端或远控页上，**当** 用户点击文本路径时，**则** 行为与现状一致（沿用现有远端规则，本工具不改变这一档）。

### 用户故事：点击图片路径（优先级：P1）

作为用户，我希望点击交付来的截图 / 图片时看到图片预览，和现在点击消息里的图片路径一样。

**为什么是这个优先级**：截图是最典型的"我现在就要你看"的交付物。

**独立测试**：交付一张 `.png`，点击路径后断言走到现有图片预览实现。

**验收场景**：

1. **假设** 交付文件的扩展名被现有图片判定（`isImageFileExtension`）识别，**当** 用户点击时，**则** 走现有图片路径点击的实现（预览 / 打开），不按"其它文件"档处理。
2. **假设** 扩展名是图片但文件内容不是图片，**当** 用户点击时，**则** 由既有打开链如实报错，不静默吞掉。

### 用户故事：点击其它文件时用系统默认程序打开（优先级：P1）

作为用户，我希望点击交付来的、既不是文本也不是图片的文件（`.pdf` / `.docx` / `.zip` / `.xlsx` …）时，本机场景直接用系统默认程序打开它，以便我不必自己去文件管理器里找。

**为什么是这个优先级**："其它类型"是本工具相对"正文里写个路径"唯一多出来的价值——正文路径对这类文件只能干看着。

**独立测试**：桌面端点击 `report.pdf` 路径，断言宿主收到打开请求并调用系统 opener；插件端点击同一路径，断言走 VS Code 的 `vscode.open`。

**验收场景**：

1. **假设** 桌面端会话运行在本机，交付文件属于"其它"档，**当** 用户点击路径时，**则** 宿主用系统默认程序打开该文件（与文件面板里"用外部程序打开"同一条实现）。
2. **假设** 插件端扩展宿主与文件系统在同一台机器上，**当** 用户点击"其它"档路径时，**则** 走 VS Code 自己的打开链（先尝试文本打开、失败降级到内置 viewer），**不**调用系统默认程序（对齐 CC 插件端的做法）。
3. **假设** 桌面端会话是 WSL（本机但路径跨了子系统边界），**当** 点击"其它"档路径时，**则** 沿用现有 WSL 路径映射规则打开，不当作异地处理。
4. **假设** 文件在交付之后被删除或移动，**当** 用户点击时，**则** 给出可见的错误提示（文件不存在 / 打不开），**不静默失败**。

### 用户故事：非本机会话不给"其它"档点击（优先级：P1）

作为用户，我希望在 SSH 远端会话或手机上的远控页里，点击交付来的 PDF/zip 这类文件时不会假装能打开（那些文件根本不在我手里的这台机器上），以便不被一个点了没反应的假链接骗。

**为什么是这个优先级**：与上一条是同一枚硬币的两面——能打开就给入口，不可能打开就别给。

**独立测试**：SSH 会话下交付一个 `.pdf`，断言该路径无可点击态（cursor 不变、无 hover、点击无请求发出）；远控页同一用例。

**验收场景**：

1. **假设** 桌面端会话的 host 是 SSH 远端，**当** 渲染"其它"档路径时，**则** 该路径不可点击（不发任何打开请求），文本与图片两档行为不受影响。
2. **假设** 页面是远控页（手机 / 浏览器），**当** 渲染"其它"档路径时，**则** 不可点击；文本与图片两档沿用现状。
3. **假设** 插件端处于 Remote-SSH / 容器等"扩展宿主不在本机"的形态，**当** 点击"其它"档路径时，**则** 照常走 VS Code 自己的打开链（它本来就按扩展宿主的位置处理远端文件），插件端**不做**本机判定。
4. **假设** 同一会话中途从本机切到远端（或反之），**当** 重新渲染时，**则** "本机可达"判定以宿主下发的当前值（`hostOptions` 里该 host 的 `kind`）为准，不在前端缓存旧值。

### 用户故事：只在有渲染方时声明这个工具（优先级：P1）

作为用户，我不希望模型在一个拿不到卡片的形态里调用它——纯终端里这个工具只会画出一行 `● SendUserFile`（终端渲不出卡片，也不可点），`wave -p` 里更是连界面都没有，那是一次没有结果的交付。

**为什么是这个优先级**：它决定这个工具会不会出现在模型视野里，比点击行为更靠前。

**独立测试**：以 `entrypoint: "cli"`（交互 TUI、没有远控页跟随）创建会话，断言本轮工具清单里没有 `SendUserFile`；模拟远控页跟随该会话后再组装，断言出现。

**验收场景**：

1. **假设** 会话的消费者里只有 `terminal`（交互 CLI）或为空（`-p`），**当** 组装本轮工具清单时，**则** 不声明 `SendUserFile`。
2. **假设** 消费者里出现任何非 `terminal` 的一方（桌面端、插件端、远控页），**当** 组装工具清单时，**则** 声明它。
3. **假设** 会话曾经能交付、现在消费者退回 `terminal`，**当** 历史消息里已有这个工具的调用时，**则** 那些结果照常渲染（工具仍在注册表里，只是不再声明给模型）。

### 用户故事：可执行文件不让打开（优先级：P2）

作为用户，我希望交付来的可执行程序 / 脚本类文件（`.exe` / `.bat` / `.ps1` / `.sh` / `.app` …）即使在本机也不被系统默认程序直接执行，以便模型诱导我双击一个来路不明的程序时不至于真的跑起来。

**为什么是这个优先级**：这是"其它档用系统 opener"的必备刹车，P1 的前提，但失败场景不是高频路径，所以排 P2。

**独立测试**：桌面端交付 `build/setup.exe`，点击后断言请求**照常**走到宿主打开链、宿主拒绝执行并回一条可见提示，且系统进程未被拉起。

**验收场景**：

1. **假设** 交付文件是 `.exe` 这类可执行文件，**当** 渲染时，**则** 它只是"其它"档的一张卡片——分类不单独标注可执行，前端不判断、不预置任何提示（2026-11-23 定：判定只留在宿主，前端多一层就多一处会走偏的真相）。
2. **假设** 用户在本机点击该卡片，**当** 请求到达宿主时，**则** 黑名单在**宿主打开前**拒绝（桌面端 `handleOpenPath`、插件端 `handleOpenFile` 各一道），并发一条可见原因（"出于安全，不打开可执行文件"），不出现"点了没反应"。
3. **假设** 会话在远控页或桌面端 SSH，**当** 渲染可执行文件时，**则** 它和其它"其它"档一样不可点（灰卡），因为那两种形态本来就没有本机打开通道。

### 用户故事：参数校验与错误回执（优先级：P2）

作为用户，我希望模型传错参数（传目录、传不存在的文件、传空数组）时立刻拿到明确的错误，以便它自己修，而不是我面对一个点了打不开的死链。

**为什么是这个优先级**：坏参数是模型最常见的失误，在工具边界兜住比在前端兜成本低得多。

**独立测试**：`files: ["/tmp"]`、`files: ["nope.md"]`、`files: []` 三种输入各返回 `success: false` 与对应错误文案，且消息里不渲染可点击路径。

**验收场景**：

1. **假设** `files` 缺失或为空数组，**当** 工具执行时，**则** 返回参数错误并说明至少需要一个文件路径。
2. **假设** 某个路径不存在，**当** 工具执行时，**则** 返回错误（提示先写盘再交付），整体不渲染可点击路径。
3. **假设** 某个路径是目录而非文件，**当** 工具执行时，**则** 返回错误并说明只接受文件路径。
4. **假设** 多个路径里只有部分无效，**当** 工具执行时，**则** 整体失败并指出哪些路径无效（不做"部分成功"——模型改正后重试更不容易留下半截状态）。

## 非功能需求

- **工具名与描述**：工具名对齐 CC 叫 `SendUserFile`；描述必须写清"刚做完一个用户会想看的文件（报告、图表、截图、构建产物）时用它主动交付，别只在回复里提一嘴；不要把临时文件或每次保存都发过来"，避免模型把普通文件也塞给它。
- **只读且并发安全**：工具不写文件、不发网络请求、不改变会话状态，声明为只读 + 并发安全。
- **不是受限工具**：没有外发、没有上传、没有破坏性动作，不读文件内容，也不需要逐次权限确认。**不做按路径的读取权限判定**：这个工具不新增任何能力（模型本来就能把同样的路径写进回复正文），把 Read 的规则搬进来只会让工具名在规则表里多一份谁也不认识的判定。
- **判定唯一**：三档分类（图片 / 文本 / 其它）与黑名单各自只有一份实现。图片沿用现有的图片扩展名判定，文本沿用现有文本路径判定的那份逻辑，不新增平行的第二套扩展名表。
- **前端零判定**：前端只做渲染与转交。"本机是否可达"取宿主下发的 `hostOptions` 里该 host 的 `kind`（`local` / `wsl` 可开、`ssh` 不开），不靠连接 id 字符串或 host 名前缀去猜——webview 拿不到已保存的连接表，猜必错。
- **一次实现两处复用**：点击某一档时调用的就是消息正文路径点击的同一条链路，"交付路径"不复制一份打开逻辑。
- **黑名单只在宿主侧**：前端**不判断**哪些扩展名可执行——它只区分文本 / 图片 / 其它，可执行文件就是"其它"。拒绝发生在宿主打开前（桌面端 `handleOpenPath`、插件端 `handleOpenFile`），安全判定不放前端，也免得前端多一份会和宿主漂移的字典。
- **声明有条件、注册不撤**：只在消费者里存在非 `terminal` 的一方时声明给模型（判据与实现见 `core/session-consumers.md`）；工具本身始终留在注册表里，历史调用才不会变成 `Tool not found`。
- **黑名单清单**（一份实现，三处共用）：`exe` `msi` `msp` `msc` `com` `scr` `cpl` `vbs` `vbe` `jse` `wsf` `wsh` `hta` `lnk` `url` `reg` `inf` `app` `command` `workflow` `scpt` `pkg` `dmg` `run` `bin` `appimage` `desktop` `deb` `rpm` `apk`。**脚本类（`sh` `bat` `ps1` `js`）故意不在黑名单里**：它们在文本白名单里，打开方式是编辑器（不执行），列进黑名单只会把"帮我看看这个脚本"变成拒绝。
- **结果形态**：工具返回结构化的文件清单（路径、文件名、档位），由消息层渲染成每个文件一张卡片：图标取文件树那套 `FileTypeIcon`（按文件名解析，与文件面板一致），卡片上只写文件名，绝对路径放 `title`。**卡片本身就是命中区**，高度默认 40px、远控页 44px（iOS 触控基准）——不沿用 16px 文本行的命中区：实测远控页两行中心距只有 18px，手指会点到隔壁文件。
- **测试**：SDK 层覆盖参数校验、路径解析、档位判定、权限口径；前端 e2e 覆盖三档点击与两类非本机会话的不可点态。

## 边界情况

- **交付后文件被删 / 改名？** 点击时由宿主如实报错（"文件不存在"），不静默——静默会让人以为是自己没点准。
- **同一文件传两次？** 去重后只渲染一条。
- **后缀像文本但内容是二进制（或反之）？** 按扩展名归档，打开时由既有链路按真实内容降级（VS Code 侧 `showTextDocument` 失败会退到内置 viewer），工具层不做内容嗅探。
- **文件很多（几十个）？** 全部列出、不折叠；描述里已要求模型别发临时文件，数量失控属模型行为问题，不由 UI 兜。
- **远控页下文本 / 图片？** 沿用现有远端规则（预览而非本地打开），本工具不改这一档；只有"其它"档在远控页被显式关掉。
- **远控页里用户其实想看某个 PDF？** 本期不做下载/预览，明确不可点。要支持得先有"把文件从会话机器搬到浏览器"的通道，那是另一件事。
- **WSL 会话？** 算本机（路径经现有映射打开），不按远端处理。
- **命中黑名单的可执行文件？** 本机点击照常把请求交给宿主打开链，宿主在打开前拒绝并回一条可见原因；远控页 / 桌面端 SSH 下它与其它"其它"档一样不可点（灰卡）。
- **终端里会话被手机接管 / 手机退出？** 工具的出现与消失跟着消费者走（`core/session-consumers.md`），已有的历史交付卡片不受影响。
- **模型用这个工具发临时文件 / 每次都发？** 描述里明确劝阻；工具层不设数量或路径白名单（无法判断"临时"），由提示词承担。
- **工具结果被转成纯文本展示（老客户端 / 导出）？** 退化为一行文件路径文本，链接能力缺失但信息不丢。
