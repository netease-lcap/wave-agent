> **设计取舍（本轮修订定案）**
>
> - **工具名 = `REPL`，且只有这一个名字**。用户可见的界面名是「Code Mode」。规格文件已随工具名改为 `docs/specs/core/repl-tool.md`；源码目录 `src/repl/` 与常量名已随之改齐。**没有别名**：`Eval` 是 Claude Code 自己那个 EvalTool 的名字（`2007-225920B-EvalTool.js` 是它的取证出处，属 CC 的文件名，不是我们的别名），我们的历史是 `Exec` → `REPL`，`Eval` 从未注册过——所以 `--tools Eval`、`disallowedTools: ["Eval"]`、权限规则里的 `Eval` 都是**未知工具名**，既不解析成本工具，也不会因为它禁用本工具（2026-11-25 删掉了 2026-11-20 照 CC 的 `aliases: ["Eval"]` 搬进来的 `REPL_TOOL_ALIASES`）。

> - **默认开启**。这一点**不**对齐 Claude Code（它是 `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE` opt-in）：我们的 MCP 与延迟工具只有这一条到达路径，默认关闭等于默认砍掉它们。回退开关 `enableRepl: false` 保留（旧键 `enableExec` 继续接受），服务端可下发。
> - **上下文长驻**。一个 `(会话, agent)` 一个 JavaScript 上下文，跨脚本、跨轮次复用；脚本里定义的变量与函数在下一次调用里仍然存在。**定时器不跨脚本**——它随设立它的脚本结束而被清除（对齐 Claude Code 的 `the timer is cleared when that script ends`），否则一个 60 秒的 `setTimeout` 会在三轮之后突然触发。这与 Claude Code 一致，也是本形态相对旧 `Exec`（一次一建、跑完销毁）的主要收益。
> - **中断只 abort，不重置上下文**。用户按 Esc 中断一次运行，只终止这次运行，变量全部保留。对齐 Claude Code：中断后该脚本**仍能再发起最多 20 次**嵌套调用（照常执行、照常返回），**第 21 次起**宿主不再回答（返回一个永不 settle 的 Promise），已经在飞的调用照常收尾——这个宽限是为了让脚本的 `finally` / 收尾逻辑还能跑完。上下文被重置只有一种情形——脚本把受管全局改成了不可配置，或把 `globalThis` 改坏到再也无法启动新调用（见「执行预算与终止」），且重置必须显式告知模型。
> - **隔离与终止都在同进程内完成**：沙箱是**同进程**的 `node:vm` 上下文，不引入 worker 线程或子进程。终止靠**往脚本源码里注入步数计数器**（循环头与调用点插一次记账）+ vm 的同步 wall-clock 超时。这是对齐 Claude Code 的实测形态——它的 REPL 模块里只有 `import * as vm from "vm"` 与 `vm.runInContext`，全模块 `child_process` / `worker_threads` / `Bun.spawn` / `new Worker` 出现 **0 次**；它能停下 `await 之后 while(true)` 靠的正是注入到源码里的计数器（默认 3 亿步），不是杀进程。代价：同步段会真实占用宿主事件循环，长度由 vm 的 wall-clock 超时上界约束。
> - **`timeout` 入参对齐 Claude Code**：schema 从只有 `code` 扩展为 `code` + `timeout`（毫秒，**默认 30000、上限 600000**），语义是**只计 vm 里的同步执行**——脚本在等一次嵌套调用（审批弹窗、慢服务器）时 vm 没有在跑，那段时间不计入。它与**同步等待窗口**（固定 30000 ms，见「异步车道」那一条）是两个数：改 `timeout` 只改同步段能占多久，改不了「脚本跑多久之后转后台」。
> - **调用形态 = 裸全局函数**。脚本里写 `await Grep({...})` 这样的裸全局函数，不再写 `tools.<name>({...})`；`tools.<name>()` 作为兼容入口同时保留（Claude Code 两套都提供）。**哪些工具在池里由三个输入决定**（`enableReplCoreTools` / 搜索折叠态 / 工具自述 `defer`），描述与提示里的示例因此只点名池内的工具（照 Claude Code 直接点名，不写限定句）、不得点名默认配置下不可达的 `Read`。非标识符名（含 `-`、`.`）仍走 `tools["<name>"]()`。
> - **两个开关，键名与解析链一致**：`enableRepl`（总开关，默认开——本产品没有独立的 `ToolSearch` 工具，延迟声明的收益只能靠 REPL 的池 + 公告兑现；旧键 `enableExec` 继续接受）与 **`enableReplCoreTools`**（核心工具收进 REPL，默认关；暂不改默认值）。两者都是布尔、都按「远端 managed settings → 本地合并 settings.json → 代码默认值」解析，都能单独下发灰度，且后者是前者的一条输入——`enableRepl: false` 时它无意义。
> - **声明分三档，与 Claude Code 同构**。Claude Code 的呈现是三层，不是两层：
>   1. **带签名内联**——code-mode-only 的核心工具（Read/Glob/Grep/Bash/PowerShell/NotebookEdit）写进 `interface Tools`，每个带 `(input: {...}): Promise<unknown>`，工具级描述截到 120 字符、超长优先断在句末；**我们没有 NotebookEdit，且把 CC 留在 `tools[]` 的 Write/Edit 也一并收进开关**，所以我们的第 1 档是 Read/Glob/Grep/Bash/PowerShell/Write/Edit 七个；**返回类型按工具自己声明的输出 schema 渲染真实 TypeScript 类型，未声明才是 `unknown`（任何情况下都不得写 `Promise<string>`）**：内置工具在 `ToolPlugin.outputSchema`（JSON Schema，写法与入参 `parameters` 相同，随各自的 `XxxResultData` 一起导出）里声明，MCP 工具取服务端声明的 outputSchema；与入参共用同一个 `renderType`，所以返回的对象也展开成字面量类型、可选字段写成 `?`。**这一处有意偏离 Claude Code**——CC 在 2.1.325 内置与 MCP 一律写 `Promise<unknown>`，2.1.331 起 MCP 渲真实类型、内置仍是 `unknown`；它的代价写在 issue #108630 里：95%+ 的 server 不声明 outputSchema，模型只能按描述散文猜字段，猜错就白跑一轮。我们要模型第一次就把 JS 编排写对，所以内置也渲真实类型，`unknown` 只作兜底；**折叠态下的 `Grep` / `Glob` 是例外**：它们落第 2 档只列名字——Claude Code 2.1.331 在折叠态把这两个从签名档挪进名字档（它不想鼓励模型在折叠态走 REPL 搜索），`enableReplCoreTools` 打开也不升档；
>   2. **只列名字**——其余内置在被从 `tools[]` 撤下的情况下拿到 `schema: undefined`，全部塞进一行 `// Also callable as tools.<name>(input); describeTool(name) returns …` 注释；
>   3. **只列服务器名**——MCP 工具**一个名字都不进**声明（`Ir()` 里 `h.isMcp !== !0` 硬过滤），提示词里只有一句 `MCP tools: connected servers are A, B and 3 more. Find a tool with searchTools…`，服务器名去重后最多列 40 个。
>
>   我们采用同样的判据：**开关打开时，"核心工具收进 REPL" 那批带签名内联**（它们是最高频的，只留名字等于每个新会话第一次写脚本都要先搜一次，代价正好落在最常走的路线上）；**其余 deferred 内置只列名字**（低频，列名字足够让模型知道该去搜）；**MCP 只列服务器名 + 指向 `searchTools` 的提示**（数量不可控——一台服务器就可能带几十个工具，逐个列名会让公告随接入规模线性膨胀）。默认（开关关闭）时只有第 2、3 档。签名内联必须复用 `searchTools` 的同一个渲染器，不得另写一份。
>
> - **失败语义对齐 Claude Code**：内置工具失败 resolve 成 `{ error: string }`（失败 = 这个工具没执行成：入参非法、权限被拒、hook 拦下、spawn 报错；**shell 工具的命令非零退出不算失败**，见 `core/bash-tools.md`「退出码不是工具成败」），MCP 工具失败 **throw**。脚本据此决定是否需要 try/catch——内置失败是常态，MCP 失败是异常。MCP 的抛错对象必须带 `toolName`、`error`（工具原始错误文本）与 `detail`（解析后的响应体，若原本是 JSON），并在文案里说明白「这是工具失败，不是脚本语法错误」。
> - **沙箱 globals 这版做五个**：``$`cmd` `` 命令模板、`preview(out)` 结果预览、`self.log(...)` 自述日志、`running()` 后台脚本自省、`tools.list()` 可达工具名。**不做**的有：`write()`/`edit()`/`file()`（与现有 `Write`/`Edit`/`Read`的参数名不一致，且 Claude Code 的 helper 返`{ok}`/`{error}`，等于再教一套失败语义）、`sleep()`（与异步车道抢语义）、`atob()`/`btoa()`（密封里没有正当用途）、`team` 多代理（我们的子代理模型不同，由独立上下文覆盖）。
> - **``$`cmd` `` 这一版补齐 Claude Code 的链式面**：新增 `.cwd(dir)` / `.env({...})` / `.lines()` / `.json()`（`.nothrow()` / `.timeout(ms)` 原本就有），结果对象新增 `output` / `file` / `truncated` / `note`。两处**刻意不照抄**：①`.cwd()` / `.env()` **不**做成 `cd '<dir>' && ` / `export K='v'; ` 的命令前缀，而是在宿主侧派生一份只作用于**本次调用**的工具上下文（换 cwd、按层叠加会话 env）——前缀会把模型写的命令改掉，从而绕过 Bash 自己的「`sleep` 开头不转后台」判断、改写权限规则匹配到的那段命令文本，还会让命令里的 `cd` 经 `onCwdChange` 把整个会话的工作目录带跑；②**退出码语义分两层，与 Claude Code 同层**：家族判定（家族内 1 = 无匹配/有差异，是正常结果）在 shell 工具层做，产出 `success` 与 `data.returnCodeInterpretation`；``$`cmd` `` 这一层**对任何非零退出都 throw**——Claude Code 的 `$` 原文就是「throws on a non-zero exit, as Bun.$」，它只提供 `.nothrow()`。工具的判定随 `note` 进 `ShellError` 的文案，不作为免 throw 的理由。
> - **`$` 没做的字段**：`bytes`（我们的落盘记录是**字符数**不是字节数，报一个假的字节数不如不报）、`whole` / `withheld` / `unsandboxedRetry` / `preview()` 这组（对应 Claude Code 的「读全部 vs 只读一屏」与沙箱重试形态，我们这一版没有那条通道）。缺字段的判据是「模型拿它没法行动」，不是「Claude Code 有我们就得有」。
> - **工具调用次数上限对齐 Claude Code 的 50,000**。旧值 `REPL_DEFAULT_MAX_TOOL_CALLS = 50` 太紧（一个正常编排脚本就能撞上）。语义照抄：越界的那一次不执行，且**本脚本之后的所有调用都不再被回答**（不是拒绝一次然后继续）——这样才能保证一个 runaway 脚本在下一次工具往返时就停下，而不是靠步数慢慢磨。
> - **异步车道这版做，两种形态都做**。①脚本超出**固定的同步等待窗口 30000 ms**（不读模型给的 `timeout`，对齐 Claude Code 的 `30000`）仍在跑 → 回 `(dispatched #N)` 并继续在后台跑；②**全 dispatch 形态**——一次调用只派发、立刻回 `(dispatched #N)`，从不等。并发超出上限（对齐值 8）时**拒绝**而不是排队（排队会让模型以为已经派发），结果作为事件稍后送达，`Poll` 用于显式等待。
> - **结果文本还对齐 2.1.326 的三处细节**：①`<log>` 的粒度是**流**不是行——脚本的全部 stdout 进一个 `<log>`、全部 stderr 进一个 `<log>`（条目之间换行，每条以 `[stderr] ` 开头），逐行拆分会让一段 200 行的构建输出变成 200 个元素；②每部分 30000 字符之外，**整个结果的文本还有 100000 字符**的总上限（对齐 Claude Code 的 `Do=1e5`），越界处截断并写明被砍掉多少字符；③脚本用了 `console.*` 且 ring 里有内容时，结果里必须带一句说明（`[console.log wrote N lines to the console ring, not to this output — use self.log(...) for output you want to see, or read the ring with console.tail()]`）——这是模型最容易踩的一脚。
> - **不自造 `scriptHelper` 标记**：Claude Code 的 `scriptHelper: true` 是它 host 边界上的内部字段，而且它在那一层**主动丢弃**带这个标记的事件（二进制 offset `344367583`：`if(e.scriptHelper===!0)return;`，命中的工具名是 `searchTools` / `describeTool` / `ask` / `haiku` / `opus` / `sonnet` / `fable`）。我们的可见通道是 `ToolBlock.shortResult`，没有那条管道，因此**刻意不对齐「丢弃」**：同一信息落到摘要行上（`searchTools: <query>` / `describeTool: <name>`，不计入 `N tool calls`，失败也出现），也**没有引入** `scriptHelper` 这个标识符——照抄一个我们并不拥有的内部字段名，只会让后来的人以为那条管道存在。
> - **纯文本第二形态是刻意保留的偏离**：脚本没有嵌套调用、没有 `<log>`、也没有被拒的调用时，结果**不套** `<repl-output>`，直接就是那个值（或 `error: …`）。Claude Code 除 dispatch 回执外一律套外壳；我们不套，因为给一个纯值裹一层元素不承载任何模型需要的信息，只是每次都要读过去的一层。

## 用户场景与测试 _(必填)_

### 用户故事：沙箱是一个长驻的 JavaScript 上下文（优先级：P1）

作为连续编排的模型，我希望上一次脚本里算出来的变量和函数在下一次调用里还在，而不是每次都从头再读一遍文件、再跑一遍命令。

**为什么是这个优先级**：这是本形态相对旧 `Exec` 的核心收益。旧形态每次新建上下文，模型只能靠「一次脚本做完全部事」来规避重复 IO；而一个 turn 内多次调用是常态（写一段 → 看结果 → 再写一段），每次重读文件的代价直接落在上下文与延迟上。

**独立测试**：在同一会话连跑两个脚本，第一个 `const n = await Read(...)`，第二个 `return n.file.content.slice(0, 20)`；断言第二个脚本拿到第一个脚本的变量。再跑第三个脚本，用 `const n = 2` 覆盖它（脚本自己定义的名字可复用），断言它读到 `2`。

**验收场景**：

1. **假设** 同一会话的同一 agent 连跑两个脚本，**当** 第二个脚本执行时，**则** 第一个脚本在顶层定义的变量与函数必须可见，且值与当时一致。
2. **假设** 脚本在顶层 `const` / `let` / `function` 一个**受保留的名字**（一个 helper、一个工具名、一个 JavaScript 内建），**当** 脚本提交时，**则** 脚本必须**根本不运行**，返回一条专用错误（`ReplGlobalOverwrite`）说明「该名字是 helper / 工具 / JS 内建，顶层声明会为之后每一次调用覆盖它」，并给出出口「换一个名字，或声明在函数里，那里它是局部的」——对齐 Claude Code：这是提交前的静态拒绝，不是运行期的重复声明错误，`const Read = 1` 这种覆盖内建也照样拦。**受保留的名字只有这三类，且它们是建 context 那一刻的冻结集合**：脚本自己上一轮定义的变量不在其中，重名必须**放行**（语义就是覆盖，下一次调用看到的是新值）。这与 Claude Code 2.1.326 完全同档：`za()` 在 `compile()` 之前拒绝，判据是 `isGlobalName = (N) => snapshot.has(N) || toolWrapperNames.has(N)`（`snapshot` = 建 context 时 `globalThis` 的自有属性 + 装好的 helper，offset 344581398 / 344596664），报错文案自证只有三类（`a helper, a tool or a JavaScript built-in`）。
3. **假设** 用户按 Esc 中断一次运行，**当** 中断完成时，**则** 上下文必须保留：变量、函数、已完成的调用结果都还在，只有那次运行被终止。
4. **假设** 会话执行 `/clear`、或恢复到另一个会话、或一个子代理运行结束，**当** 该事件发生时，**则** 对应的上下文必须被释放（上下文丢弃），不得跨对话泄漏。
5. **假设** 上下文压缩（compaction）发生，**当** 压缩完成时，**则** 上下文**不得**被释放——压缩改的是对话历史，不是运行时状态。
6. **假设** 进程重启或会话 resume，**当** 第一个脚本执行时，**则** 上下文必须是新的；若对话历史里已有过 `REPL` 调用，结果里必须提示「这是一个新上下文，之前脚本里的变量与定时器不在」，不得让模型以为旧变量还在。
7. **假设** 子代理调用 `REPL`，**当** 它执行时，**则** 必须使用属于该子代理的独立上下文，与主线程的变量互不可见；子代理结束时该上下文被释放。
8. **假设** 上一个脚本用 `setTimeout` 排了一个 60 秒后触发、或 `setInterval` 排了一个循环的回调，**当** 该脚本已经结束、下一个脚本执行时，**则** 这些定时器必须已被清除、永不触发；顶层变量与函数仍然可见——「长驻」指的是变量与函数，不是未完成的回调。
9. **假设** 同一上下文上有两个脚本并发（前一个还在 await 一次工具调用），**当** 第二个脚本到达时，**则** 两者必须都能运行（上下文是共享的），且各自的返回值只交给各自的调用；上下文里变量的修改顺序按脚本实际执行顺序，不额外串行化。

### 用户故事：在 REPL 里编排一轮内的多步调用（优先级：P1）

作为使用多个工具（内置或 MCP）的开发者，我希望模型用一次工具调用就能串起多步操作（取数据 → 转换 → 写回），而不是每一步都单独往返一轮。

**为什么是这个优先级**：编排省的是轮次，是「加载更多工具之后还能用得动」的关键。

**独立测试**：给一个脚本同时调用两个池内工具，并把第一步的结果作为第二步的实参，断言两次调用都真实发生且最终返回值是第二步的结果。

**验收场景**：

1. **假设** 脚本写了 `const a = await mcp__srv__fetch({ id: 1 }); return await mcp__srv__store({ value: a });`，**当** 执行时，**则** 两次调用都必须真实发生，脚本能拿到上一次的返回值继续使用。
2. **假设** 脚本 await 某个工具调用，**当** 该调用返回时，**则** 脚本收到的值就是该工具的输出：**内置工具拿到的是它产出的 `data`**（`Glob` 是 `{ numFiles, filenames, truncated }`、`Read` 是 `{ file }`，不是给人看的那段文本），**MCP 工具**是 `structuredContent` 优先；没有结构化内容时，文本若是 JSON 就是解析出来的那个值（对象 / 数组），不是 JSON 才是文本本身；两者都没有则 `null`；**不得再包一层信封**。
3. **假设** 脚本传给工具的实参对象，**当** 调用转发时，**则** 必须逐字段原样透传（不重命名、不补默认值、不做 schema 校验）。
4. **假设** 某个内置工具调用没执行成（`success: false`：入参非法、权限被拒、hook 拦下、spawn 报错），**当** 它返回时，**则** 脚本必须收到 `{ error: string }` 而不是 rejection——脚本不写 `try/catch` 也能继续跑下一步。**命令跑起来、只是退出码非零不算这一类**：shell 工具照常交完整 `data`（`stdout` / `exitCode` / `returnCodeInterpretation`），脚本直接读 `r.stdout` 即可。
5. **假设** 某个 MCP 工具调用失败，**当** 它返回时，**则** 必须 reject，脚本需要 `try/catch` 才能继续；错误文本必须让脚本能判断这是工具失败而不是脚本语法错误。
6. **假设** 脚本调用一个既不在本次调用的 globals 上、也不在池内的名字，**当** 执行时，**则** 必须抛引擎自身的 `ReferenceError` / `TypeError`——对齐 Claude Code：它只有「声明过、但本次调用没给」这一条专用文案（`<name> is not available in this REPL call`），**没有**「未知名字 → 去 `searchTools` 找」这条路径；我们也不造这一条。
7. **假设** 脚本用 `return` 返回一个对象，**当** 执行完成时，**则** 返回值必须序列化后交给模型；**返回值是 `undefined` 时，结果段是空的**——markup 形态写作 `<result/>`（对齐 Claude Code：它把 `result === undefined` 渲染成 `""`，再由元素渲染成自闭合标签），text 形态（无 tools / refused / log / stderr，形态定义见设计取舍「纯文本第二形态」）只在**整条结果什么都没有**时补一句说明。**空结果不解释**，更不得断言「没有日志」——日志、stderr、工具调用各自有元素代言，一句「脚本没有返回值也没有 self.log 输出」压在一串 `<log>` 下面就是自相矛盾。
8. **假设** 脚本用 `self.log(...)` 或 `console.*`，**当** 结果返回时，**则** **只有 `self.log` 进结果的日志段**；`console.*` 进一个有上限的内存 ring，**不随结果返回**，脚本要读它必须自己调 `console.tail(n)` / `console.buffer()` / `console.dropped()`。结果里必须带一句提示（措辞见本故事场景 9），因为这是模型最容易踩的一脚。
9. **假设** 脚本用了 `console.*` 且 ring 里有内容（哪怕一次 `self.log` 都没打过），**当** 结果渲染时，**则** 必须补一句说明，措辞对齐 Claude Code：`[console.log wrote N lines to the console ring, not to this output — use self.log(...) for output you want to see, or read the ring with console.tail()]`，N 取 ring 里的行数；这句走结果的注释通道（与其它宿主注释同一处），不冒充脚本自己的输出。**我们比 Claude Code 宽一档**：它只在捕获的 stdout 为空、ring 非空时才补这句，我们只要 ring 有内容就补——「少量输出 + 一串 ring」才是最容易被误读的组合。
10. **假设** 某个内置工具的 `data` 里带 base64（`Read` 读图片时的 `file.base64`），**当** 这个值进入沙箱时，**则** 必须换成正文字段说明这段内容被移出、真字节只经结果附件回到模型——脚本拿到的是「这里有张图、形状是什么」，而不是几百 KB 的字符串（把它拼进下一步只会得到一坨 base64）。
11. **假设** 内置工具同时产出了 `data` 与给人看的 `content` / `shortResult` / `exitCode`，**当** 脚本 await 时，**则** 只有 `data` 进入脚本，其余形态不得出现在返回值上——脚本要看文本，就自己 `return` 那段 `data` 或改用 `$` 命令模板；扁平工具与脚本两条通道的形状不同，这一点必须写进 `REPL` 的描述。

### 用户故事：沙箱是密封的，脚本拿不到宿主能力（优先级：P1）

作为运维该功能的人，我希望模型的脚本无论写什么都不能读写宿主文件、发网络请求、加载模块或动态编译代码，也不能把宿主对象偷渡回沙箱。

**为什么是这个优先级**：执行的是模型生成、可能来自不可信上下文的代码。隔离不成立，其余一切免谈。

**独立测试**：在脚本里依次尝试 `require`、`import(...)`、`eval`、`new Function`、`process`、`globalThis.fetch`，断言全部不可用；再断言工具函数与返回值的 `constructor` 属于沙箱 realm；最后把某个受管全局改成不可配置，断言得到显式「上下文已重置」而不是一个半坏的上下文。

**验收场景**：

1. **假设** 脚本引用 `require`、`process`、`Buffer`、`module`、`globalThis.fetch`、`XMLHttpRequest`，**当** 脚本执行时，**则** 这些必须是 `undefined`——上下文只注入显式的 globals（`tools` 与 `tools.list()`、`console`、`self` 与 `self.log`、`$`、`preview`、`running`、`searchTools`、`describeTool`、四个定时器、各工具函数），不把宿主 realm 的东西挂上去。
2. **假设** 脚本调用 `eval(...)` 或 `new Function("...")`，**当** 执行时，**则** 必须抛 `EvalError`（`codeGeneration: { strings: false, wasm: false }`），不得执行被编译的代码。
3. **假设** 脚本写 `import x from "y"`、`import("node:fs")` 或 `require("fs")`，**当** 执行时，**则** 必须在**转译期**就被静态扫描拦下（三种形态都要扫），并给出人话错误说明「上下文是密封的」，同时点名可替代的池内工具调用——与 Claude Code 的提示同形（直接点名、不写「以公告为准」类限定）：`await Glob({pattern: "..."})`、`await Grep({pattern: "..."})`，shell 命令用 `` await $`...` ``；**不得点名某个默认配置下脚本不可达的工具**（如 `Read`）；漏网的动态形式再落到 `importModuleDynamically` 的固定抛错桩上，不得出现引擎内部的 callback 报错。
4. **假设** 脚本试图经 `someTool.constructor("return process")()` 回到能编译代码的函数，**当** 执行时，**则** 必须拿不到宿主能力：沙箱内所有函数对象（含每个工具函数、`$`、`self.log`、`preview`）都必须属于沙箱 realm，且 `Function` / `Object` / `String` 等内建构造器对象必须被冻结。
5. **假设** 脚本拿到宿主返回的对象，**当** 该值进入沙箱时，**则** 它必须是**原型为 `null`** 的普通对象、并已删掉 `constructor` 与 `prototype` 字段——不得带着宿主的原型链进来。
6. **假设** 脚本修改它收到的返回值，**当** 修改发生后，**则** 宿主侧数据不得被影响（跨界值深拷贝，跳过 `__proto__` 与函数字段）。
7. **假设** 脚本向宿主发起调用，**当** 实参进入宿主时，**则** 只允许普通数据（普通对象、数组、字符串、数字、布尔、null）；带函数的对象、类实例或原型污染载荷必须被拒绝并把错误回报给脚本。
8. **假设** 脚本把某个受管全局（工具函数、`$`、`self` 等）用 `Object.defineProperty` 改成不可配置，**当** 宿主试图在下一次调用前恢复它时，**则** 必须识别为「上下文已中毒」、丢弃该上下文并返回一条显式说明「REPL 上下文已重置，之前脚本里的变量与函数不在了，请重跑」的错误——不得让一个半坏的上下文继续服务。
9. **假设** 脚本把 `globalThis` 或其原型改坏到新调用无法启动，**当** 下一次调用开始时，**则** 同样必须丢弃上下文并给出同一句显式提示。
10. **假设** 脚本用 ``$`cmd` ``执行 shell 命令，**当** 命令执行时，**则** 它必须走与`Bash` 完全相同的执行与权限路径（不是另开一条），且返回值是纯数据在沙箱内包装成的对象。
11. **假设** 脚本把一个超过 4096 项的数组（或嵌套过深的值）返回给宿主，**当** 值跨界时，**则** 只搬运前 4096 项，并在结果对象上留一个 `truncatedFrom` 标明真实长度；嵌套过深时报明确文案而不是引擎栈溢出——静默截断会让模型把 4096 当成真实长度。
12. **假设** 脚本调用 `tools.list()`，**当** 它返回时，**则** 必须给出本会话**当前可达**的工具名数组；子代理场景下 `tools[]` 可能列出该 agent 其实没被授予的工具，模型必须能先用 `tools.list()` 核对（对齐 Claude Code 的提示语）。

### 用户故事：``$`cmd` `` 的链式方法与退出码语义（优先级：P1）

作为写编排脚本的模型，我希望 shell 调用的返回值能像一次函数调用那样被直接消费（行数组、解析好的 JSON、一段可贴给人看的展示文本、完整输出的落盘路径），并且「没有匹配」这类正常结果不要把整段脚本炸掉。

**为什么是这个优先级**：`$` 是脚本里唯一能跑命令的入口，它 resolve 成什么形状决定了模型要写多少行胶水代码（`stdout.split("\n").filter(Boolean)`、`JSON.parse` + `try/catch`）；而退出码语义决定了 `grep` 一次无匹配会被读成「失败」还是「命令的答案」——后者在真机上的表现是「脚本莫名其妙什么都没做，只回了一段红色错误」，模型很难从那里推断出该怎么改。现在那个答案由工具层给出、跟着 `ShellError` 的文案回到脚本，模型看得见它是什么。

**独立测试**：分别跑 `.lines()`、`.json()`（合法与非法两种输入）、`.cwd()`、`.env()`、家族内退出码 1（必须 throw，且文案带 `[note]`）、家族内退出码 1 加 `.nothrow()`（拿到 `returnCodeInterpretation`）、家族外退出码 1、`sleep` 超时、超大输出九种形态，断言各自的结果形状与是否 throw；再断言 `.cwd()` 不改会话工作目录、`.env()` 不泄漏到后续调用。`cd` 那一格必须有一条**真的起进程**的用例（真的 `Bash` 工具跑 `cd`，不是手写 `content` 字符串）：手写输入曾经漏掉真实形态——真的 `cd` 会把提示拼在工具兜底句前面，于是「整条就是那句」的判据再也匹配不上（真机撞出来的）。

**验收场景**：

1. **假设** 脚本写 ``const files = await $`ls`.lines()``，**当** 命令成功时，**则** 必须 resolve 成按行切分的字符串数组（去掉行尾 `\n`，末尾的空串不算一项）；已 resolve 的结果对象上同样可以 `(await $`ls`).lines()`。
2. **假设** 脚本写 ``const pkg = await $`cat package.json`.json()``，**当** stdout 是合法 JSON 时，**则** 必须 resolve 成解析后的值；**不是**合法 JSON 时则 reject 一个错误（文案说明是 JSON 解析失败并带上原因，不把整段 stdout 塞进错误里），脚本可 `try/catch`。
3. **假设** 脚本读结果对象的 `output`，**当** 命令结束时，**则** 它必须是给**模型/人**看的展示文本：stdout，其后按需追加以 `[stderr]` 开头的工具说明与 `[exit N]`（非零退出）；它只是把 `Bash` 那一份结果原样交出，不参与执行、不改变 `stdout`。`cd` 提示行不属于展示文本（见场景 12）。
4. **假设** 脚本写 ``$`ls`.cwd("/tmp")``，**当** 命令执行时，**则** 命令必须在 `/tmp` 下执行（相对路径按当前会话目录解析），且**不得**改变会话的工作目录——`cd` 提示、后续扁平 `Bash` 调用的 cwd、`onCwdChange` 一律不动，这次调用里命令自己 `cd` 也不得因此变成会话级变化；目录不存在或不是目录时命令**不执行**并返回明确错误。
5. **假设** 脚本写 ``$`printenv FOO`.env({ FOO: "bar" })``，**当** 命令执行时，**则** `FOO=bar` 必须出现在该命令的环境里（子进程继承），且**只影响这一次调用**：不写入会话环境、不污染后续 `$` 调用与扁平 `Bash`；键名必须匹配 `[A-Za-z_][A-Za-z0-9_]*`，不匹配时命令不执行并报错。命令文本本身不得被改写（模型写的什么就核权限、就执行什么）。
6. **假设** 脚本把 `.cwd()` / `.env()` / `.timeout()` / `.nothrow()` 任意串联（顺序无关），**当** 它 await 最外层那个对象时，**则** 全部约束必须同时生效；链式方法返回**新对象**、不改原对象（`const p = $`x`; p.nothrow(); await p` 仍按 throw 语义走）。
7. **假设** 命令是 `grep` / `egrep` / `fgrep` / `rg` / `find` / `diff` / `test` / `[` 之一（取命令行里**最后一个命令词**），或是 `git diff` / `git grep`，**当** 它以 **1** 退出时，**则** ``$`cmd` `` 仍必须 throw `ShellError`——家族判定属于 shell 工具（它给出 `success: true` 与 `data.returnCodeInterpretation`），不属于 `$`；`.nothrow()` 下结果对象的 `note` 就是那份 `returnCodeInterpretation`。对齐 Claude Code：它的 `$` 同样对非零退出 throw，家族只决定 tool result 的 `isError` 与 `returnCodeInterpretation`。
8. **假设** 脚本 await 一次没加 `.nothrow()` 的调用、而它以任意非零码结束（家族内外、任意码），**当** 它结束时，**则** 必须 throw `ShellError`（带 `exitCode` / `stdout` / `stderr`），文案在工具有解释时以 `[note] <解释>` 结尾。`.nothrow()` 是关掉 throw 的**唯一**开关。
9. **假设** 命令以 `sleep` 开头，**当** 它超过等待上限时，**则** 必须被**终止**并返回失败结果（`exitCode` 为终止码、`stderr` 说明是超时终止），**不得**转后台、不得占一个后台槽——转后台等于这条命令永远拿不到结果，而模型写 `sleep` 就是在等。
10. **假设** 命令输出超过 `Bash` 的结果上限（30000 字符），**当** 结果回到脚本时，**则** `stdout` 必须是**预览**（不是 `<persisted-output>` 那层外壳文本），`truncated` 为 `true`，`file` 给出完整输出落盘的真实路径，脚本能用 `Read` 或再跑一条 `` $`grep … ${out.file}` `` 把缺的部分取回；未超限时 `truncated` 为 `false` 且 `file` 不出现。
11. **假设** 结果带 `note`（工具对退出码的解释，如 `grep` 的「无匹配」），**当** await 它时，**则** `note` 只作为信息携带（与 `stderr` 分开：`stderr` 是失败说明，`note` 是退出码的读法），**不**构成免 throw 的理由。
12. **假设** 命令自己 `cd` 到别处（`Bash` 会在结果前面拼一行它自己的提示），**当** 结果回到脚本时，**则** 那行提示必须从 `stdout` 里**剥出来**，作为 `cwdNote` 单独给出，原文两形态照抄：`Shell working directory changed to <dir>` / `Shell cwd was reset to <dir>`；`stdout` 只留命令真正打印的东西——什么都没打印时是空串、`output` 是 `[exit 0]`，有输出时一个字节都不丢。判据是**工具真的移动了 shell**（这次调用里 `onCwdChange` 被调用过），不是文本匹配：命令自己 `echo` 一行同形文字不得被剥（否则 `stdout` 少一行，而「cwd 变了」是假消息）；`.cwd()` 是一次性目录、不移动会话，因此这一格不会出现 `cwdNote`。

### 用户故事：执行预算与终止（优先级：P1）

作为运行长任务的人，我希望脚本卡住时不会挂死会话；反过来，脚本在等一次嵌套调用（审批弹窗、慢服务器）时不该被自己的预算杀死——否则审批结果会落在一次已经死掉的运行上。

**为什么是这个优先级**：不设预算就是让模型的一个脚本挂死整个会话。而且终止必须是**确定性**的，不是尽力而为——确定性只能来自注入到生成代码里的检查（`while (true)` 每转一圈都记一次账），加上 vm 对同步段的 wall-clock 兜底。这也正是「中断只 abort、不重置上下文」能成立的前提：只有能靠代码里的检查停下，才不需要用杀上下文来止损。

**独立测试**：分别跑三个卡死脚本（同步自旋 / 先 await 再自旋 / await 一个永不 settle 的 Promise），断言前两者被预算终止、第三个交由异步车道与墙钟或中断收场，且上下文都保留；再在非询问模式下跑一个嵌套调用耗时远超 `timeout` 的脚本，断言它拿到结果；再在询问模式下跑同一脚本，断言它在上限处被终止；最后把受管全局改成不可配置，断言上下文被重置且提示显式；再跑一个在函数里抛错、由顶层调用的脚本，断言失败文本引述了函数体那行与调用那行的原文、不含列号。

**验收场景**：

1. **假设** 脚本是同步死循环，**当** 步数预算（默认 3 亿步）耗尽、或同步段 wall-clock 先到，**则** 必须被终止并返回失败结果，错误说明是哪一种预算被耗尽（`step budget N steps` / `wall clock N ms`）、提示「已完成的调用照常生效」，且上下文保留。
2. **假设** 脚本先 `await` 一次工具调用、随后进入死循环，**当** 循环继续转时，**则** 同样必须被注入的步数计数器终止——这正是 vm 的 `{ timeout }` 管不到（它只覆盖同步段）、必须靠源码注入记账的地方。
3. **假设** 脚本 await 一个永不 settle 的 Promise，**当** 等待持续时，**则** 它不消耗步数预算也不消耗同步 wall clock（脚本没在跑），运行以异步车道的方式挂着，由墙钟上限或用户中断收场；宿主事件循环不得因此被占用。
4. **假设** 模型给了一次调用 `timeout`（毫秒，**默认 30000、上限 600000**，超出按上限夹取），**当** 脚本执行时，**则** 该值必须是**同步段的 wall clock 上限**：脚本在等嵌套调用时 vm 没有在跑，那段时间**不计入**——这是「等审批、等慢服务器不烧预算」的实现基础，不是一条额外豁免。该值**不**决定同步等待窗口（窗口固定 30000 ms，见「脚本可以在后台继续跑」场景 2）——两个数混成一个，模型写 `timeout: 600000` 就会以为一次调用能同步占住十分钟。
5. **假设** 会话的权限模式**不**要求逐次确认，一次嵌套调用耗时远超 `timeout`（慢服务器、慢 hook），**当** 该调用返回时，**则** 脚本预算不得因此耗尽，脚本拿到结果并继续；等待也不设累计上限——一个永不返回的调用由用户中断收场，`REPL` 不为它另造一条预算（与扁平调用一致）。
6. **假设** 会话的权限模式**要求**逐次确认，**当** 一次脚本里的嵌套调用停在审批弹窗上很久时，**则** 脚本的存活时间必须从启动起算、总计不超过 600000 ms，**且包含等待审批的时间**——这一档是有意收紧的（对齐 Claude Code 原话：`stopped 600000 ms after it starts, counting the time spent waiting on permission prompts`），否则一个人不回来的审批弹窗就能让上下文无限期挂着一个半跑的脚本。
7. **假设** 某次嵌套调用超过自己的闸门仍未返回，**当** 到时，**则** 看门狗必须终止该次调用并把错误回报给脚本，脚本可以继续。闸门是 `ceil(nativeTimeoutMs × 1.5) + 5000`，shell 工具**再加 30000 ms**；`nativeTimeoutMs` 按工具家族取三档，**只有前两档装看门狗**：
   - **① shell 工具**（`Bash` / `PowerShell`）——入参 `timeout`，没给就取它自己的默认 **120000 ms**（工具本体那两分钟）。所以一条不带 timeout 的命令闸门是 `120000 × 1.5 + 5000 + 30000 = 215000 ms`，**不是** 20000 ms。
   - **② 文件与任务家族**（`Edit` / `Glob` / `Grep` / `Task*`）——没有 `timeout` 入参，按 **10000 ms** 计。
   - **③ 其余工具（`Read` / `Write` / MCP / 其它内置）——不装看门狗**：宿主不知道它的预算，编一个基数只会砍掉本来在正常跑的调用。

   算出来的闸门 **≥ 600000 ms 就直接不装**（脚本级上限先到，那个定时器只会打进空气）。这套分档与数值取自 Claude Code 2.1.329 的 `Zo()`（偏移 122990，`Ka` 白名单 → `1e4`，shell 取 `Math.min(入参 ?? 工具默认, 上限)`，其余返回 `undefined`）与 `Oh.arm()`（偏移 427811：`nativeTimeoutMs === undefined` 直接 return、`Math.ceil(t × 1.5) + 5000`、`Of` 命中的工具再加 `30000`、`h >= 600000` 不装；`Of = [Bash, PowerShell]` 见 `0516-3372B-fno.js`）。

8. **假设** 同一脚本里用 `Promise.all` 并发发起多次嵌套调用，**当** 它们都在等待时，**则** 等待窗口是**一个**（脚本整体在等），不是每次调用各暂停一次；任一调用返回后其余仍在等的照旧不计时。
9. **假设** 脚本的嵌套调用次数到达上限（默认 50,000），**当** 越界的那一次发起时，**则** 该次调用必须不被执行，且**本脚本后续的每一次调用都不再被回答**；脚本可以继续跑自己的计算，但结果里必须说明「已到达调用次数上限」。
10. **假设** 用户中断或会话关闭，**当** `AbortSignal` 触发时，**则** 当前运行必须尽快终止并返回失败结果；**且上下文必须保留**（见「长驻上下文」故事 4）。中断之后该脚本**还能再发起最多 20 次**嵌套调用（照常执行、照常返回），**第 21 次起不再被回答**（返回一个永不 settle 的 Promise），已在飞的调用照常收尾——宿主不得把它们当成取消掉的调用去伪造结果，这 20 次宽限是为了让 `finally` 里的收尾还能跑完。
11. **假设** 脚本把某个受管全局改成不可配置、或把 `globalThis` 改坏到新调用无法启动，**当** 宿主在恢复/启动时发现，**则** 必须丢弃该上下文并返回一条显式提示「上下文已重置，之前脚本里的变量与函数不在了，请重跑」。这是**唯一**会丢失上下文的情形（另见「沙箱是密封的」故事 8、9），静默丢弃会让模型继续引用不存在的变量。
12. **假设** 沙箱内部抛错（脚本语法错误、运行时错误、加固检查失败），**当** 宿主捕获时，**则** 必须转成一条失败工具结果（`REPL` 的 Promise 不得 reject），模型总要拿到可据以行动的结果。语法错误这一档必须给出**行列位置 + 出错行原文**，并明说这一档一行都没执行（`The script did not run: it failed to parse, so nothing in it was executed.`，取自 Claude Code 2.1.331 `ReplParseError` 的首句——只看到位置的模型会以为出错行之前的语句已经跑过）；源码含反引号时追加一句「模板字符串在下一个反引号结束、`${` 开始插值，所以含反引号或 shell `${VAR}` 的文本更适合放 `'…'` 字符串，或先写文件再读」，含 `'''`/`"""` 时追加「JavaScript 没有三引号字符串」。这类提示只在失败回执里按源码特征追加，**不得**配任何自动修复、自动转义或重试——解析失败就是一行都不执行（对齐 Claude Code 2.1.325：它的 REPL 执行链只有一次 `sourceType: "script"` 解析，失败即整段拒绝）。运行时错误另有一条同族提示：`TypeError: "…" is not a function` 且源码含**连续两个反引号**时，追加「连续两个反引号会结束一个模板字符串、把下一个字符串当成 tag 调用」的说明（同处 `vPi` 的第一条，判据同为源码特征而非错误消息类型）。
13. **假设** 脚本大量 `self.log`，**当** 日志被收集时，**则** 交给模型的日志必须被字符上限截断（**每部分 30000 字符**，对齐 Claude Code），且截断处要带省略标记，不得用日志撑爆上下文。
14. **假设** 脚本 `return` 的值某一部分超过上限，**当** 结果交给模型时，**则** 该部分必须被截到约 **30000 字符**、**保留头部 60% 与尾部**、中间写 `... [N chars elided] ...`；值是个对象的某个键时，还要追加一句「完整值仍在 REPL 的这个键下，切片或搜索即可，不要重读或重跑它」——扁平调用自身有结果大小上限（超出落盘 + 预览），嵌套调用不加限就比它替代的那次调用更贵。
15. **假设** 整个结果的文本（所有 `<log>` + `<result>`/`<error>` + 注释）超过 **100000 字符**，**当** 它交给模型时，**则** 必须在 100000 字符处截断，并附一行说明还剩多少字符被截掉——分部分的上限管不住部分的数量，这条总闸门是最后一道。
16. **假设** 一次脚本里多次嵌套调用各带回图片，**当** 结果返回时，**则** 脚本侧看到的必须是**文本占位符**（`[N base64 chars — N bytes moved to the REPL result, subject to its per-result cap]`）而不是原始 base64，真字节直通到结果附件；图片数量必须有上限（对齐值 8 张、PDF 4 个），超出部分丢弃并说明。
17. **假设** 脚本在同步段长时间占用（栈深度、正则回溯这类「一步很长」的内建调用），**当** 同步 wall clock 到点，**则** 必须靠 vm 的超时终止，且错误文案说明「步数预算计的是循环与调用，不是一次内建调用内部花的时间」——两者的边界要在文案里讲清楚，否则模型会以为调小步数就能拦住正则。
18. **假设** 脚本在运行期抛错（`TypeError` / `ReferenceError` / 脚本自己 `throw`，也包括步数预算在某个循环里把它停下），抛错点落在脚本某一行，**当** 宿主渲染失败结果时，**则** 错误文本必须是「`<错误名>: <消息>`」后接一段引述：标题行 `Thrown at (statements quoted from the script):`，之下取栈里属于脚本的帧（**最多 4 帧**，相邻重复只留一条），每帧一行 `  in <函数名或 <anonymous>> (line N): <该行脚本原文>`（行文本截 200 字符）。**不得**报列号，也**不得**引述注入后的代码：步数计数器是按**同行**注入的，行号保真而列号已漂移（同一行每个 call / await 之前多 14 个字符），模型拿着 `28:67` 去数列会数到别处；引述的必须是模型写的那一行。落在脚本最后一行之后的包装代码（`try` / `finally` / IIFE）不参与引述。对齐 Claude Code 2.1.331 的 `xYr`：它同样丢弃列号、改为引述语句行（它的插桩也是同行文本拼接）；行号是我们多给的——它准，且只占几个字符。

### 用户故事：脚本可以在后台继续跑，结果稍后送达（优先级：P1）

作为跑长测试或长构建的模型，我希望脚本超出同步等待窗口后不必让我干等，结果到了自动出现在我的上下文里。

**为什么是这个优先级**：一次 20 分钟的测试套件如果必须同步等待，就是一个 turn 被占死 20 分钟；而模型真正需要的只是「跑完了告诉我」。

**独立测试**：跑一个睡过窗口的脚本，断言第一次调用返回 dispatch 回执而不是结果；断言结果稍后作为一条事件消息出现在对话里；断言 `Poll` 能在结果到达前返回状态、到达后返回结果；再断言并发到达上限时是拒绝而不是排队。

**验收场景**：

1. **假设** 脚本在同步等待窗口内完成，**当** 它结束时，**则** 结果必须作为该次 `REPL` 调用自身的结果返回，形态与同步执行一致。
2. **假设** 脚本超过同步等待窗口仍在跑，**当** 窗口到期时，**则** 该次 `REPL` 调用必须返回一条 dispatch 回执（形如 `(dispatched #N)`，N 即 `evalId`），脚本继续在后台运行，且不再阻塞它之后的脚本。窗口是**固定 30000 ms 的常量**，与模型给的 `timeout` 无关：`timeout: 600000` 不得把它拉长（那只放宽同步段的 wall clock），`timeout: 5000` 也不得把它缩短；唯一例外是询问权限模式，那一档窗口是 600000 ms 且**终止**而不是转后台（见「执行预算与终止」场景 6）。
3. **假设** 脚本结束、结果要交给模型，**当** 渲染结果时，**则** 必须是 `<repl-output eval="N" ms="M">` 元素，子元素按固定顺序出现：`<tools>`（这次调了哪些工具）、`<refused>`（被拒或被拦的调用）、`<log>`（**每个流一个**：全部 `self.log`/stdout 拼成一个 `<log>`，全部 stderr 条目拼成另一个 `<log>`，每条以 `[stderr] ` 开头、彼此以换行分隔）、然后是 `<error>` 或 `<result>` 二选一；**脚本没有产生的那一段不出现**（不写空的 `<tools/>` / `<refused/>` —— 真机上模型会把它们读成「宿主拒了某一步」）；出现但内容为空时才写作 `<tag/>`；文本里的 `&`、`<`、`>` 必须转义成 `&amp;` `&lt;` `&gt;`。这是对齐 Claude Code 的形态，模型实际读到的就是它。
4. **假设** 脚本没有嵌套调用、没有 `<log>`、也没有被拒的调用（只有一段返回值，或只有一条错误），**当** 渲染结果时，**则** 必须**不套** `<repl-output>` 外壳，直接给出结果值本身（失败时是 `error: …`；若同时还有宿主注释，则按 `stdout:` / `stderr:` / `error:` / `result:` 分段），不得把裸控制字符或空元素交给模型。触发条件是「无 tools、无 refused、无 log」，三者任一出现就回到 markup 形态。这是**有意偏离 Claude Code 的地方**：它除 dispatch 回执外一律套外壳；我们让一个纯值保持是纯值。
5. **假设** 一个后台脚本终于结束，**当** 结果就绪时，**则** 必须作为一条事件消息送达（外壳 `<event kind="repl-eval">`，内含上面那个 `<repl-output>`），在下一个 turn 之前或 `Poll` 的结果里被模型读到。
6. **假设** 有后台脚本仍在运行，**当** 组装下发内容时，**则** 必须有状态信号说明还有什么在跑（`<event kind="repl-status">`，属性 `pending` 为在跑的条数），且该信号不得干扰缓存前缀。
7. **假设** 模型在没有其它事可做时等待长脚本，**当** 它调用 `Poll` 时，**则** `Poll` 必须在有东西到达时立即返回；没有东西到达时，必须在缓存过期前返回一条状态行说明还有什么在跑，而不是无限挂住；一次投递装不下的事件必须带「后续还有，按最旧优先」的标记，不得静默丢弃。
8. **假设** 同一 turn 里既有 `REPL` 调用又有 `Poll`，**当** `Poll` 执行时，**则** 它必须等待该 turn 的脚本；脚本已经返回则 `Poll` 立刻结束。
9. **假设** 一个后台脚本已经发出 dispatch 回执，**当** 模型再次提交同一段脚本时，**则** 宿主**不做**去重：回执文本与结果里的 `evalId` 让模型自己判断，提示词必须写明「回执意味着它已经在跑（或已排队），再发就会跑两遍」。我们若在宿主侧无条件去重，模型就无法故意重跑一个脚本。
10. **假设** 后台脚本运行超过墙钟上限（默认 2 小时），**当** 上限到达时，**则** 必须终止它并把失败结果作为事件送达。
11. **假设** 同一上下文里有多个后台脚本，**当** 并发数到达上限（对齐值 8）时，**则** 新提交的脚本必须**直接返回一条错误结果**说明「已达并发上限，先用 `Poll` 等它们 settle」并标记为 dispatch 形态，**不得排队、不得启动**——排队会让模型以为已经派发。
12. **假设** 后台脚本属于一个子代理，**当** 子代理结束时，**则** 它启动的后台脚本必须被终止，其未送达的结果丢弃。
13. **假设** 会话启用了「全 dispatch」形态，**当** 模型调用 `REPL` 时，**则** 该次调用必须只派发、立刻返回 `(dispatched #N)`，**从不等脚本**；结果随后以事件送达——两种形态共存时以配置为准，且不得出现「同一个脚本既回了结果又发了一次事件」。
14. **假设** 模型想确认后台脚本的状态或终止其中一个，**当** 它调用 `running()` 时，**则** 必须返回列表，每项含 `id`、`snippet`（脚本片段）、`ageMs`、`state`、`settled`、`self`（是否由当前脚本发起）、`abort()`；`abort()` 必须能终止该脚本。这是异步车道的自省出口，缺了它模型只能盲等 `Poll`。

### 用户故事：开关把核心文件与 shell 工具也收进 REPL（优先级：P2）

作为希望模型尽量用代码编排的高级用户，我希望可以让 `Read`、`Glob`、`Grep`、`Bash`、`PowerShell`、`Write`、`Edit` 这些核心工具也只在脚本里可达，从而让 `tools[]` 进一步变短。

**为什么是这个优先级**：默认关闭。它把最高频的调用从「一次工具调用」变成「一层脚本包裹」，值不值得取决于使用者的工作形态；而 Claude Code 是把这一档作为 code mode 的默认形态的。

**独立测试**：开关打开时断言这七个工具不在 `tools[]` 里、在池里、可被脚本调用、公告里**带签名**出现；开关关闭时断言它们在 `tools[]` 里、不在池里、不在公告的任何一档。另外两条反向用例：同一档里平铺调用 `Bash` 必须拿到错误结果且**命令真的没跑**（用文件副作用判据，不看文案）；脚本内 `await tools.Bash({...})` 必须照常执行。

**验收场景**：

1. **假设** `enableReplCoreTools` 未配置或为 `false`（默认），**当** 组装工具声明时，**则** `Read`/`Glob`/`Grep`/`Bash`/`PowerShell`/`Write`/`Edit` 必须照常扁平声明、**不进池**——脚本里 `typeof Read === "undefined"`，`await Read({...})` 抛 `ReferenceError`，模型要读文件就直接调 `Read` 工具而不是在脚本里写（没有「两边都有」这一档：进池与否与是否平铺是同一个判定）。`Glob` / `Grep` 在搜索折叠态下例外：只进池、不平铺，见「搜索折叠态下的 Grep / Glob 只在脚本里可达」。
2. **假设** `enableReplCoreTools: true`，**当** 组装工具声明时，**则** 这七个工具必须全部从 `tools[]` 撤下、进入池、并且可被脚本调用。
3. **假设** 开关打开，**当** 渲染公告时，**则** 这七个工具必须落在**带签名的那一档**（不只是名字）——它们是最高频的，让模型每个新会话第一次写脚本前都先搜一次，等于把成本压在最常走的路上；描述按公告的宽度截断，完整形状仍经 `describeTool` 取。
4. **假设** 开关关闭，**当** 渲染公告时，**则** 这七个工具不得出现在任何一档里（它们在 `tools[]` 里带完整定义）。
5. **假设** 开关打开且模型直接调用 `Read`，**当** 该调用发生时，**则** 必须得到一条明确指引（「只能在 REPL 脚本里用」），而不是「未知工具」。
6. **假设** 开关打开，**当** 渲染池内工具的形状时，**则** `Bash` / `PowerShell` 的声明必须与平铺时**逐字相同**，**含 `run_in_background`**：脚本里 `await tools.Bash({ command, run_in_background: true })` 真的会启动后台任务、立刻回 `backgroundTaskId`（含 `backgroundOutputPath`），命令结束时走既有后台任务通知链路；不传该参数时行为与今天完全一致（同步等待、超时按 `sleep` 判据决定转后台还是终止）。池条目里的 schema 是公告签名、`searchTools` 命中与 `describeTool` 共用的同一份，所以剥掉它等于对模型谎报能力。对齐 Claude Code：它的 Bash schema 只在**后台任务被禁用**时才 `.omit({ run_in_background: true })`（2.1.331 `0766-6267394B-AL.js:244495`），与是不是 code mode 无关。
7. **假设** 开关打开后 `REPL` 被权限规则拒绝或被 `enableRepl: false` 关掉，**当** 组装声明时，**则** 这七个工具必须立即回到扁平声明——撤退必须是无损的。
8. **假设** `enableReplCoreTools` 在服务端下发与本地 settings.json 里取值冲突，**当** 合并配置时，**则** 服务端优先（与 `enableRepl` 同一条解析链）。
9. **假设** `enableRepl: false` 而 `enableReplCoreTools: true`，**当** 组装声明时，**则** 这七个工具必须照常扁平声明——总开关关闭时二级开关不生效，不得出现「工具既不在 `tools[]` 也不可达」。
10. **假设** 运行中修改 `enableReplCoreTools` 触发配置热重载，**当** 重新评估时，**则** 七个工具的池内/扁平两种形态必须即时切换，无需重启会话。
11. **假设** 模型发出一个**本轮 `tools[]` 里没有**的工具名（池化的核心工具、池化的 MCP 工具、被权限规则过滤掉的名字，或根本不存在的名字），**当** 该调用发生时，**则** 必须在执行之前被拒——不进权限判定、不跑 PreToolUse、工具本体一次都不跑——并回一条 `is_error` 的工具结果：**在池里的名字**给「只能在 REPL 脚本里用」并附**可逐字照抄**的调用形态（`await tools.Bash({...})`；非标识符名走 `tools["mcp__my-srv__x"]({...})`），**不在池里的名字**给「本轮没有这个工具，用你已有的继续」；注册表只用来挑这两句话，不参与「能不能跑」的判定（对齐 Claude Code「每个 `tool_use` 先查本轮 `tools[]`」，见问答「平铺调用了池内工具怎么办」）。
12. **假设** 脚本内调用池内工具（`tools.Bash(...)` 或 `$`），**当** 该调用发生时，**则** 场景 11 的校验**不得**生效——模型声明的是 `REPL`，脚本可达的是整个池，这条链路是「已声明之后的二次入口」，与模型直接平铺调用是两回事。

### 用户故事：搜索折叠态下的 `Grep` / `Glob` 只在脚本里可达（优先级：P2）

作为模型，我希望在 `Grep` / `Glob` 被「搜索折进 Bash」收起时，仍能在 REPL 脚本里拿到结构化搜索（匹配计数、`files_with_matches`、`**` 模式的文件列表），因为 Bash 影子只给文本，编排时我要的是对象。

**为什么是这个优先级**：折叠是与 Claude Code 对齐的既定设计（[fs-tools.md](./fs-tools.md)「高效代码探索」），省的是顶层 `tools[]` 的体积与一次工具往返；但「只要计数 / 只要文件名 / 多个模式串起来筛」这类需求，影子 `grep` 要模型自己解析文本，结构化 `Grep` 一次给对象。Claude Code 2.1.331 的形态是**注册但顶层不可达**：折叠只拒平铺调用（文案指路 `await Grep({...})`），REPL 池始终含两者（`CODE_MODE_ONLY_TOOLS` 成员），公告把它们降到只列名字；我方此前实现成「不注册」，池由已注册工具构建 ⇒ 多切了 REPL 这一层——本故事把它补回来。

**独立测试**：默认工具集（有 bash、未点名、`enableRepl` 默认开）下断言 `Grep` / `Glob` 不在 `tools[]`、在池里、`tools.list()` 含两者；脚本 `await Grep({ pattern })` 返回结构化 `data`；公告里只有名字、无签名；`describeTool("Grep")` 返回完整 schema；平铺调 `Grep` 被 `is_error` 拒且工具本体没跑（文件副作用判据）；Bash 描述仍是 `grep -rn` 档；`enableRepl: false` 时两者两个入口都没有；`--tools Grep` 时两者回到 `tools[]`。

**验收场景**：

1. **假设** 会话处于搜索折叠态（未以 `--tools` 点名、有可用 bash）且 `REPL` 已声明，**当** 组装工具声明时，**则** `Grep` / `Glob` 不得出现在 `tools[]`，但必须进入池、可被脚本调用——两者只走一条入口，不得同时出现在两边。
2. **假设** 处于折叠态，**当** 渲染公告时，**则** 两者必须落在**只列名字**那一档，不得带签名——对齐 Claude Code 2.1.331：折叠态它把这两个从签名档挪到名字档，不鼓励模型在折叠态走 REPL 搜索；`enableReplCoreTools` 打开也一样（`Read` / `Bash` / `Write` / `Edit` 带签名，`Grep` / `Glob` 仍只列名字）。
3. **假设** 处于折叠态，**当** 模型在脚本里 `describeTool("Grep")` 或 `searchTools("Grep")` 时，**则** 必须拿到与注册表同源的完整 schema 与输出类型——只列名字不等于拿不到形状。
4. **假设** 处于折叠态，**当** 模型平铺调用 `Grep` 或 `Glob` 时，**则** 按「开关把核心文件与 shell 工具也收进 REPL」场景 11 在执行前被拒，文案给可照抄的 `await tools.Grep({...})`，不得回「未知工具」。
5. **假设** 处于折叠态，**当** 渲染 Bash 工具描述时，**则** 它必须仍是「Use `grep -rn` in Bash」那一档——判据是「本轮是否扁平声明了 `Grep` / `Glob`」，不是「是否已注册」（fs-tools.md 场景 14）。
6. **假设** 处于折叠态但 `REPL` 未声明（`enableRepl: false`、被权限规则拒绝、`--tools` 没点名它），**当** 组装声明时，**则** 两者两个入口都没有——与 REPL 从未存在时一致；注册表可以留着（历史转录重放），但 `tools[]` 与池都不得出现。`REPL` 恢复声明时两者必须跟着回到池里，无需重启。
7. **假设** 以 `--tools` 点名了 `Grep` 或 `Glob`，或会话没有可用 bash，**当** 组装声明时，**则** 折叠态解除：两者按 `Read` 同款口径走——`enableReplCoreTools` 关时在 `tools[]` 带完整 schema、不在公告里；开时进池带签名、离开 `tools[]`。
8. **假设** 子代理被启动，**当** 它组装自己的池时，**则** 遵守同一口径（折叠态下两者在池里、不在 `tools[]`）。
9. **假设** 处于折叠态，**当** 脚本调用 `tools.list()` 时，**则** 列表含两者——`tools.list()` 报告的是池，不是 `tools[]`。

### 用户故事：公告分档呈现（优先级：P1）

作为模型，我希望在池变化时收到一条消息，告诉我当前可以从沙箱调用哪些工具；**最高频的那批**附带可直接照抄的签名，其余内置只给名字，MCP 只给服务器名与搜索入口。

**为什么是这个优先级**：公告是池收敛之后模型唯一的能力地图。**漏掉一个工具等于宣称这个能力不存在**，是本功能最坏的失败模式；而"最高频的也必须先搜一次"则是把成本压在每天的常规路线上；反过来把 MCP 工具逐个列名，会让公告随接入的服务器数量线性膨胀。

**独立测试**：渲染一个含核心工具（开关打开）、其他延迟内置与多个 MCP 服务器的池，断言第一档带签名、第二档只有名字、MCP 只以服务器名出现在搜索提示里；再断言同一份池两次渲染逐字节相同。

**验收场景**：

1. **假设** 池里有一批被判定为"核心工具"的工具（见「开关把核心文件与 shell 工具也收进 REPL」），**当** 渲染公告时，**则** 它们必须带**可照抄的签名**（工具名、参数与返回类型，由 `searchTools` 的同一个渲染器产出），且工具级描述必须被截到一条的宽度（约 120 字符，超长优先断在句末），不得整段写入。
2. **假设** 池里还有其他延迟内置工具，**当** 渲染公告时，**则** 它们必须只以**名字**出现（可归入一行"这些也能调、用 `describeTool(name)` 取完整形状"的提示），不得带参数签名、不得带描述、不得带分组标题。
3. **假设** 池里有 MCP 工具，**当** 渲染公告时，**则** 它们的**工具名一个都不得出现**，只能出现其所属服务器的名字（去重、顺序确定）加一句"用 `searchTools` 找工具，按其返回的入参调用"的提示——对齐 Claude Code；服务器名数量必须有上限（默认 40），超出部分合并为 `and N more`。
4. **假设** 池里有非延迟工具，**当** 渲染公告时，**则** 它们不得出现（已在 `tools[]` 里带完整定义）。
5. **假设** `REPL` 自己也是本会话的工具，**当** 渲染公告时，**则** 它不得出现在公告里。
6. **假设** 池有多条工具，**当** 渲染公告时，**则** 输出中不得出现任何数量、预算、字符数、时间戳或连接状态（服务器名的 `and N more` 是唯一例外，它是名字列表本身的省略标记）。
7. **假设** 池未变化，**当** 两次渲染公告时，**则** 文本必须逐字节相同；`REPL` 在 `tools[]` 里的描述必须与池无关。
8. **假设** 池很大（例如接入了几十个内置延迟工具），**当** 渲染公告时，**则** 第 2 档的名字仍必须完整列出（不轮转、不省略）——第 1 档可以截描述但**不得截名字**，只有第 3 档的服务器名有数量上限。
9. **假设** 某个核心工具的签名在截断后丢掉了关键信息，**当** 模型需要完整形状时，**则** 它必须能经 `describeTool(name)` 或 `searchTools` 取到未裁剪的版本，且三者（公告摘要、搜索结果、运行时校验）必须来自同一份 schema。
10. **假设** 一个 MCP 服务器连上或断开，**当** 渲染公告时，**则** 只有服务器名列表变化，工具名永不出现——因此单台服务器带几十个工具也不会让公告变长。
11. **假设** 某个核心工具声明了输出 schema，**当** 渲染它的签名时，**则** 返回类型必须是由该 schema 渲染出的真实 TypeScript 类型（嵌套对象也展开，例如 `Promise<{ numFiles: number; filenames: string[]; truncated: boolean }>`）；**未声明**输出 schema 的工具写 `Promise<unknown>`；**任何情况下都不得写 `Promise<string>`**——那个类型会让模型以为返回值是一个能 `.split()` 的字符串。

### 用户故事：公告作为尾部消息增量播报（优先级：P1）

作为模型，我希望在池发生变化时收到一条公告消息，而不是每次请求都重新读一遍工具声明。

**为什么是这个优先级**：`tools[]` 位于缓存前缀内，池一变就改写它等于每连一台服务器就击穿一次前缀。

**独立测试**：让池从「空」变到「非空」、再变到「另一套服务器」，断言每次变化都追加一条新消息、历史消息逐字节不变、状态未变时不重复播报。

**验收场景**：

1. **假设** 池非空且 `REPL` 已声明，**当** 组装 `tools[]` 时，**则** `REPL` 的 description 必须是**与池无关的常量**。
2. **假设** 会话从未播报过公告且池非空，**当** 组装下一次请求时，**则** 必须在消息尾部追加一条 `isMeta` 公告消息，且它必须已经出现在本次请求里。
3. **假设** 池的公告内容发生变化，**当** 播报时，**则** 只允许向尾部追加消息，历史里任何已有消息必须逐字节不变。
4. **假设** 池内容与上一次播报时相同，**当** 组装请求时，**则** 不得重复播报。
5. **假设** 上下文压缩把之前那条公告吃掉了，**当** 下一次组装请求时，**则** 必须重新播报一份完整公告（「重复优于丢失」）。
6. **假设** 池在两次播报之间发生变化，**当** 播报时，**则** 必须重发完整的名字列表，不得发增量。
7. **假设** `REPL` 因开关关闭或被权限拒绝而不再声明，**当** 播报时，**则** 必须追加一条「公告不再适用」的消息；通道重新打开而池未变时必须重新播报完整公告。
8. **假设** 宿主或测试替身没有提供这条通道，**当** 组装请求时，**则** 必须静默跳过，不得把它读成「池已清空」。

### 用户故事：在沙箱内搜索工具形状（优先级：P1）

作为模型，当我看到公告里的某个名字、却不知道它的参数形状时，我希望能在同一个脚本里先搜索、再调用。

**为什么是这个优先级**：公告只给名字（或只给最高频那批的签名），所以搜索是其余延迟工具的唯一 schema 通道；搜索不到就等于这个能力不可用。

**独立测试**：在一个池里放若干名字相近的工具，断言按精确名搜索只返回那一条并排首位；断言结果数默认 8、传 `max` 不得超过 25；断言空查询抛错；断言 `describeTool` 在超长描述与超长 schema 上按 4000 / 6000 / 15000 截断并带「取完整」提示；断言这两个 helper 出现在结果摘要行里（`searchTools: <query>` / `describeTool: <name>`，参数截 200 字符）但不移动 `N tool calls`，且失败（空查询抛错、`{ error }`）时行照样在。

**验收场景**：

1. **假设** 脚本调用 `searchTools("...")`，**当** 查询执行时，**则** 首参必须是**字符串**（对齐 Claude Code 的 `searchTools(query: string, max?: number)`），在宿主侧对完整池做本地匹配并返回结果，不需要额外模型往返。
2. **假设** 查询命中某个工具，**当** 结果返回时，**则** 每条含 `name`、`about`（描述，截 **160** 字符）、`input`（入参 TypeScript 类型文本）与 `output`（返回类型 TypeScript 文本，与公告签名同一个渲染器；未声明输出 schema 的工具是 `unknown`——对齐 Claude Code 2.1.331 的 `searchTools` 形状），返回值是对象数组而非 JSON 文本。
3. **假设** 模型已经看到公告里的某个名字，**当** 用它作为查询时，**则** 必须按精确名短路、只返回那一条并排首位，不做模糊扩散。
4. **假设** 查询串形如 `mcp__srv__x`，**当** 池里有同前缀的工具时，**则** 必须按前缀命中它们，且 MCP 工具在打分上加权更高。
5. **假设** 查询串里有以 `+` 开头的词（如 `+slack +message`），**当** 匹配时，**则** 这些词必须**全部命中**（AND 语义），其余词只参与打分。
6. **假设** 查询是普通关键词，**当** 排序时，**则** 必须按匹配强度分级（名字全等 > 整词 > 子串 > `searchHint` > 描述正则），同级内 MCP 加权更高，且排序必须确定。
7. **假设** 查询是关键词，**当** 结果返回时，**则** 条数默认 **8**，可由第二个参数调整但宿主侧硬上界 **25**；结果里**没有** `total` 字段（那是独立 `ToolSearch` 工具的结果形状，不是 REPL globals 上的）。
8. **假设** 查询串为空、为空白、或首参不是字符串，**当** 搜索执行时，**则** 必须抛错并给出正确用法（`searchTools: pass the words to look for, e.g. searchTools('slack message')`），**不得**按空查询返回整个池。
9. **假设** 某个工具带有 `searchHint`，**当** 它参与匹配时，**则** 该短语必须计入打分，且不得出现在公告里。
10. **假设** 脚本调用 `describeTool(name)`，**当** 该名字在池内时，**则** 必须返回描述与 `inputSchema`，且 `inputSchema` 是**该条目原始的 JSON Schema 对象**（对齐 Claude Code 的 `inputSchema: EIo(...)`），不是 TypeScript 文本；另带 `output`——返回类型的 TypeScript 文本（未声明输出 schema 则为 `unknown`），与签名共用同一个渲染器；描述上限 **4000** 字符；schema 仍有字符预算（单条 **6000**），但预算是**先丢注释、不丢结构**：超预算时先去掉 `description` / `examples` / `default` 这类注释关键字，仍超则只留参数名、类型与 `required` 并附一句说明——**`inputSchema` 在任何情况下都必须是对象**，不得退回字符串（字符串 schema 没法被程序化使用，模型只能再猜一次）。`searchTools` 一侧的 `input` 仍是 TypeScript 文本（单条约 6000、单次总 **15000**），被截处附「这部分被省略了，`describeTool` 返回的是完整 schema」的注释。不在池内时返回明确错误。三者（公告摘要、搜索结果、运行时校验）必须来自同一份 schema。
11. **假设** 脚本从未调用过 `searchTools`，**当** 它读 `REPL` 的描述时，**则** 必须能直接读到 `searchTools` 自身的参数名与返回类型（它是唯一不能靠搜索得知形状的入口）。
12. **假设** 池里同时有内置延迟工具与 `mcp__` 前缀的工具，**当** 渲染签名时，**则** 合法标识符名用 `Read(...)` / `tools.Read(...)`，非标识符名用 `tools["<name>"](...)`。
13. **假设** `searchTools` / `describeTool` 被调用，**当** 执行时，**则** 它们**不是**工具调用（不触发 hook、不计入调用次数），但必须在**结果摘要行**里出现：形态是 `searchTools: <query>` / `describeTool: <name>`（参数照 Claude Code 的做法截 **200** 字符），**不计入** `N tool calls`；查询为空而抛错、`describeTool` 返回 `{ error }` 时这一行照常出现——这一行回答的是「脚本刚才在做什么」，不是「这次查找成功了吗」。

### 用户故事：嵌套调用复用同一套权限（优先级：P2）

作为用户，我希望 REPL 里的每一次嵌套调用都经过与直接调用完全相同的权限确认。

**独立测试**：让一次嵌套调用命中拒绝规则，断言调用被拒绝且理由回到脚本；再让它命中「总是允许」规则，断言不再询问。

**验收场景**：

1. **假设** 嵌套调用的某个工具没有匹配的权限规则，**当** 该调用发生时，**则** 必须与扁平调用一样弹出确认；用户选择「是，不再询问」后必须以叶子工具全名保存持久规则。
2. **假设** 已存在针对某个叶子工具全名的允许规则，**当** REPL 内调用它时，**则** 必须直接执行，不按 `REPL` 这个外层工具名匹配。
3. **假设** 已存在拒绝规则，**当** REPL 内调用它时，**则** 必须被拒绝，理由作为该次调用的结果回到脚本（内置是 `{ error }`，MCP 是 rejection）。
4. **假设** `REPL` 自身被权限规则拒绝，**当** 模型调用它时，**则** 拒绝必须发生在工具层，不得进入沙箱。
5. **假设** 会话的权限模式要求逐次确认，**当** 一次脚本里有多次嵌套调用时，**则** 每一次都必须单独过闸，不得因为外层已经批准而整体放行。

### 用户故事：嵌套调用触发同一套 hook（优先级：P2）

作为用户，我希望 REPL 里的每一次嵌套调用都跑一遍与直接调用相同的 PreToolUse / PostToolUse hook。

**独立测试**：配置 matcher 指向池内工具名的 PreToolUse hook，让脚本调用它，断言 hook 被执行且能拦下该次调用。

**验收场景**：

1. **假设** hook 的 matcher 指向某个池内工具，**当** 脚本调用它时，**则** PreToolUse 与 PostToolUse 都必须触发，按叶子工具全名匹配。
2. **假设** PreToolUse 以 exit 2 退出，**当** 该调用发生时，**则** 该次调用必须失败（内置返回 `{ error }`，MCP reject），错误文本为 `PreToolUse:<叶子工具名> hook error: <stderr>`。
3. **假设** PostToolUse 以 exit 2 退出，**当** 该调用完成时，**则** 对话里新增一条 `isMeta` 用户消息（与扁平调用同形），脚本照常继续。
4. **假设** 一次嵌套调用被 PreToolUse 拦下，**当** 生成结果摘要时，**则** 它照常计入调用次数并参与列出。
5. **假设** hook 自身抛错或超时，**当** 处理结果时，**则** 该次嵌套调用照常执行（fail-open）。
6. **假设** 模型直接调用 `REPL` 本身，**当** hook 评估时，**则** `REPL` 自己的 hook 照常触发；沙箱内的 `searchTools` / `describeTool` 不是工具调用，不触发 hook。

### 用户故事：启用开关与回退（优先级：P2）

作为管理员或用户，我希望 REPL 默认开启，并可通过配置显式关闭、退回扁平声明形态，**不发生任何能力损失**。

**为什么默认开**：本产品没有独立的 `ToolSearch` 工具，「把 `tools[]` 变短、按需发现」这层 defer 收益只能靠 REPL 的池 + 尾部公告兑现；关掉它等于放弃 defer，所以默认开、关掉只是回退形态。这与 `enableReplCoreTools` 的默认值无关——后者只决定最高频的七个工具要不要进池。

**独立测试**：分别以未配置（默认开启）、`true`、`false`（外加服务端下发相反值）三种情况断言 `REPL` 的注册与否，以及池内工具是否回到扁平声明。

**验收场景**：

1. **假设** 未配置 `enableRepl`（旧键 `enableExec` 等价），**当** 会话初始化时，**则** 按代码默认值（开启）注册 `REPL`，池内工具从扁平声明中撤下、改由尾部公告呈现。
2. **假设** 配置 `enableRepl: false`，**当** 会话初始化时，**则** `REPL` 不注册；MCP 工具与被判定为延迟的内置工具都必须照常扁平声明、照常可调用。
3. **假设** 服务端下发 `enableRepl`，**当** 合并配置时，**则** 远端值优先于本地 settings.json 与代码默认值。
4. **假设** 运行中修改开关触发配置热重载，**当** 重新评估工具注册时，**则** `REPL` 必须即时注册/注销，无需重启会话。
5. **假设** 通过 `tools` / `disallowedTools` 把 `REPL` 排除，**当** 组装声明时，**则** 与关闭开关同等处理。
6. **假设** 用户把某个内置工具加入非延迟名单，**当** 组装声明时，**则** 该工具回到扁平声明、从池与公告中消失，不需要关闭整个 REPL。
7. **假设** `enableReplCoreTools` 被打开后又关闭，**当** 关闭生效时，**则** 那七个工具必须回到扁平声明、从池与公告中消失，且它们各自原有的能力不受影响。

### 用户故事：结果摘要列出实际的内层调用（优先级：P2）

作为用户，我希望 REPL 调用的折叠行与结果行直接告诉我这次脚本调用了哪些工具、每个工具在操作什么。

**独立测试**：让脚本依次调用一个带 `formatCompactParams` 的工具和一个没有带它的工具，断言折叠行只显示模型自己写的描述、结果摘要首行是调用次数、其后逐行是「工具名 + 紧凑参数」，没有紧凑参数的那个只写工具名。

**验收场景**：

1. **假设** 脚本发生了 N 次嵌套调用，**当** 生成结果摘要时，**则** 首行是调用次数，且不得出现 `REPL` 字样。
2. **假设** 脚本调用了池内工具，**当** 生成结果摘要时，**则** 首行之后逐行列出调用，每行是「工具名 + 紧凑参数」，与 `Agent` 工具的短结果同一套：参数取该工具自己的 `formatCompactParams`；工具没提供时退回参数的扁平化尾部（超过 30 字符时前置 `…`）；参数为空或 `{}` 时只写工具名。
3. **假设** 嵌套调用次数超过 2，**当** 生成结果摘要时，**则** 只列出最近 2 次，且首行以 `... ` 开头。
4. **假设** 脚本尚未结束，**当** 某次嵌套调用发生时，**则** 结果摘要必须立即更新。
5. **假设** 脚本没有发生任何嵌套调用，**当** 脚本结束时，**则** 结果摘要为 `0 tool calls`。
6. **假设** 脚本以失败结束，**当** 生成结果摘要时，**则** 摘要为 `failed`。
7. **假设** 一次调用被用户拒绝或 hook 拦下，**当** 生成结果摘要时，**则** 它照常计入总数并参与列出。
8. **假设** 生成该次调用的折叠行，**当** 渲染工具块时，**则** 参数位置只显示模型自己写的 5-10 字描述，不出现脚本片段。
9. **假设** 脚本调用过某个池内工具，**当** 该次 `REPL` 结束时，**则** 该次调用的工具名必须结构化保留供宿主读取，不进 `tools[]`、不进交给模型的结果文本。
10. **假设** 同一次脚本里同一个工具被调用了多次，**当** 记录调用名时，**则** 每一次都必须保留，不得去重。
11. **假设** 一次脚本被 dispatch 到后台，**当** 结果稍后送达时，**则** 它的调用名记录必须随事件一并保留，不得因为不在同一轮而丢失。

### 用户故事：描述与提示词讲清这个上下文怎么用（优先级：P1）

作为模型，我需要 `REPL` 的描述和系统提示里那段引导告诉我这个上下文怎么用（一次做多少、输出算什么、`console` 与 `self.log` 谁进上下文、`(dispatched #N)` 是什么意思），否则我只能靠试错。

**为什么是这个优先级**：Claude Code 的实测表明模型行为的真正来源是这段文字——工具 schema 只说得出参数，说不出「把全部操作合并进一次调用」，也说不出「每次调用是一次完整模型往返」。而且这类文案写错比没有更坏：模型会照着错的那条去做。

**独立测试**：渲染 `REPL` 的描述与提示词块，逐条断言下面每一块都在场；再断言这些文案与运行时实际行为不矛盾（每条都能在 spec 里找到对应的验收场景）。

**验收场景**：

1. **假设** 组装 `REPL` 的描述，**当** 渲染时，**则** 必须包含「把全部操作合并进一次 REPL 调用」这条要求，并说明理由（每次调用是一次完整的模型往返，脚本内部的往返相对免费）。
2. **假设** 组装描述，**当** 渲染时，**则** 必须说明「输出 = 最后一个表达式的值 + 一路 `self.log(...)` 的内容」，并说明返回对象里的 Promise 会被自动 await、而内联使用（`const p = f(); use(p)`）必须自己 `await`。
3. **假设** 组装描述，**当** 渲染时，**则** 必须说明两条通道的分工：`console.*` 进内存 ring（要读用 `console.tail(n)`），`self.log` 才进结果；`preview(out)` 用来把长输出挡在上下文外（默认 200 字符）。
4. **假设** 组装描述，**当** 渲染时，**则** 必须说明截断与转义：每个部分约 30000 字符、头尾保留、中间有标记；整个结果的文本总计不超过 **100000** 字符；`&` / `<` / `>` 只显示成实体，不改文件与值。
5. **假设** 组装描述，**当** 渲染时，**则** 必须说明异步语义：窗口内回结果（**窗口是固定的 30000 ms**，与 `timeout` 无关）、超出回 `(dispatched #N)`、**回执意味着它已经在跑或已排队所以再发就会跑两遍**、`Poll` 用来等、长命令（10 分钟）会转后台且上限 2 小时。
6. **假设** 组装描述，**当** 渲染时，**则** 必须说明持久上下文的边界：变量与函数跨调用保留，但**不跨重启 / resume / fork / wake**，且在那之后的第一条结果会说明这一点。
7. **假设** 组装描述，**当** 渲染时，**则** 必须给出 shell 的两种写法：heredoc 喂 stdin、PowerShell 的引号规则（单引号双写 + here-string）。
8. **假设** 组装描述，**当** 渲染时，**则** 必须把 `$` 的三条语义逐字教到：**①** 每个字符串插值整体单引号化、作为一个参数，所以 `${x}` 要**裸写**——自己再包一层引号，`$` 加的那层就保护不住了，值里的 shell 语法会执行；**②** 模板正文照原样进 shell，**除了 `\`` 与 `\${` 会掉反斜杠**，想在 shell 里看到字面反引号或 `${` 就把它们当 `${}` 值传进去；**③** 另有 `$(cmd, ms)` 这条出口——命令以**纯字符串**给出、可带超时毫秒，绕开插值。这三条在 Claude Code 2.1.326 里写在随请求下发的 helper `d.ts` 正文里（`## Declarations` 段首），我们写在工具描述里，**都是静态行为描述，不含任何随会话变化的量**。
9. **假设** 会话处于询问权限模式，**当** 组装描述，**则** 必须说明这一档会等脚本返回、且上限 600000 ms 从启动起算并包含等人时间。
10. **假设** 描述里有一段 globals 声明（名字 + 签名），**当** 渲染时，**则** 它必须与真实注入的 globals 逐名一致——不得写入没有注入的东西，也不得漏掉已注入的（包括 `tools.list()` 与 `running()`）。
11. **假设** 会话在子代理里，**当** 渲染描述时，**则** 必须补一句「`tools[]` 可能列出这个 agent 并没有被授予的工具，先查 `tools.list()`」，因为子代理的工具集与主线程不同。
12. **假设** 渲染描述的「Sandbox API」段与密封提示（`import` / `require` 被拦时的错误文本），**当** 两者举例时，**则** 示例只能点名默认配置下在池里的工具（折叠态的 `Grep` / `Glob`）或 `$` 命令模板，照 Claude Code 的形态直接点名、不写「以公告为准」类限定，**不得点名某个默认配置下脚本不可达的工具**（`enableReplCoreTools` 默认关时 `Read` 就是这种：描述里写 `await tools.Read({...})` 等于教模型一个会报 `ReferenceError` / `TypeError` 的调用）。

## 非功能需求

- **零新增依赖**：隔离只用 Node 内置的 `node:vm`（上下文 + 加固 + 源码注入），不引入 worker 线程、子进程、解释器、AST 库或沙箱运行时；步数计数器的插入与还原用字符串/正则级处理即可，不需要额外构建产物。
- **准入判定的单一来源**：池的成员必须由一个判定函数产出，声明收敛、公告、搜索、沙箱可达集合四处全部从这一个函数导出。`enableReplCoreTools` 与搜索折叠态（`shouldRegisterSearchTools` 为 false）各自只能作为该判定的一条输入，不得在别处另写一份名单；折叠态排在核心池之后、MCP 之前，`toolTier` 对折叠态的 `Grep` / `Glob` 返回 `named`。
- **池的单一来源**：池的内容与被撤下的扁平声明必须来自同一个函数。
- **单一执行漏斗**：嵌套调用必须走现有的唯一执行入口（含权限/审批检查），不得另开一条。内置是 `ToolManager.execute`，MCP 是 `McpManager.executeMcpTool`。
- **hook 与权限同漏斗**：PreToolUse / PostToolUse 挂在嵌套调用本来就经过的执行入口上，扁平与池内两条路径共用同一段 hook 代码。
- **上下文的单一归属**：一个 `(会话, agent)` 只允许一个上下文；释放点只有三个——`/clear`、切换到另一个会话、子代理结束；外加一条**异常**释放：上下文被脚本改坏（受管全局不可配置 / `globalThis` 不可用）时必须丢弃重建并显式告知。不得有第五个隐式释放点（压缩、空闲、轮次结束、超时预算耗尽都不释放——预算是靠代码里的检查停下来的，不靠杀上下文）。
- **模型可见文本稳定且与池无关**：`REPL` 在 `tools[]` 里的描述必须对任意工具池逐字节相同；但它**每次请求都会重新渲染**（与旧形态不同，旧形态是常量）。
- **播报无进程内状态**：公告的播报状态以历史里的标记行为唯一真源。
- **不阻塞会话**：脚本的同步段会真实占用宿主事件循环，同步段的长度由 `timeout`（默认 30000、上限 600000）约束，而**同步等待窗口是固定 30000 ms 的常量**——它不读 `timeout`，模型给 600000 也只能同步等 30000 ms，之后调用回 `(dispatched #N)`；进入等待（嵌套调用在飞、永不 settle 的 await）后不得继续占用，等待期间预算不增长——**唯一例外是询问权限模式**：那一档按 600000 ms 从启动起算且含等人时间（见「执行预算与终止」场景 6），因为不设这条，人不回来的审批弹窗会把上下文无限期挂着。
- **可观测**：沙箱异常记日志；步数预算耗尽、同步 wall clock 超时、用户中断、上下文中毒四种终止原因必须各自可区分（结果文案与日志都要能说出是哪一种），一律以失败工具结果回到模型（不抛异常、不静默）。进度分两侧，各有自己的通道：**模型侧**——后台脚本跑完之后的结果必须送达模型，通道是 `drainReplEvents` / `waitForReplEvents` 攒出的 `repl-eval` 事件（带 `evalId`、`toolsUsed`、结果与用时）与 `Poll`（`pollTool.ts`）读出的 `repl-eval` / `repl-status`，脚本转后台之后仍然持续可用；**UI 侧**——`searchTools` / `describeTool` 与每次嵌套调用都刷新折叠行，让行显示「脚本正在搜工具」而不是一段静默（摘要行形态见「在沙箱内搜索工具形状」场景 13：出现、不计入 `N tool calls`、失败也出现）；但 `(dispatched #N)` 回执送出之后那一行已 `end`，此后的进度**不再回写 stage**——`end` 是终态，后台进度只走上面那条模型通道。
- **测试**：SDK 层覆盖准入判定（含四条覆盖口与 MCP 无条件）、池构建与声明收敛、公告渲染与播报状态机、搜索（排序分级、默认 8/上界 25、`+term` AND 语义、`mcp__` 前缀命中、精确名短路、`searchHint`、空查询抛错、`describeTool` 的截断与 JSON Schema 对象形态）、上下文生命周期（复用、中断保留、**定时器随脚本清除**、三个释放点、上下文中毒重建、resume 提示、**顶层声明覆盖 helper / 工具 / 内建的静态拒绝（脚本自己定义过的名字放行）**）、源码注入（循环头与调用点各插一次、注入后行号仍映射回原文、还原函数能剥干净）、运行时（await 贯通、内置 `{error}` 与 MCP throw 的差异、未知名即 `ReferenceError`、日志上限、图片占位符与张数上限、**`timeout` 只计同步段**、**询问模式 600000 含等人**、**每调用看门狗**、abort 后前 20 次照答且第 21 次起永挂、三种卡死形态、步数预算与同步 wall clock 各自终止、调用次数上限越界后不再回答、并发调用共享等待窗口）、沙箱加固（无 `require`/`process`、`eval` 抛错、`import()` 三形态静态扫描、内建构造器冻结、跨界值原型为 `null` 且超 4096 项带 `truncatedFrom`、受管全局不可配置即中毒）、异步车道（窗口内返回、**窗口固定 30000 ms 不随 `timeout` 变化**、dispatch 回执、**全 dispatch 形态**、`<repl-output>` 与 `<event kind>` 外壳的 markup 契约与转义、事件送达、`Poll`、并发上限**拒绝**而非排队、墙钟上限、**无宿主去重 + `evalId`**）、沙箱 globals（``$`cmd` ``的`.nothrow()`/`.cwd()`/`.env()`/`.lines()`/`.json()` 与插值转义、**任何非零退出都抛、`.nothrow()` 里 `note` = 工具的 `returnCodeInterpretation`**、**`sleep` 超时只终止不转后台**、`output`/`file`/`truncated`/`note`/`cwdNote`（含 `note` 不抑制 throw、`cwdNote` 只在真的 `cd` 时出现且不吃掉同形的命令输出、**一条真起进程跑 `cd` 的用例**）、`preview` 默认 200、`self.log`与`console` ring 的分工、`running()`、`tools.list()`）、返回类型（每个内置工具的 `outputSchema` 都能被 `renderType` 渲染成合法 TypeScript、未声明为 `unknown`、签名里不再出现 `string`、脚本 await 到的是 `data`）、开关（池内/扁平两种形态的往返、**池内 shell 工具保留 `run_in_background`（公告签名里有这个参数、脚本内真调拿到任务 ID）**、**平铺调用池内工具被拒且工具本体一次都没跑（副作用判据）、脚本内调用不受这条校验影响**、**折叠态搜索工具进池且公告只列名字、平铺被拒、Bash 描述不翻、REPL 关闭时两个入口都没有**）、工具层（参数校验、结果摘要、内层调用名记录、**`<log>` 每流一个**、**结果总文本 100000 上限**、\*\*console ring 提示\*\*）与 hook。

## 边界情况

- **上下文什么时候会丢？** 只有一种情形：脚本把受管全局改成了不可配置、或把 `globalThis` 改坏到新调用无法启动，宿主只能丢弃重建。这时结果里必须显式说明「这是一个新上下文，之前的变量与定时器不在」——静默会让模型继续引用不存在的变量。中断、预算耗尽、压缩、轮次结束都**不**丢上下文。
- **中断之后上下文里的定时器怎么办？** 定时器本来就不跨脚本：设立它的脚本一结束就被清除，中断与正常结束一样。变量保留。
- **上下文压缩之后要不要提示？** 不提示。上下文本身没丢，提示只会让模型以为要重读。
- **resume 之后为什么会有「上下文是新的」提示？** 历史里有 `REPL` 调用就说明模型记得自己建过变量，而新进程里它们不存在。提示的条件是「历史里有过调用 且 当前上下文确实是新的」。
- **子代理与主线程能互相看到变量吗？** 不能。各自一个上下文，按 agent 分槽。
- **同一个上下文并发两个脚本，变量冲突怎么办？** 按 JavaScript 语义：后执行的赋值覆盖先执行的。宿主不额外串行化也不做冲突检测——串行化会把并发编排的收益抹掉。
- **脚本定义过的全局名字要不要列给模型？** **不要**。Claude Code 的 `scriptGlobalNames()` 只喂压缩摘要（`replBindingsKept`），不进系统提示，本方同样不要求把这份清单拼进提示：它每轮都变，且模型真要知道有什么，自己 `return Object.keys(globalThis)` 或重跑一句就够了。
- **顶层重名这一面还差哪一格？** 只拦**声明**（`const` / `let` / `function` / `class`）。Claude Code 的 `za()` 还拦对**未声明名字的赋值**、`x++`、非 `var` 的 `for-of`，并带作用域豁免（自己在外层声明过的名字不算写全局，`globalThis.x =` 只在 `mod` 档放行）——offset `344594863`。**这一格有意不做**：它本质是防手滑的保险（脚本忘了 `const` 就把值写进全局），而真正会咬人的「顶层声明覆盖 helper / 工具 / 内建」已经在提交前被拦掉了；剩下的收益要一整层分析器来换（全树遍历 + 每层作用域名字集合 + MemberExpression 识别 + `mod` 例外，约 120~180 行），且与现有的 `const → var` 重写**相冲**——那层重写正是为了让顶层声明在同一份 wrapper 里可重声明，再叠一套「写全局」判定，两边对「什么算写全局」会给出不同答案。
- **后台脚本在等待一个审批弹窗时，算不算运行中？** 算。它不消耗脚本预算，但仍在并发计数里，且 `Poll` 的状态行必须把它列为「在跑」。
- **`self.log` 和 `console.log` 有什么区别？** 不同：`self.log` 的内容进结果，`console.*` 进一个**有上限的内存 ring**、不随结果返回，脚本要读只能 `console.tail(n)` / `console.buffer()` / `console.dropped()`。这是对齐 Claude Code 的分工——`console` 留给脚本自己调试，`self.log` 才是给模型看的。
- **`preview(out)` 的默认长度？** **200 字符**（对齐值），传第二个参数可指定。它是把值 `String()` 之后从开头截取，被截时带 `…[+N chars]` 标记，返回字符串、不改变 `out` 本身。
- **``$`cmd` `` 的返回形态？** 一个 thenable 对象：`await` 它得到结果对象，字段为 `command`、`stdout`（`Bash` 合并后的输出）、`stderr`（工具自身的失败说明）、`exitCode`（数字或 `null`）、`output`（给模型/人看的展示文本：stdout + 按需的 `[stderr]` / `[note]` / `[exit N]`；**三路全空且退出码 0 时是 `[exit 0]`**——对齐 Claude Code：有输出且 exit 0 不追加 exit 行，只有「什么都没说」才留一个标记，好让脚本把「命令什么都没打印」和「命令根本没跑」区分开；非零退出时工具写进 `stdout` 末尾的那行 `Exit code <n>` 会被剥掉，`[exit N]` 由 `$` 自己渲染，不出现两遍）、`truncated`（输出是否超限）、`file`（超限时完整输出的落盘路径，可用 `Read` 取回）、`note`（「退出码非零但不是失败」的注解）、`cwdNote`（命令真的移动了 shell 时 `Bash` 写的那行提示原文，已从 `stdout` 剥出；没移动就不出现）、`running`（转后台时的任务名与输出文件），方法为 `text()` / `lines()` / `json()`。链式方法 `.nothrow()` / `.timeout(ms)` / `.cwd(dir)` / `.env({...})` / `.lines()` / `.json()` 都可用。**非零退出时 throw**（对齐 Claude Code：`A non-zero exit throws a ShellError`），**没有家族例外**：「无匹配 / 有差异」的判定由 shell 工具做（`success: true` + `data.returnCodeInterpretation`），`$` 只把那份解释以 `[note]` 跟在 `ShellError` 文案里——脚本因此一眼能看出这个退出码是什么意思，但要拿到结果对象仍须 `.nothrow()`（那时 `note` 就是那份 `returnCodeInterpretation`）。这与内置工具的 `{ error }` 语义不同，是 `$` 这一个 helper 的机制：它是模板函数、没有「返回一个错误对象」的位置。
- **`cwd` 提示为什么不留在 `stdout` 也不折叠进 `output`？** 因为它既不是命令打印的东西，也不是这次命令的结果，而是「下一条命令会在哪跑」。留在 `stdout` 会让脚本把散文当数据；折叠进 `output` 会让「空命令也 `cd` 了」这一格不再等于 `[exit 0]`（`output` 的定义是「这次命令说了什么」）。所以按 Claude Code 的做法（它剥成独立的 `cwdResetWarning`）单独给一个字段：`cwdNote` 是**原文**，两个形态自解释（`changed` 是移动生效、`reset` 是被拉回原目录）。剥离的判据是这次调用真的调过 `onCwdChange`（`Bash` / `PowerShell` 只在真的移动时调它，且同一分支里拼那行提示），而不是按文本猜——命令自己 `echo` 一行同形文字时 `stdout` 一个字节都不许少。`tools.Bash` 那条路不剥：它交回的是工具自己的 `data`，那行本来就独立躺在 `stderr` 里，脚本直接读字段即可（`$` 额外把它单列成 `cwdNote`，好让 `[exit 0]` 那一格不受影响）。
- **`$` 的 `.cwd()` / `.env()` 为什么不是 `cd` / `export` 前缀？** 因为前缀会把模型写的命令改掉：`sleep` 开头的那条「不转后台」判断看的是第一个词（`export` 会顶掉它），权限规则匹配的也是命令文本，而命令里的 `cd` 会经 `onCwdChange` 把整个会话的工作目录带跑。所以这两个方法在宿主侧**派生一份只作用于本次调用**的工具上下文（cwd 换成目标目录、env 叠加 `sessionEnv`），命令一个字都不改。代价：`.cwd()` 里的命令自己再 `cd` 时不会更新会话目录（这是想要的），`.env()` 的键必须是合法环境变量名（`[A-Za-z_][A-Za-z0-9_]*`），否则命令不执行。
- **输出太大怎么办？** 截断发生在 `Bash` 工具那一层（30000 字符）：它把完整输出写到 `<临时目录>/wave-tool-results/bash_*.txt`，交给模型的是 `<persisted-output>` 外壳 + 2048 字符预览。`$` 会把这一层**拆开**交给脚本——`stdout` 是预览、`truncated: true`、`file` 是那个真实路径——这样脚本能直接 `Read` / `grep` 到缺的部分，而不是把一层外壳文本当成命令的真实输出。没超限时 `truncated: false`、不带 `file`。`stdout` 是**命令真正打印的东西**：工具层在命令无输出时写的那句兜底话术（`Command executed with exit code: 0`）在这里被剥掉，否则脚本读 `stdout` 拿到的是散文而不是数据。判定要两条同时成立——这句话占满整条输出，且工具层自己的 `shortResult` 为空（它由原始 stdout/stderr 推出，正好只在「什么都没打印」时为空）——否则命令真打印了这句话也会被吃掉（真机踩到过：`echo 'Command executed with exit code: 0'` 回来是空 `stdout`）。**这两条之外还有一道前置**：`cd` 提示行先按场景 12 剥出去，否则「空命令顺带 `cd` 了」的那一格整条不再是这句话，判据失效（真机第二轮撞到的正是这个残余形态）。注意第二道闸门：结果交给模型时每部分仍截到 30000 字符，所以「把整个大输出 return 回去」依然会被截，正确用法是把 `file` 路径或筛过的片段交回去。
- **``$`cmd` `` 的超时呢？** 命令自己没有超时时最多等 **600000 ms**；给了更长的按它等（上限 **7200000 ms**）。超过后**转入后台**而不是抛超时：await 照常 resolve，`exitCode` 为 `null`，`running` 给出后台任务名与它输出到的文件——长构建因此不必占用上下文干等。不写这条，实现会退化成 `Bash` 的同步上限。**`sleep` 开头的命令是例外**：它超时就被终止（`Bash` 自己的不允许转后台名单），因为转后台等于模型永远拿不到结果。
- **``$`cmd` `` 里插值怎么办？** **默认对每个插值单独加单引号，作为一个参数**（数组则逐项一个参数），所以脚本里写 `` $`grep ${pat} ${file}` `` 就是安全的；要原样拼接（例如拼一个 `--flag=a b` 的片段）必须显式写 <code v-pre>${{ raw: value }}</code>。这与 Claude Code 一致（它也跑 `posixQuote`/`psQuote`），**不是**「不做转义」——`Bash` 工具那条「模型自己处理引号」的要求不适用于 `$`。另外三条容易踩的写法，描述里也必须教到（对齐 Claude Code 2.1.326 的 helper `d.ts`）：
  - **`${x}` 要裸写**：你在值外面再加的引号不算数，`$` 加的那层才保护参数边界；包一层自己的引号反而让值里的 shell 语法照常执行。
  - **`\`` 与 `\${` 掉反斜杠**：模板正文原样进 shell，只有这两处的反斜杠会被吃掉；要 shell 看到字面反引号或 `${`，把它们作为 `${}` 值传进去。
  - **`$(cmd, ms)` 是第二条出口**：命令以纯字符串给出（`typeof` 第一个参数是字符串时走这条），第二个参数是可选的超时毫秒，完全不经过插值。
- **脚本里调用了池外的工具名怎么办？** 该名字不在本次调用的 globals 上，就由引擎抛 `ReferenceError` / `TypeError`。我们**不**加「宿主侧拒 + 指向 `searchTools`」这一层（Claude Code 也没有）：唯一那条专用文案是「名字已声明、但本次调用没给」的 `<name> is not available in this REPL call`。
- **模型平铺调用了池内工具怎么办？** 那条调用必须**在运行前被拒**：每个 `tool_use` 先查「本轮真发给 API 的 `tools[]`」，查不到就回一条 `is_error` 的工具结果，绝不执行——注册表只用来挑文案（在池里→附可照抄的 `await tools.Bash({...})`；不在池里→「用你已有的继续」）。不这么做的话，公告说「只能在脚本里用」而平铺调用悄悄成功，池化就只是一条建议而不是规则；而且它天然覆盖所有同类场景（池化的 MCP 工具、被权限规则过滤掉的名字、根本不存在的名字），不用给每种情形各写一条。判定排在权限与 PreToolUse **之前**（对齐 Claude Code：它的查表拒绝排在 `canUseTool` 与 hook 之前），所以 `bypassPermissions` 也绕不过。**脚本内的 `tools.X(...)` 与 `$` 不在这条判定之下**：模型声明的是 `REPL`，脚本可达的是整个池，那是「已声明之后的二次入口」——两层用同一份名单判会把沙箱自己掐死。
- **为什么核心工具默认不收进沙箱？** 见「开关把核心文件与 shell 工具也收进 REPL」：默认关，因为它把最高频的调用从「一次工具调用」变成「一层脚本包裹」，值不值得取决于工作形态。**开关打开后它们的签名是要内联进公告的**，所以「每次多一次搜索」不再是这个取舍的成本项——真正的成本是那层包裹，以及压缩把签名吃掉之后需要重新播报（不是重新搜索）。
- **延迟集合与 Claude Code 是同一份吗？** 内置工具的 `defer` 申报与 Claude Code 2.1.285 的 `shouldDefer` 逐条对齐（含 plan mode 那一对与四个 task 工具）。**2.1.326 侧未做跨版本逐条比对，此条标为待复核**：2.1.326 里能看到的只是两组集合常量（6 个 + 8 个），没有逐名对照表。
- **服务端下发的非延迟名单里出现一个不存在的工具名会怎样？** 忽略该条，不得让整个名单失效。
- **MCP 工具能不能逃出池？** 能，但只有一条路：服务器用 `alwaysLoad` 声明。
- **MCP 服务器在公告之后、执行之前发生变化怎么办？** 执行时按当次池重新计算可达集合，两侧同源。
- **`REPL` 被禁用/被排除，会不会连带丢掉工具？** 不会。撤下的只是扁平「声明」这一形态；`REPL` 不可声明时，扁平声明必须在同一次组装里恢复。
- **池为空但 `REPL` 已注册时会播报吗？** 已经读到过公告的会话在池变空时必须收到一次「当前没有可用的可编目工具」；从未有过公告的会话整轮不发声。文案不得提及 `REPL` 这个工具名。
- **公告会不会太长？** 分档定长度：第 1 档每个工具约 120 字符描述，第 2 档的名字列表随延迟内置的数量线性增长（几十个工具约几百字符），两者都刻意不设上限也不截断——漏列一个工具会被读成「这个能力不存在」。第 3 档的服务器名有 40 个的硬上限，因为接入的服务器数量不由我们控制，而「有这台服务器 + 用 `searchTools` 找」已经足够构成能力地图。
- **`code` 缺失或为空白怎么办？** 直接返回参数错误，不启动或复用上下文。
- **脚本抛错怎么办？** 返回失败结果；抛错之前已经产生的日志仍然保留。
- **脚本不返回值、也不打日志怎么办？** **不解释**：`<result>` 是空的就写作 `<result/>`（对齐 Claude Code，它把 `undefined` 渲染成空文本再自闭合）。只有在逐字形态（无 tools / refused / log，整条结果确实什么都没有）时，结果文本才是一句说明——那是这一形态没有元素可以「空着」的兜底，不是对「没有返回值」的解释。**任何情况下都不得在已有 `<log>` / stderr 时再断言「没有日志」**：实现曾经只看返回值不看日志，于是打了日志的脚本也被贴上这句话。
- **沙箱值跨界的形状限制？** 参数必须是普通对象（拒绝带函数的对象 / 类实例）；返回值深拷贝、跳过 `__proto__` 与函数字段。
- **子代理里会注册 `REPL` 吗？** 与其它内置工具同一条注册路径；`REPL` 若被排除，同样回退到扁平声明。
- **改了公告的文案或排版会怎样？** 播报状态靠「上一条公告的正文」比对：历史里那条消息的正文就是模型读过的东西，逐字节比即可，所以改文案会让存量会话重播一次完整公告。这是有意接受的代价。**哈希不进模型可见文本**——Claude Code 也算同一份工具目录的 sha256 前 16 位，但只拼进 prompt cache key（`TD<hash>:`），一个字节都不进对话；我们原先把它写进公告的标记行（`<!-- exec-catalog {"k":"full","h":"…"} -->`），模型每轮都读得到一个 12 位十六进制串，而它对模型毫无用处。标记行现在只带 `k`（`full` / `removed`），比较用的是回读出来的正文。
- **MCP 服务器名里含 `__` 会怎样？** 只影响工具名的可读性与「非标识符名要用括号形式调用」那条渲染规则。
- **搜索返回的内容会不会很大？** 有明确预算：`searchTools` 每条 `about` 截 160、条数默认 8/上界 25；`describeTool` 描述 4000、单条 input 6000、总 input 15000，被截处带「取完整 schema」的注释。所以「搜索」本身就是有界的，不靠外层返回值上限兜。
- **服务器声明了 `outputSchema` 但返回里没有 `structuredContent` 怎么办？** 脚本拿到文本——**文本是 JSON 就先解析**（对齐 Claude Code：它把文本块 join 后 `JSON.parse`，成功才是对象），不是 JSON 才原样给出；两者都没有则 `null`。判断只看实际返回了什么，不看声明。
- **返回类型的 TypeScript 声明从哪来？** 内置工具自己声明 `ToolPlugin.outputSchema`（JSON Schema，写在与各自的 `XxxResultData` 同一个文件里），MCP 工具用服务端下发的 outputSchema，两者都没有时写 `unknown`。**这一条我们有意偏离 Claude Code**：CC 在 2.1.325 内置与 MCP 都写 `Promise<unknown>`，2.1.331 起只给 MCP 渲真实类型、内置仍是 `unknown`——它的理由是绝大多数 server 不声明输出 schema（issue #108630：模型只能按描述散文猜字段，猜错就白跑一轮）。我们的内置工具返回值形状由自己定，没有理由让模型猜，所以脚本可达的那批内置工具都补 schema。
- **运行时会不会按输出 schema 校验返回值？** **不会**（这一点与 CC 不同：它对 MCP 的 `structuredContent` 做一次 `safeParse`，不符时打警告）。我们的输出 schema 只用于渲染类型文本与 `describeTool().output`，不参与执行、不因 `data` 与 schema 不符而失败或改写返回值——`data` 由我们自己产出、形状由测试钉住，再加一层校验只会让「工具实际返回了什么」与「模型看到什么」出现第二份真相。
- **服务器只返回图片怎么办？** 脚本侧的值是 `null`，图片照常作为 `REPL` 结果的附件交给模型。
- **结果摘要里被权限规则拒绝的工具计入调用次数吗？** 构池时就被排除的工具不计入（从未到达宿主）；执行期被拒的（用户点拒绝、hook 拦下）计入。
- **内层调用在对话流里怎么显示？** 在结果摘要里以「次数 + 最近 2 次调用」出现，不物化成独立工具行。
- **后台脚本的结果送达顺序？** 按脚本编号，先完成的先送达。同一编号只送达一次。
- **`timeout` 给到 600000，为什么调用还是 30000 ms 就回了？** 因为同步等待窗口是固定 30000 ms（对齐 Claude Code 的 30000），`timeout` 只放宽容忍的同步段 wall clock。两个数混成一个时，模型写 `timeout: 600000` 会以为一次调用能同步占住十分钟，而真正的长活本来就该走异步车道。
- **`console.*` 的提示什么时候出现？** ring 里有内容就出现，哪怕脚本同时也用了 `self.log`。Claude Code 更严一档（只在捕获的 stdout 为空、ring 非空时才补）；我们放宽，因为「少量输出 + 一串 ring」才是最容易被读错的组合。这段文案走结果的注释通道，不冒充脚本自己的日志。
- **折叠态下的 `Grep` / `Glob` 为什么只列名字、不带签名？** 折叠的初衷是让顶层搜索走 Bash 影子；公告里带签名等于在给它们打广告，模型会在折叠态倾向走 REPL 搜索——与「影子是付费买的那个」相悖。只列名字是「能力在、但不鼓励」的折中，Claude Code 2.1.331 也是这么分的（折叠态 `MV()` 把两者挪进 names-only 档）；真需要结构化输出时 `describeTool` 一次就到。
