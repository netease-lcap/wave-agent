# 功能规格说明：Focus 视图

`参考实现`：Claude 桌面端 6.28899.6 的 focus view（`ion-dist.asar` 里的 chunk `cac57de41`）与 Claude Code VSCode 扩展 2.1.246 的 `claudeCode.focusView`。两者做法不同：插件端把消息重新分组后**全量渲染**（无分页、无虚拟列表），桌面端把折叠做在**布局层**、渲染仍走虚拟列表。wave 采用后者。本规格只描述产品行为。

## 用户场景与测试

### 用户故事：一键聚焦，只看问答（优先级：P1）

作为在长会话里干活的用户，我希望把中间几十上百条工具调用收起来，只看到「我问了什么、它最后答了什么」；需要细节时点开某一行看一眼，而不是一路滚过刷屏的工具输出。

**为什么是这个优先级**：长会话里工具块是绝大多数行数，滚动找上一句答复的成本随轮数线性上升；聚焦视图是「看会话」这一主路径的直接优化，且不改变任何既有能力（工具块一点就展开）。

**独立测试**：三端（desktop / VS Code / JetBrains）打开含 ≥2 轮、每轮 ≥3 次工具调用的会话，点聊天顶栏的「聚焦」按钮：工具活动收成每轮一行摘要、轮尾答复仍在；点摘要展开再收起；刷新页面与重开会话后开关仍保持；关闭聚焦后完整恢复原样。

**验收场景**：

1. **假设**会话里已有至少一轮对话，**当**用户点击聊天顶栏的「聚焦」按钮（与「更多 / 面板」同一行；不进输入框工具行——那一行在手机上是满的），**则**聊天流切到聚焦视图：每一轮的工具活动收成**一行摘要**，用户消息与轮尾答复保持原样显示；按钮进入选中态（`aria-pressed="true"`，按钮底色变、悬停提示从「聚焦视图」变「退出聚焦视图」，图标本身不换形）；再点一次恢复原视图。开关是**显示偏好**，按端持久化（重开页面、重开会话、切换会话后保持），不写入会话内容、不进入发给模型的上下文。

2. **假设**处于聚焦视图且某轮已结束，**当**用户查看该轮，**则**摘要行显示该轮的活动量（如「3 次工具调用」；轮内有失败的工具调用时行尾补「2 个失败」；该轮只有思考没有工具时「思考过程」；既没工具也没思考的兜底「过程」），行首有圆点，整行是按钮（可 Tab 聚焦、Enter/Space 等价点击）。**折叠范围是该轮除「轮尾答复」以外的全部助手活动**——轮尾答复指本轮最后一条助手消息、且该消息不含工具块；若本轮最后一条助手消息仍带工具块（这一轮还在跑），则整轮进摘要、卡外不显示答复文本。

3. **假设**某轮正在执行（流式中），**当**用户查看该轮摘要，**则**摘要行实时更新为进行态：正在执行的工具显示「正在执行 Bash…」（工具名取自当前块），模型在思考时显示「正在思考…」，行尾补「已 N 次」；行首圆点做脉冲动效（系统开了「减少动效」则只保留颜色不闪）。该轮结束时摘要行自动切回场景 2 的完成态文案，无需用户操作。

4. **假设**用户点击一行摘要，**当**摘要展开，**则**卡内按原始顺序显示该轮被折叠的活动（每次工具调用一行，可继续点开看输出；思考与过程叙述按原文显示），再次点击收起；同一轮可反复展开收起。**展开状态只存于当前页面生命周期**：刷新、切会话、切走聚焦视图后回到「全部收起」。

5. **假设**用户正看着会话尾部、新的一轮开始，**当**第一条消息到达，**则**新轮按进行态出现（场景 3），已结束的轮不受影响、不因新消息重新展开；关闭聚焦视图时，之前被折叠的活动全部回到展开显示状态（折叠只是显示层，不改变任何消息的内容或顺序）。

6. **假设**会话还有更早的历史未加载，**当**用户在聚焦视图下滚到顶部触发取上一页，**则**取页与落位行为与普通视图一致；跨页边界的一轮按**已加载到的部分**计算摘要，取回更早的消息后该轮摘要就地更新。若取回的消息让这一轮的起点前移（原先的轮首只是已加载部分），该轮的展开态回到收起——卡头的身份来自这一轮的用户消息，起点变化时按新的一轮重新认领，用户点开即可。

7. **假设**某一轮里有上百次工具调用，**当**用户展开该轮，**则**展开不应把上百条全部挂到 DOM：滚动到哪渲染到哪（虚拟列表对**摘要行**与**展开后的活动行**同样生效），首次展开后的可见区域内容必须立即可见、不出现长时间空白。

8. **假设**用户在聚焦视图下使用会话大纲或转录搜索，**当**目标落在被折叠的活动里，**则**该轮自动展开并把目标滚到视口内；搜索命中计数仍按真实消息数统计，不因折叠而减少。

9. **假设**用户关闭聚焦视图，**当**列表重绘，**则**所有被折叠过的活动恢复为普通视图的显示形态，滚动位置保持不跳到顶部或底部。

## 边界情况

- **空轮与单条消息**：一轮里只有一条纯文本助手消息（没有任何工具调用）时**不生成摘要行**——没有可折叠的东西，摘要行反而增加噪声。
- **只有思考**：一轮里只有 reasoning 块、没有工具调用时按场景 2 的「思考过程」显示（运行中是「正在思考…」），属于可折叠（聚焦视图的本意就是把这些中间过程收起来）；空白思考块不算。
- **失败与中断**：轮内有失败的工具调用时卡头带失败计数；**以失败提示收尾的一轮，那条提示留在卡外**——它是本轮最后一条助手消息且不含工具块，按「轮尾答复」规则不折叠，否则报错会被收进摘要里看不见。用户中断（Stop）的那一轮按已结束处理。
- **空会话不显示按钮**：没有可见消息（欢迎页）时顶栏不渲染这个按钮——没有可折叠的轮，按钮只会占位；会话收到第一条消息后按钮出现。
- **压缩块与通知行**：上下文压缩块（`compact`）与通知行（`notice`）不折叠——它们是「这一轮为什么变成现在这样」的说明，且体量小。
- **权限确认与提问**：这两者是页面级弹窗（不挂在某一轮的行上），所以聚焦视图**不做**「待确认自动展开」——没有可展开的轮内内容，也不需要：弹窗本身盖在流上。
- **超长会话**：聚焦视图不改变分页页大小，也不干预驱逐策略；开关切换不触发重新取数。
- **跨端一致**：三端共用同一 UI，开关状态按端各自持久化（不要求跨端同步，与主题等显示偏好同档）。

## 非目标（明确排除）

- **不改变模型行为**：本规格只做显示层折叠；「让模型少在工具之间叙事」属于提示词侧的独立改动（参考 CC 的 `# Focus mode` 系统提示词），不并入本规格。
- **不做自动折叠策略**：不按轮数/时长/条数自动进入聚焦，只由用户显式切换。
- **不做服务端/宿主侧过滤**：消息仍全量到达 webview，折叠纯在渲染层发生；分页与驱逐策略不变。
- **不支持按工具类型选择性折叠**（如只折叠 Bash）：整轮折叠是唯一粒度。
