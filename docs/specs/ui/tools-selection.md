# 功能规格说明：工具选择

**创建日期**：2026-02-25

## 用户场景与测试 _（必填）_

### 用户故事：选择特定工具（优先级：P1）

作为用户，我希望将 agent 可用的工具限制为特定集合（例如仅"Read"和"Edit"），以便控制 agent 在给定会话中可以执行的操作。

**为什么是这个优先级**：这是请求的核心功能。它允许用户出于安全或专注目的限制 agent 的能力。

**独立测试**：可以通过使用 `--tools "Read,Edit"` 启动 CLI 并验证 agent 仅尝试使用这些工具来进行测试。

**验收场景**：

1. **假设** CLI 使用 `--tools "Read,Edit"` 启动，**当** agent 被要求执行任务时，**则**它应该只能访问"Read"和"Edit"工具。
2. **假设** CLI 使用 `--tools "Bash"` 启动，**当** agent 被要求读取文件时，**则**它应该失败或报告工具不可用。

---

### 用户故事：禁用所有工具（优先级：P2）

作为用户，我希望通过向 `--tools` 参数提供空字符串来禁用所有工具，确保 agent 只能通过文本进行通信。

**为什么是这个优先级**：提供"安全模式"或"仅聊天"模式，这是受限环境中的常见需求。

**独立测试**：使用 `--tools ""` 运行 CLI 并验证没有工具被注册或对 agent 可用。

**验收场景**：

1. **假设** CLI 使用 `--tools ""` 启动，**当** agent 初始化时，**则**提供给底层 SDK 的工具列表应为空。

---

### 用户故事：使用默认工具（优先级：P3）

作为用户，我希望使用"default"关键字显式请求默认工具集，或者完全省略该标志。

**为什么是这个优先级**：确保向后兼容并提供显式方式来重置为标准行为。

**独立测试**：使用 `--tools "default"` 运行 CLI 并验证其行为与不使用该标志运行完全相同。

**验收场景**：

1. **假设** CLI 使用 `--tools "default"` 启动，**当** agent 初始化时，**则**它应该可以访问完整的标准工具套件（Bash、Edit、Read、Glob、Grep 等）。

---

### 用户故事：打印模式工具选择（优先级：P2）

作为用户，我希望将 `--tools` 标志与 `--print`（或 `-p`）选项一起使用，以便控制在打印模式下生成输出时可用的工具。

**为什么是这个优先级**：确保在所有使用 agent 的 CLI 模式中保持一致。

**独立测试**：运行 `wave --print --tools "Read" "some prompt"` 并验证 agent 仅使用"Read"工具。

**验收场景**：

1. **假设** CLI 使用 `--print --tools "Read"` 运行，**当** agent 处理提示时，**则**它应该只能访问"Read"工具。

---

### 用户故事：显式列出的工具保持扁平（优先级：P1）

作为使用 `--tools` 精确指定工具的用户（`mcp__server__tool` 这类 MCP 叶子，或 `Read` 这类内置工具名），我希望被显式列出的工具仍然作为独立工具声明，并且只有白名单内的工具能被调用，以便工具延迟加载（见 [`core/tool-deferred-loading.md`](../core/tool-deferred-loading.md)）不会削弱 `--tools` 的选择语义。

**为什么是这个优先级**：`--tools` 是能力白名单；若被显式列出的工具只存在于目录中（或目录里混入了白名单外的工具），用户精心限定的能力集合就会被静默改变。

**独立测试**：以 `--tools "mcp__server__tool"` 启动，检查该工具以独立工具形式出现且可被调用；以 `--tools "Read,Edit"`（内置工具含被标注 defer 的）启动，检查这些内置工具仍逐条声明；检查目录中不出现任何未被 `--tools` 允许的工具。

**验收场景**：

1. **假设** 用户以 `--tools "mcp__server__tool"` 启动，**当** 工具列表构建时，**则** 该 MCP 叶子必须作为独立工具逐条声明（不被工具延迟加载吸收），白名单语义与无延迟加载时完全一致
2. **假设** 用户以 `--tools "Read,Edit"` 启动且其中某内置工具默认参与延迟加载（被标注 defer），**当** 工具列表构建时，**则** 该内置工具必须逐条声明（显式列出等同于强制扁平），不得只出现在目录中
3. **假设** `--tools` 只允许了部分工具且工具延迟加载生效，**当** 目录被渲染时，**则** 目录中不得出现任何未被 `--tools` 允许的工具（目录同样是白名单的下游，不是绕过白名单的入口；`ToolInvoke` 也不得成为调用白名单外工具的入口）
4. **假设** 用户以 `--tools "Read,Edit"` 启动且环境中配置了 MCP 服务器，**当** 工具列表构建时，**则** 目录中不出现任何 MCP 工具（工具集被限制为白名单内的工具）
   - **状态注记（待达成）**：本条当前**未实现**——今天 `--tools` 只约束内置工具的注册，**不过滤 MCP 工具**。本节是待达成的目标，不是现状；偏差记录见 [`core/tool-deferred-loading.md`](../core/tool-deferred-loading.md)。

---

### 边界情况

- **无效工具名称**：当用户提供不存在的工具名称（例如 `--tools "MagicWand"`）时会发生什么？
  - _假设_：系统应该警告用户并忽略无效工具或快速失败。
- **大小写敏感性**：工具名称是否区分大小写（例如"bash"vs"Bash"）？
  - _假设_：为方便用户，工具名称应不区分大小写，但映射到正确的内部名称。
- **冗余输入**：`--tools "Read,Read,Edit"` 会怎样？
  - _假设_：重复项应被去重。
- **与工具延迟加载的关系**：`--tools` 显式列出的工具（MCP 叶子 `mcp__server__tool` 或内置工具名）等同于强制逐条声明（效果同逐工具的 `alwaysLoad` opt-out），且目录只能包含白名单内的工具；被 `--tools` 排除的工具不得以「目录条目」的形式重新出现在可调用集合中，`ToolInvoke` 也不得成为调用白名单外工具的入口。
  - **状态注记（待达成）**：「目录只能包含白名单内的工具」对 **MCP 工具**当前**未实现**——今天 `--tools` 只约束内置工具的注册，不过滤 MCP 工具，因此 MCP 工具仍可能进入目录。本条是待达成的目标，不是现状；偏差记录见 [`core/tool-deferred-loading.md`](../core/tool-deferred-loading.md)。
