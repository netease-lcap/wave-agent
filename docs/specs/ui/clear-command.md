# 功能规格说明：清除命令

**特性分支**：`clear-command`
**创建日期**：2026-04-01

## 用户场景与测试 *（必填）*

### 用户故事：通过斜杠命令清除对话（优先级：P1）

作为 CLI 用户，我希望输入 `/clear` 来重置对话历史，以便在不重启应用的情况下开始全新会话。

**验收场景**：

1. **假设** 存在一个活跃对话且有消息，**当** 用户输入 `/clear`，**则** 对话历史被清除，生成新的会话 ID，并清除终端屏幕。
2. **假设** 正在处理中的 AI 响应，**当** 用户输入 `/clear`，**则** 正在进行的 AI 处理在清除对话前被中止。
3. **假设** 任务列表包含当前会话的项目，**当** `/clear` 执行后，**则** 任务列表与新的会话 ID 同步。

---

### 用户故事：通过 SDK 程序化清除（优先级：P1）

作为 SDK 消费者，我希望调用 `agent.clearMessages()` 来重置对话，以便我的应用程序可以程序化地开始新会话。

**验收场景**：

1. **假设** 存在一个活跃的代理会话且有消息，**当** 调用 `agent.clearMessages()`，**则** 对话历史被清除并生成新的会话 ID，效果与输入 `/clear` 相同。

---

### 用户故事：桌面端原地清除对话（优先级：P1）

作为桌面端用户，我希望 `/clear` 与 IDE 插件行为一致地原地清空当前对话，以便当前会话以新会话 ID 继续，而不会在侧边栏产生空条目。

**验收场景**：

1. **假设** 桌面端存在一个活跃对话且有消息，**当** 用户输入 `/clear`，**则** 对话历史被原地清除，生成新的会话 ID，且不新建后台代理会话。
2. **假设** 桌面端对话刚被 `/clear` 清空，**当** 清空完成后，**则** 侧边栏不出现空标题的新条目。
3. **假设** 桌面端对话刚被 `/clear` 清空，**当** 用户发送清空后的第一条消息，**则** 该会话以新会话 ID 登记进侧边栏会话列表。
4. **假设** 桌面端正在流式输出，**当** 用户输入 `/clear`，**则** 命令被忽略（与 IDE 插件一致）。
5. **假设** 桌面端用户点击"新对话"按钮或快捷键，**当** 当前会话有内容，**则** 生成全新的代理会话，原会话保留在侧边栏不受影响。

---

### 边界情况

- **如果在没有对话的情况下调用 `/clear` 会发生什么？** 仍然会生成新的会话 ID；不会抛出错误。
- **IDE 插件顶部"新建会话"按钮不执行清空**：该按钮改为在宿主新标签页中开启全新会话（见 session-management.md）；`/clear` 斜杠命令在 IDE 插件中保持原地清空语义。
- **桌面端 `/clear` 与"新对话"入口的区分**：`/clear` 在桌面端与 IDE 插件一致，原地清空当前会话；"新对话"按钮（侧边栏）与快捷键则生成全新的代理会话，二者互不影响。

## 需求 *（必填）*

### 功能需求

- CLI 必须在 `AVAILABLE_COMMANDS` 中将 `clear` 注册为 CLI 内部命令，清除逻辑在 `Agent.clearMessages()` 中实现。
- 执行 `/clear` 必须中止任何正在进行的 AI 消息处理。
- 执行 `/clear` 必须清除对话历史并生成新的会话 ID。
- 执行 `/clear` 必须将任务列表与新的会话 ID 同步。
- `Agent` 类必须暴露异步 `clearMessages()` 方法，其中直接包含清除逻辑（中止 AI、清除消息、同步任务）。
- CLI 必须通过清除终端屏幕并重新挂载聊天界面来响应会话 ID 变更。
- 桌面端 `/clear` 必须通过 stdio 调用 `agent.clearMessages()` 原地清空当前会话（与 IDE 插件一致），不得通过新建代理会话实现。
- 桌面端在会话 ID 变更通知中，仅当会话含有消息时才将其登记进侧边栏会话索引；清空后的空会话待首条用户消息时登记（与全新会话一致）。
- 桌面端"新对话"入口（侧边栏按钮、快捷键）必须使用独立于清除命令的消息新建代理会话。
- 流式输出期间 `/clear` 必须在所有宿主（CLI、IDE 插件、桌面端）被忽略。
