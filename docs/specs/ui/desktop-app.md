# 功能规格说明：Wave Desktop（Electron 桌面应用）

**特性分支**：`desktop-electron-app`
**创建日期**：2026-07-27

## 背景与目标

新增 `packages/desktop`，将 Wave Agent 包装为独立 Electron 桌面应用，服务于无 VS Code 的用户。Desktop 不 fork 子进程运行 Agent，而是通过 stdio 协议连接**全局安装的 wave-code CLI**（`wave --stdio`），复用 `packages/webview` 的 React UI 与现有会话/权限/更新等消息协议，实现与 IDE 插件功能对齐的桌面体验。SSO 登录、确认交互、文件提及与媒体等能力 webview 与 CLI 侧均已实现，desktop 仅做宿主消息层接线，行为与 IDE 插件保持一致。

在此基础上，desktop 进一步提供**原型预览与元素评论**能力：agent 启动的 localhost 开发服务器（如 Vite 原型）链接可直接在应用右侧预览面板打开，用户可在预览页中悬停高亮、点选元素并发表评论，评论连同元素上下文（页面 URL、CSS 选择器、元素摘要）作为用户消息发回 agent，形成「对话生成原型 → 预览 → 指哪改哪」的迭代闭环。该能力为 **desktop 独有**，IDE 插件（VSCE/JetBrains）不提供，其链接点击行为保持现状。

desktop 还支持**并排多对话**：将侧边栏中的会话拖拽到窗口右侧，即可在聊天区新增一个分屏展示该会话，2 条乃至更多会话并排陈列、各自独立输入与流式生成，把多会话并行（FR-031）从后台能力升级为可见的多任务工作台。该能力同为 **desktop 独有**，IDE 插件不提供。

## 用户场景与测试 *（必填）*

### 用户故事 1 - 无 VS Code 用户使用 Wave（优先级：P1）

作为一名没有安装 VS Code 的用户，我希望下载并安装 Wave 桌面应用后直接开始使用，以便我无需配置编辑器即可获得 AI 编程助手。

**为什么是这个优先级**：这是 desktop 存在的根本理由——覆盖没有编辑器的用户群体。

**独立测试**：在一台没有 VS Code 的机器上安装打包后的应用，启动后可以选择工作目录并开始对话。

**验收场景**：

1. **假设**用户已全局安装 `wave-code` CLI，**当**启动 desktop 应用，**则**应用必须显示工作目录选择界面，用户选择/确认后即可开始会话。
2. **假设**用户未安装 `wave-code` CLI，**当**启动 desktop 应用，**则**应用必须自动通过 npm 全局安装 CLI 并继续启动流程。
3. **假设**应用已启动，**当**用户发送消息，**则**主进程必须通过 `wave --stdio` 子进程运行 agent 并在 UI 中流式显示回复。

### 用户故事 2 - 会话管理（优先级：P2）

作为用户，我希望在应用内新建会话并恢复上次的会话与工作目录，以便我可以在不同任务之间切换。

**为什么是这个优先级**：会话管理是日常使用的基础能力，且 sidebar 是 desktop 相对 IDE 插件的布局扩展。

**独立测试**：进行一个会话后点击"新对话"开始全新会话；重启应用验证回到选择工作目录的初始状态；从侧边栏会话树恢复一条历史会话；删除一条 worktree 会话并验证 worktree 与临时分支被一并清理。

**验收场景**：

1. **假设**应用正在运行，**当**用户点击侧边栏"新对话"，**则**必须在当前窗口内开始一个全新会话（回到欢迎页 + 输入框状态）；**不中止任何正在生成的会话——原会话在后台继续运行，可从侧边栏切回查看结果**。
2. **假设**用户关闭并重新打开应用，**当**应用启动，**则**必须每次全新开始：不恢复上次的工作目录与会话，用户在输入框左上角的选择器中挑选目录（可从「最近打开」列表选择）后开始新会话。
3. **假设**侧边栏显示会话树，**当**用户查看侧边栏，**则**必须看到二级结构：一级为目录分组（可折叠），二级为该目录下最近 5 条会话（按最近活跃倒序）；会话树数据完全来自 desktop 自维护的会话索引，不向 CLI 查询。
4. **假设**有一个或多个会话正在流式生成回复，**当**用户查看侧边栏，**则**每个正在生成的会话条目前都必须显示"运行中"标识（可同时存在多个）；对应会话生成结束后其标识消失。
5. **假设**某会话存在等待用户响应的确认请求（工具权限/编辑确认、计划确认、AskUserQuestion 等），**当**用户查看侧边栏，**则**该会话条目前必须显示"待确认"标识（与运行中标识以颜色区分；待确认与运行中同时成立时优先显示待确认）；用户响应确认后其标识消失。
6. **假设**侧边栏会话树已加载，**当**用户点击当前目录下的某条会话，**则**必须恢复该会话到当前窗口；点击其他目录下的会话时，必须切换到该会话的工作目录再恢复；**切换会话或目录不中止任何正在生成的后台会话**。
7. **假设**侧边栏会话树已加载，**当**用户点击某条会话的删除图标并确认，**则**必须从索引中移除该会话；若该会话是 worktree 会话，还必须一并删除其 worktree 目录与临时分支。

### 用户故事 3 - SSO 登录（优先级：P1）

作为用户，我希望在 desktop 中完成 SSO 登录/登出，以便我可以使用企业账号访问 Wave 服务。

**为什么是这个优先级**：登录是首次使用的前置条件。SSO 登录流程（本地 HTTP 回调服务器、授权码交换、token 持久化）全程在 `wave --stdio` 子进程内完成，webview 已有登录按钮与 LoginDialog，desktop 只需接线宿主消息层。

**独立测试**：在未登录状态下启动应用，点击登录按钮，完成浏览器 SSO 授权后验证应用显示已登录状态并可以继续会话。

**验收场景**：

1. **假设**用户未登录，**当**用户点击登录按钮，**则**主进程必须向 CLI 发送 `login` 请求，收到 `authUrl` 通知后用系统默认浏览器打开授权页面。
2. **假设**用户在浏览器中完成授权，**当** CLI 子进程完成授权码交换，**则**主进程必须收到 `login` 响应并向 UI 回传 `loginResponse`，UI 显示已登录状态。
3. **假设**应用启动时已有有效 token，**当**主进程初始化，**则**必须通过 `getAuthStatus` 查询登录状态并通知 UI。
4. **假设**用户已登录，**当**用户触发登出，**则**主进程必须向 CLI 发送 `logout` 请求并更新 UI 为未登录状态。

### 用户故事 4 - 与 IDE 插件一致的交互能力（优先级：P1）

作为用户，我希望 desktop 中的确认（Confirmation）、AskUserQuestion、`@文件` 提及、图片粘贴、PDF 附件等交互与 IDE 插件完全一致，以便我获得相同的使用体验。

**为什么是这个优先级**：这些是 agent 交互的安全基础与核心场景，webview 已实现，desktop 必须保证宿主消息层正确接线。

**独立测试**：触发一个需要确认的工具调用并响应；输入 `@` 选择文件；粘贴图片发送。验证行为与 IDE 插件一致。

**验收场景**：

1. **假设** agent 发起工具确认或 AskUserQuestion 请求，**当**主进程收到请求，**则**必须渲染 webview 现有的确认/问答 UI，并将用户响应回传给 CLI。
2. **假设**用户在输入框键入 `@`，**当**用户选择文件，**则**应用必须通过主进程列出工作目录中的文件供选择（复用 webview 文件选择器）。
3. **假设**用户粘贴图片或附加 PDF，**当**消息发送，**则**媒体内容必须随消息发送给 agent（复用 webview 现有实现）。

### 用户故事 5 - 自动更新 CLI（优先级：P2）

作为用户，我希望应用启动时自动检测并升级 `wave-code` CLI 到兼容版本，以便我始终使用受支持的后端。

**为什么是这个优先级**：CLI 是 desktop 的运行时依赖，版本错配会导致协议不兼容。

**独立测试**：安装旧版本 CLI，启动应用，验证应用提示并自动升级。

**验收场景**：

1. **假设**已安装的 CLI 版本低于应用要求的最低版本，**当**应用启动，**则**应用必须通过 npm 全局升级 CLI 后再创建会话。
2. **假设** CLI 升级失败，**当**应用检测到失败，**则**必须向用户显示可操作的错误信息（如手动安装命令）。

---

### 用户故事 6 - 无干扰通知（优先级：P3）

作为用户，我希望版本更新提示和默认的 plan/通知提醒以非模态的方式出现在消息流中，以便我不会被系统弹窗打断。

**为什么是这个优先级**：desktop 无编辑器状态栏/状态对话框，需要替代通知通道。

**独立测试**：在会话中触发一个通知，验证它作为系统消息插入消息列表而非弹窗。

**验收场景**：

1. **假设** CLI 有新版本，**当**应用检测到更新，**则**必须在消息流中插入一条系统消息，而不是弹出模态对话框。
2. **假设**有后台任务或 plan 状态变化的通知，**当**通知到达，**则**默认在消息流中显示，不打扰当前输入。

### 用户故事 7 - 跨平台分发（优先级：P2）

作为团队，我希望 desktop 应用能打包为 macOS（arm64）和 Windows 安装包，以便覆盖主要用户平台。

**为什么是这个优先级**：分发能力决定功能是否能到达用户。

**独立测试**：在 CI 或本地分别打出 macOS arm64 与 Windows 包，安装后验证启动与会话功能。

**验收场景**：

1. **假设**配置了 electron-builder，**当**执行打包命令，**则**必须生成 macOS arm64 与 Windows 安装产物。
2. **假设**应用依赖 native node 模块，**当**在 macOS 上打包 Windows 产物失败，**则**必须先通过 CI matrix 调研解决，再实现打包流程。

### 用户故事 8 - 跟随系统主题（优先级：P2）

作为用户，我希望 desktop 自动跟随操作系统的亮色/暗色外观，与 IDE 插件保持一致的"不暴露独立主题切换选项"行为（VSCE 跟随 VS Code 主题、JetBrains 跟随 IDE LaF），避免在桌面端重复维护一套主题切换 UI。

**为什么是这个优先级**：webview 全程依赖 `--vscode-*` CSS 变量，Electron 宿主默认不注入任何变量，不实现本特性界面将不可用（背景透明、文字不可读）。但主题来源统一由操作系统外观驱动，不在桌面端暴露独立的亮/暗/系统切换选项，与 IDE 插件行为对齐、降低维护成本。

**独立测试**：在系统暗色与亮色外观下分别启动应用；运行中切换系统外观验证自动跟随、无需重启；流式输出期间切换系统外观验证不中断；退出重启验证首帧即呈现系统主题、无闪烁。

**验收场景**：

1. **假设**应用启动，**当**当前系统外观为暗色（或亮色），**则**首帧即呈现对应主题，不得出现明暗闪烁。
2. **假设**应用运行中，**当**用户切换操作系统外观（亮↔暗），**则**应用必须自动跟随切换，无需重启、不重建 React 树、不刷新页面、不中断会话与流式（仅重赋 CSS 变量）。

---

### 用户故事 9 - 基于分支的 worktree 隔离会话（优先级：P2）

作为用户，我希望在新会话页面选择分支并勾选 worktree，让会话在基于所选分支创建的临时 worktree 中进行，以便我并行试验而不污染主工作区。

**为什么是这个优先级**：worktree 隔离让用户在不污染主工作区的前提下并行试验，是桌面端"边改边试"的核心场景；创建与命名逻辑参考 CLI `wave -w` 的既有实现。

**独立测试**：选择一个 git 仓库作为工作目录，选择某分支并勾选 worktree 后开始会话，验证会话实际在新建的 worktree 目录中进行；不勾选时验证会话直接在所选目录中进行。

**验收场景**：

1. **假设**用户选择的工作目录是 git 仓库，**当**处于新会话状态（消息列表为空），**则**工作目录选择器旁必须显示分支选择器与「worktree」勾选项，分支选择器默认选中当前分支，worktree 勾选项默认勾选。
2. **假设**用户勾选了 worktree，**当**开始会话，**则**主进程必须基于所选分支创建随机命名的临时分支与 worktree（命名方案与 `wave -w` 一致），会话实际工作目录为该 worktree 路径。
3. **假设**用户未勾选 worktree，**当**开始会话，**则**会话必须直接在所选工作目录中进行（与现状一致）。
4. **假设**用户选择的工作目录不是 git 仓库或 git 命令不可用，**当**处于新会话状态，**则**不得显示分支选择器与 worktree 勾选项。
5. **假设**项目配置了 WorktreeCreate 钩子，**当**勾选 worktree 开始会话且 worktree 为本次新建，**则**必须在新 worktree 目录中执行该钩子（与 `wave -w` 行为一致）；复用已存在的同名 worktree 时不执行。

### 用户故事 10 - localhost 原型预览（优先级：P2）

作为用户，当 agent 为我启动了本地开发服务器（如 Vite 原型）后，我希望点击消息列表中的 localhost 链接时在应用右侧打开预览面板，而不是跳转到外部浏览器，以便我边对话边看原型。

**为什么是这个优先级**：预览面板是「指哪改哪」闭环的载体，没有它元素评论无从谈起；但应用基础对话能力不依赖它。

**独立测试**：让 agent 启动一个 localhost dev server，点击消息中的 localhost 链接，验证右侧预览面板加载页面；点击非 localhost 链接验证仍用外部浏览器打开。

**验收场景**：

1. **假设**消息列表中渲染了 localhost 链接（`localhost`、`127.0.0.1`、`[::1]`，任意端口），**当**用户点击，**则**必须在窗口右侧打开预览面板并加载该 URL；面板已打开时再点击另一 localhost 链接，则在同一面板内导航。
2. **假设**用户点击非 localhost 的 http(s) 链接，**则**必须用系统默认浏览器打开，行为与现状一致。
3. **假设**预览面板已打开，**当**用户点击关闭，**则**面板收起、聊天区恢复全宽；再次点击 localhost 链接可重新打开。
4. **假设**预览中的 dev server 支持热更新，**当** agent 修改源文件，**则**预览必须通过 dev server 自身的热更新机制自动反映改动；面板同时必须提供手动刷新按钮。
5. **假设**预览面板已打开，**当**用户点击「在浏览器打开」，**则**必须用系统默认浏览器打开当前预览 URL。
6. **假设**目标 localhost 服务不可达（未启动/已停止/端口错误），**当**预览加载失败，**则**面板必须显示可操作的错误提示（如「无法连接」+ 重试），而不是白屏。

---

### 用户故事 11 - 预览页元素评论（优先级：P2）

作为用户，我希望在预览面板里悬停高亮某个元素、点击它并写下评论，评论连同元素上下文一起发给 agent，以便 agent 精确理解我指的是哪里并据此修改原型。

**为什么是这个优先级**：这是「指哪改哪」闭环的核心交互，是本特性区别于「单纯开个浏览器」的价值所在。

**独立测试**：打开预览 → 开启元素拾取 → 悬停验证高亮 → 点击元素 → 输入评论并提交 → 验证聊天中发出一条含元素上下文的用户消息。

**验收场景**：

1. **假设**预览面板已加载页面，**当**用户开启「元素拾取」模式，**则**鼠标悬停的元素必须显示高亮轮廓，且页面自身交互（点击、链接跳转、表单提交）被拾取拦截。
2. **假设**拾取模式已开启，**当**用户点击某元素，**则**必须显示跟随该元素的浮层评论卡片：评论输入框底部左侧显示元素标签名、右侧为无文字的圆形发送图标按钮；被选元素保持定格高亮；用户可回车或点击发送图标提交，可通过点击卡片外空白处取消，取消后回到悬停拾取状态、可改选其他元素。
3. **假设**用户提交评论，**则**必须向当前会话发送一条用户消息，内容包含：页面 URL、元素 CSS 选择器、元素摘要、评论文本；该消息在聊天列表中的呈现与普通用户消息一致。
4. **假设**拾取模式已开启，**当**用户再次点击拾取开关，**则**必须退出拾取模式、恢复页面正常交互；提交评论后必须自动退出拾取模式（一次评论一个元素，不支持连续评论）。
5. **假设**页面发生导航或整体刷新，**则**拾取模式必须重置为关闭状态，防止拾取脚本随页面重建失效后界面状态不一致。

### 用户故事 12 - 侧边栏「更多」菜单（优先级：P3）

作为用户，我希望桌面端的设置、企业控制台、登录/登出入口集中在侧边栏，以便聊天头部保持简洁、应用级入口有固定位置。

**为什么是这个优先级**：纯布局调整，不改变任何菜单项功能；桌面端头部已无新建/历史按钮，迁移仅剩的「更多」按钮后头部更干净。

**独立测试**：desktop 下验证聊天头部无「更多」按钮、侧边栏头部右侧有；点击弹出菜单，逐项验证设置/企业控制台/登录登出行为与迁移前一致；在 VSCE/JetBrains 下验证头部「更多」按钮保持现状。

**验收场景**：

1. **假设**应用以 desktop 宿主运行，**当**用户查看界面，**则**聊天头部右上角不得显示「更多」按钮，侧边栏头部右侧必须显示「更多」按钮。
2. **假设**用户点击侧边栏「更多」按钮，**当**菜单弹出，**则**必须显示与迁移前一致的菜单项（设置、企业控制台、登录/退出登录），交互（点击外部/Esc 关闭、按登录态切换登录/退出登录项）与共享实现一致。
3. **假设**应用尚未选择工作目录，**当**用户点击侧边栏「更多」按钮，**则**菜单必须可用（设置/登录等入口不依赖工作目录）。
4. **假设**应用以 VSCE/JetBrains 宿主运行，**当**用户查看聊天头部，**则**「更多」按钮与菜单保持现状，不受影响。

### 用户故事 13 - 会话切换快捷键（优先级：P3）

作为用户，我希望用键盘快捷键在会话之间循环切换，以便无需鼠标点击侧边栏即可在多个并行会话间移动（与 Claude Code Desktop 的 `Ctrl+Tab` 体验一致）。

**为什么是这个优先级**：多会话并行后切换频次上升，快捷键是效率增强，非基础能力。

**独立测试**：创建多条会话（含跨目录分组），按 `Ctrl+Tab` / `Ctrl+Shift+Tab` 验证正/反向按侧边栏树顺序循环激活会话；macOS 上另按 `Cmd+Shift+]` / `Cmd+Shift+[` 验证等效；查看应用菜单栏验证存在对应菜单项并显示快捷键。

**验收场景**：

1. **假设**侧边栏会话树有多条会话，**当**用户按下「下一个会话」快捷键，**则**必须按会话树的展平顺序激活当前会话的下一条（跨目录分组），当前为末尾时回卷到第一条；「上一个会话」反向循环，当前为第一条时回卷到末尾。
2. **假设**目标会话属于其他目录分组，**当**快捷键切换发生，**则**行为与鼠标点击该条目完全一致：切换到该会话的工作目录（worktree 会话恢复到其 worktree 路径），且不中止任何后台生成中的会话。
3. **假设**折叠分组中包含会话，**当**循环经过该分组，**则**其会话照常参与循环（折叠仅影响展示，不影响循环顺序）。
4. **假设**会话树为空或仅当前一条会话，**当**用户按下快捷键，**则**无任何效果。
5. **假设**用户查看应用菜单栏，**则**必须存在「下一个会话」「上一个会话」菜单项并显示对应快捷键，点击菜单项与按快捷键等效。

### 用户故事 14 - 拖拽并排多对话（优先级：P2）

作为用户，我希望把侧边栏里的会话拖拽到窗口右侧，让 2 条甚至更多会话并排展示、各自独立交互，以便我对照多个任务的进展或同时推进多条对话。

**为什么是这个优先级**：多会话并行（FR-031）已让后台会话持续生成，并排展示把「并行」从后台能力升级为可见的多任务工作台；但不影响单会话基础体验。

**独立测试**：进行两条会话后，把其中一条从侧边栏拖到右侧聊天区，验证出现两个并排分屏、各自独立输入与流式；继续拖入第三条验证三分屏；关闭其中一个分屏，验证剩余分屏等宽重排且被关闭分屏的会话在后台继续运行。

**验收场景**：

1. **假设**侧边栏已有至少一条会话，**当**用户按住会话条目拖放到右侧聊天区，**则**必须在聊天区右侧新增一个分屏并展示该会话，原有分屏保持不动；拖放悬停期间聊天区必须显示放置反馈（放置区高亮与插入位置指示）。
2. **假设**已有两个分屏，**当**用户继续拖入其他会话，**则**必须继续向右追加分屏；新增后各分屏等宽重新分配。
3. **假设**被拖入的会话已在某个分屏中展示，**当**用户放下，**则**不得重复新增，改为聚焦并高亮已有该会话的分屏。
4. **假设**多个分屏并排，**当**用户在任一分屏的输入框发送消息，**则**消息必须进入该分屏绑定的会话；各分屏的消息流、流式状态、任务列表、消息队列与确认交互互不影响，多个分屏可同时流式生成。
5. **假设**多个分屏并排，**当**用户点击侧边栏会话，**则**必须替换「焦点分屏」展示的会话；焦点分屏为最近一次交互（点击或输入）的分屏并有可见标识，从未交互时焦点为第一个分屏；其他分屏的会话不受影响。
6. **假设**某分屏正在流式生成，**当**用户关闭该分屏，**则**分屏关闭但会话在后台继续生成（侧边栏运行中标识保留），剩余分屏等宽重排；仅剩一个分屏时不提供关闭入口。
7. **假设**新增分屏后各分屏宽度将低于最小宽度，**当**用户放下拖拽，**则**必须拒绝新增并给出轻量提示，现有分屏布局不变。

### 边界情况

- **CLI 缺失且 npm 不可用**：用户机器上没有 Node.js/npm 时，应用必须显示安装 Node.js 的引导信息，而不是抛出 npm 原始错误。
- **Node.js 版本过低**：系统 Node.js 主版本低于 20 时，应用必须提示升级 Node.js。
- **npm 注册表不可达**：CLI 安装/升级时必须使用 npmmirror 注册表以提高国内可达性；失败时给出手动安装命令。
- **工作目录不存在或被删除**：会话绑定的 cwd 失效时，agent 文件操作应报错且 UI 能显示该错误。
- **退出应用时会话仍在运行**：退出应用必须终止 CLI 子进程，避免孤儿进程。
- **auth/token 过期**：401 等鉴权失败的表现与当前 webview/stdio 行为保持一致（由 CLI 侧现有错误处理透出），本特性不做额外处理。
- **系统外观在流式输出期间变化**：系统外观在 agent 流式输出期间切换，应用必须立即跟随、不中断流式、不重建会话状态（渲染进程仅重赋 CSS 变量）。
- **nativeTheme 不可用**：主进程读取 `nativeTheme.shouldUseDarkColors` 失败时必须回退为暗色主题，不得崩溃。
- **非 git 工作目录或 git 不可用**：不显示分支选择器与 worktree 勾选项，会话直接在该目录进行。
- **worktree 创建失败**：分支名冲突、磁盘错误等导致 worktree 创建失败时，必须向用户显示错误，不得静默回退为在原目录开会话。
- **删除 worktree 会话时 worktree 已被外部删除**：git 清理命令失败不得阻塞删除流程，仅删除索引记录并向用户告警。
- **删除当前活跃会话**：允许删除；删除后回到新会话页（销毁该会话的 agent——若为 worktree 会话，须先切回原仓库目录再清理 worktree）。
- **快捷键触发时会话树为空或仅当前一条**：无效果（不报错、不切换）。
- **快捷键循环经过磁盘上已删除目录下的会话**：与点击行为一致——提示目录不存在，从会话索引移除该条记录。
- **后台会话请求权限确认**：后台（非活跃）会话发起工具确认/AskUserQuestion 时不弹窗打断当前视图，该会话挂起等待，侧边栏条目显示"待确认"标识；切回该会话时再弹出对应确认，用户响应后该会话继续。
- **并行会话数超上限**：超出存活 agent 上限时驱逐最久未使用的空闲会话（正在生成或待确认的会话不被驱逐）；被驱逐会话再选中时透明重建，用户无感知。
- **CLI 侧创建的会话不出现在侧边栏**：会话索引仅收录 desktop 内创建的会话，CLI 侧历史会话不展示、也不受影响。
- **预览目标服务不可达**：预览加载失败时必须显示错误提示与重试入口，不得白屏或影响聊天区。
- **拾取脚本注入失败**（页面异常、加载中途开启拾取等）：必须提示「该页面暂不支持元素拾取」并保持面板可用，不得崩溃。
- **被评论元素随后被 agent 改动**：评论携带的是提交时刻的上下文快照；选择器失效不构成错误，后续评论需重新拾取。
- **分屏中会话被删除**：侧边栏删除某会话时，展示该会话的分屏必须一并关闭；若它是唯一分屏，则该分屏回到新会话状态（始终保留至少一个分屏，不销毁其他分屏的 agent）。
- **可见分屏不参与 agent 驱逐**：FR-031 的最久未使用驱逐不得命中正在任一分屏展示的会话；容量压力仅在不可见会话间消化。
- **不可见会话的确认请求**：不在任何分屏展示的会话发起工具确认/AskUserQuestion 时维持后台挂起规则（见 FR-031 边界），重新可见时再弹出；已在分屏中展示的会话的确认直接在该分屏内显示。
- **窗口缩窄**：窗口变小导致现有分屏低于最小宽度时不强制关闭分屏，最小宽度仅约束「新增分屏」动作。
- **预览面板已打开时拖入会话**：预览面板保持最右侧唯一共享实例不变；分屏最小宽度校验在扣除预览面板宽度后的聊天区内计算，不足时同样拒绝新增。

### 功能需求

- **FR-001**：系统必须提供 `packages/desktop` Electron 应用，作为独立桌面客户端。
- **FR-002**：主进程必须通过 stdio 连接全局安装的 `wave-code` CLI（`wave --stdio`），而不是 fork 子进程运行 Agent。
- **FR-003**：启动时必须检测 CLI 是否存在；缺失时必须通过 `npm install -g wave-code --registry=https://registry.npmmirror.com` 自动安装；Node.js 主版本低于 20 时必须提示升级 Node.js；Node.js/npm 完全缺失时必须提示安装 Node.js。
- **FR-004**：启动时必须比较已安装 CLI 版本与要求的最低版本，低于最低版本时必须自动升级。
- **FR-005**：UI 必须提供常驻侧边栏：顶部为"新对话"按钮（plus 图标 + 文字），点击在当前窗口内开始全新会话（单窗口架构）；**新会话的工作目录必须取最近工作目录列表的首项**（最近使用的真实目录——worktree 会话激活时当前目录为 worktree 临时路径，但临时路径不入最近列表，见 FR-023，故新会话天然回退到其仓库根目录）；下方为会话历史树（见 FR-020）。工作目录选择入口位于输入框（input-wrapper）内部左上角，为下拉选择器（与权限模式下拉同模式：自定义 trigger + 菜单、点外部关闭），菜单选项包含「最近工作目录」列表与「浏览…」项；该选择器**仅在新会话状态（消息列表为空）显示**，对话一旦开始即隐藏，工作目录在新会话期间确定；无工作目录时显示「选择工作目录…」占位，首次启动与切换工作目录体验一致；**无工作目录时整个输入区（文本框、+、/、权限模式、发送按钮）必须禁用**（agent 未初始化，所有输入操作均无意义），仅 workdir 选择器保持可用，host 侧对绕过前端的发送请求必须以「请先选择工作目录」系统消息兜底。工作目录为 git 仓库时，选择器右侧还必须显示分支选择器与「worktree」勾选项（见 FR-022/FR-023）。
- **FR-006**：工作目录通过下拉里的「浏览…」项触发原生目录选择对话框选择；必须支持从最近目录列表中移除条目（仅删除持久化记录，不删除磁盘文件，也不影响侧边栏会话树——会话树由会话索引派生，见 FR-020）；不再提供"仅临时聊天"临时目录选项。
- **FR-007**：webview UI 必须零修改复用现有 Chat 组件；desktop 特有布局（侧边栏、工作目录选择）必须基于现有组件抽取扩展，通过 `Window.waveHostType` 区分宿主。
- **FR-008**：确认（Confirmation）、AskUserQuestion、`@文件` 提及、图片粘贴、PDF 附件必须复用 webview 现有实现，desktop 仅实现对应的宿主消息处理（如 `listFiles` 请求），行为与 IDE 插件一致。
- **FR-009**：desktop 每次启动必须全新开始：不持久化也不恢复上次的工作目录与会话。宿主侧在 `userData/wave-desktop.json` 持久化最近工作目录列表与会话索引（FR-024）；会话内容数据仍由 CLI 的 session store 管理，恢复会话通过 stdio 的 `restoreSession` 完成；侧边栏会话树由 desktop 会话索引驱动（FR-020），不再调用 stdio `listSessions`。
- **FR-020**：侧边栏必须提供二级会话历史树，数据完全来自 desktop 自维护的会话索引（FR-024），不得通过 stdio `listSessions` 拉取：
    - **一级**：目录分组完全从会话索引派生——按索引记录的 `workdir` 字段聚类，分组按组内最新会话的 `lastActiveAt` 倒序排列，可折叠/展开；默认展开当前会话所在分组，无当前会话（或当前会话不在任何分组中）时回退为展开当前工作目录分组，无工作目录时默认全部折叠；目录显示 basename；索引中无会话的目录不出现为分组（最近工作目录列表不参与侧边栏渲染，仅服务目录选择器）；磁盘上已删除的目录，其分组与会话仍保留列出，点击会话时自动从索引清除（见点击行为）。
    - **二级**：每个目录分组下展示该目录最近 5 条主会话（按 `lastActiveAt` 倒序，仅显示标题，不显示时间）；worktree 会话归入其原仓库目录分组，条目不显示额外标识。
    - **状态标识**：会话条目前以圆点标识状态（多会话并行时可同时多个条目带标识）：
        - **运行中**：正在流式生成回复的会话显示绿色圆点（`--vscode-testing-iconPassed`）；streaming 结束后消失。
        - **待确认**：会话存在等待用户响应的确认请求（工具权限/编辑确认、计划确认、AskUserQuestion 等）时显示警示色圆点（`--vscode-testing-iconQueued`，与运行中绿色同族配对）；用户响应后消失。待确认与运行中同时成立时优先显示待确认（会话挂起等待用户操作，"运行中"具有误导性）。
    - **数据加载**：索引变更（新会话创建、标题/时间更新、删除）及运行中/待确认状态变化后必须实时刷新推送 webview；目录切换不改变树数据，仅影响 webview 侧的分组展开状态。
    - **点击行为**：点击会话 → 激活该会话到当前窗口（该会话已有 live agent 时直接激活，否则为其创建 agent 并 `restoreSession`），**不销毁其他会话的 agent**；点击其他目录下的会话 → 切换到该会话的工作目录（worktree 会话恢复到其 worktree 路径）；点击磁盘上已删除目录下的会话 → 提示目录不存在，从会话索引移除该条记录（与失效 worktree 会话一致），并将目录从最近工作目录列表移除。
    - **删除**：每条会话提供删除图标（仅 hover 该条目时显示），行为见 FR-025。
- **FR-010**：版本更新提示与普通通知必须以非模态方式插入消息流显示。
- **FR-011**：desktop 必须支持斜杠命令，处理方式与 IDE 插件完全一致：斜杠命令不做宿主侧拦截，统一转发给 agent 处理（登录通过 webview 登录按钮/LoginDialog 触发，不经 `/login` 命令）。
- **FR-012**：desktop 必须支持 SSO 登录/登出，复用 webview 登录按钮与 LoginDialog（零修改）：主进程必须路由 `login`/`logout`/`getAuthStatus` 请求；收到 `authUrl` 通知时必须用系统默认浏览器打开授权页面；登录/登出完成后必须向 UI 回传 `loginResponse`/`logoutResponse`；初始化时必须通过 `getAuthStatus` 查询并同步登录状态；登录成功后必须向 agent 会话推送更新后的配置（含新 token）。SSO 流程本身（本地回调服务器、授权码交换、token 持久化）由 CLI 子进程完成。
- **FR-013**：必须提供 electron-builder 配置，支持 macOS（arm64）与 Windows 打包；native 模块跨平台打包若受阻，必须先通过 CI matrix 调研解决。
- **FR-021**：发布流程必须与 IDE 插件一致——`publish.yml`（`v*` tag 触发）中提供 `build-desktop` matrix 任务（`macos-latest` 产出 arm64 dmg/zip，`windows-latest` 产出 nsis 安装包），构建产物作为资源附件上传到同一个 GitHub Release（与 vsix、JetBrains zip 并列）；构建使用 production 模式压缩的 webview 产物，electron-builder 以 `--publish never` 运行（仅出包，发布由 action-gh-release 统一完成）；首版不做代码签名，macOS 未签名包的 Gatekeeper 绕过方式必须写入用户文档。
- **FR-022**：新会话状态下，若所选工作目录为 git 仓库，工作目录选择器右侧必须显示分支选择器与「worktree」勾选项；非 git 目录或 git 不可用时两者都不显示。分支选择器为下拉（与权限模式下拉同模式），列出该仓库本地分支，默认选中当前分支；分支列表必须通过 stdio `listGitBranches` 请求获取（不经 desktop 主进程直接执行 git），工作目录切换后必须重新查询；选择分支本身不改变工作目录。
- **FR-023**：勾选 worktree 并开始会话时，主进程必须通过 stdio `createWorktree` 请求创建临时分支与 worktree（复用 CLI `wave -w` 的创建与命名逻辑）：worktree 路径为 `<repoRoot>/.wave/worktrees/<name>`，分支名为 `worktree-<name>`，`<name>` 为双形容词-名词随机命名；请求携带用户所选分支作为基础分支；会话实际工作目录为返回的 worktree 路径，worktree 信息（路径、分支名、基础分支、仓库根）必须随会话记录持久化到会话索引；激活 worktree 会话时，最近工作目录列表必须记录其仓库根目录，而非 worktree 路径（worktree 为临时目录，不应进入最近列表）；创建失败必须向用户显示错误，不得静默回退为在原目录开会话。未勾选时行为与现状一致（会话直接在所选目录进行）。
- **FR-024**：desktop 必须自维护会话索引并持久化于 `userData/wave-desktop.json`：desktop 内创建的会话在创建时登记（sessionId、标题、所属目录、实际 cwd、lastActiveAt、可选 worktree 信息）；标题取首条用户消息截断；lastActiveAt 随会话活动更新；恢复会话等任何重新登记路径都不得丢失已有的 worktree 信息与所属目录（worktree 会话始终归属原仓库根目录）；索引仅收录 desktop 内创建的会话（CLI 侧历史会话不收录）；侧边栏会话树完全由该索引驱动。
- **FR-025**：侧边栏每条会话必须提供删除图标，仅 hover 该条目时显示；点击必须弹确认框——worktree 会话须明确告知将一并删除 worktree 目录与临时分支、未提交改动将丢失；确认后必须从会话索引移除该记录，若为 worktree 会话还须通过 stdio `removeWorktree` 请求清理其 worktree 与临时分支（`git worktree remove --force` + 删除 `worktree-<name>` 分支，复用 CLI 既有实现）；CLI session store 中的会话数据保留不删；worktree 清理失败不得阻塞索引删除（告警即可）；删除当前活跃会话后回到新会话页，若正在流式生成须先终止当前会话再清理。
- **FR-014**：主进程必须复用从 VS Code 扩展移植的 stdio 客户端层（StdioClient、BinaryResolver、StdioAgent）。
- **FR-015**：退出应用时必须终止 CLI 子进程。
- **FR-016**：主题来源必须为操作系统亮色/暗色外观，不暴露独立的主题切换选项（与 IDE 插件保持一致：VSCE 跟随 VS Code 主题、JetBrains 跟随 IDE LaF）。
- **FR-017**：主进程必须通过 Electron `nativeTheme` 在启动时及系统外观变化时计算当前 effective 主题（`light` / `dark`），并将主题信息注入渲染进程。
- **FR-018**：渲染进程必须在接收到主题信息后，通过 document root 的 `data-theme` 属性切换全套 `--vscode-*` CSS 变量（亮色/暗色各一组），webview 全部样式基于这些变量；主题切换必须以 `data-theme` 切换 + CSS 变量重赋值实现，**不得重建 React 树、不得刷新页面、不得中断会话与流式**。
- **FR-019**：首帧防闪烁——必须在 React 挂载前确定 effective 主题并写入 `<html data-theme>`，启动首帧即呈现系统主题，不得出现明暗闪烁。
- **FR-026**：消息列表中渲染的链接被点击时必须按目标分流（仅 desktop 宿主）：目标为 localhost（`localhost`、`127.0.0.1`、`[::1]`，任意端口）时在右侧预览面板打开；其他 http(s) 链接用系统默认浏览器打开。共享 webview 侧仅新增链接点击委托并按宿主类型分流，IDE 插件宿主的链接行为必须保持现状。
- **FR-027**：预览面板为窗口右侧与聊天区并存的侧栏：必须显示当前 URL；提供刷新、「在浏览器打开」、关闭操作；宽度可拖拽调整；同一时刻仅一个预览面板，新链接在面板内导航（不提供多标签并存）；dev server 热更新导致的页面变化不得破坏面板状态（URL 显示、工具栏可用）。
- **FR-028**：预览面板必须提供「元素拾取」开关，位于预览地址（URL 显示）右侧。开启后：悬停元素显示高亮轮廓；拦截页面自身点击/跳转/表单提交；再次点击开关退出；**提交评论后自动退出**（一次评论一个元素，不支持连续评论）；页面导航或整体刷新后自动重置为关闭。
- **FR-029**：拾取元素后必须显示**跟随元素的浮层评论卡片**：
    - **位置**：锚定在被选元素旁边，优先显示在元素下方，下方空间不足时翻转到上方；页面滚动或窗口缩放时跟随元素移动；元素被滚出可视区域时浮层暂时隐藏，滚回可见时恢复。
    - **内容**：单个输入框容器——评论输入区，底部一行左侧为元素标签名（仅标签名，如 `button`，悬停显示完整选择器），右侧为小尺寸圆形发送图标按钮（前景色圆形底 + 背景色箭头图标，不使用品牌红，不显示文字）。
    - **交互**：被选元素保持定格高亮；输入框聚焦状态下回车发送，发送图标按钮为等效点击入口；点击卡片外空白处视为取消，取消后回到悬停拾取状态、可改选其他元素。
    - **提交结果**：向当前会话发送一条用户消息，包含：页面 URL、元素 CSS 选择器、元素摘要（标签名 + 文本摘要）、评论文本；聊天列表呈现与普通用户消息一致。
- **FR-030**：健壮性要求：预览加载失败必须显示错误提示与重试入口（不白屏、不影响聊天区）；拾取脚本注入失败必须提示「该页面暂不支持元素拾取」且不得崩溃。
- **FR-031**：desktop 必须支持多对话并行生成——多个会话可同时流式生成回复，新建会话、切换会话、切换工作目录均不得中止其他正在生成的会话（含其他工作目录下的会话）。实现约束：
    - **多 agent 共存**：主进程为每个并行会话维护一个独立的 StdioAgent，多个 StdioAgent 共存于同一 `wave --stdio` 子进程（CLI 侧按 sessionId 多租户路由），可跨工作目录。
    - **活跃会话语义**：webview 为单视图，同一时刻只渲染「活跃会话」；新建/切换会话仅切换活跃指针，后台会话的 StdioAgent 保留、其增量通知不得推送到 webview（避免串台），仅更新自身缓存与会话树运行中标识。
    - **状态派生**：会话的运行中（streaming）状态记录在各 StdioAgent 上，宿主从活跃 agent 派生当前视图的 streaming 状态、从全部 agent 派生会话树各条目的运行中标识，不单列冗余状态表。
    - **容量上限**：同时存活的 agent 数必须有上限（默认 8）；超出时驱逐「非活跃 + 未在生成 + 无待处理确认」的最久未使用 agent；被驱逐的会话再次被选中时必须透明地重建 agent 并 `restoreSession`，用户无感知。
    - **清理语义**：删除会话、退出应用时必须销毁对应的 agent（退出时销毁全部）；配置/登录/登出/插件变更必须同步更新所有存活 agent 的配置。
- **FR-032**：侧边栏会话条目必须支持拖拽放下到右侧聊天区（基于 HTML5 拖放，不引入拖拽库）：放下时在聊天区右侧新增一个分屏展示该会话（该会话已有 live agent 时直接展示，否则创建 agent 并 `restoreSession`）；拖放悬停聊天区期间必须显示放置反馈（放置区高亮与插入位置指示）；拖放一律为右侧新增，不支持拖到已有分屏上替换（替换通过点击侧边栏完成，见 FR-035）；拖入已在某分屏展示的会话时不得重复新增，改为聚焦并高亮该分屏。
- **FR-033**：分屏为聊天区内的纵向分栏：各分屏等宽分配，最小宽度 360px，新增后平均分宽将低于 360px 时必须拒绝新增并给出轻量提示（预览面板打开时在扣除其宽度后的聊天区内校验）；分屏数量不设固定上限，仅受最小宽度约束；每个分屏头部右侧提供关闭按钮，仅剩一个分屏时不显示关闭按钮（始终保留至少一个分屏）；关闭分屏不销毁会话 agent——正在生成的会话在后台继续，侧边栏运行中标识不变，可从侧边栏再次打开；窗口缩小不强制关闭已有分屏。
- **FR-034**：每个分屏必须拥有独立的消息列表、输入区、任务列表、消息队列与确认交互（首版分屏头部复用现有头部组件，其新对话/中止按钮作用于本屏会话，全局设置/登录按钮各屏重复展示但行为一致）；输入发送、中止、队列操作、确认响应、消息回退等会话级操作必须按分屏路由到对应 agent——webview 与宿主之间以分屏标识寻址（新会话状态的分屏尚无 sessionId，亦须可寻址），宿主推送的会话级增量消息必须携带分屏/会话标识，webview 按分屏过滤渲染；登录状态、应用配置、主题、权限模式等全局状态各分屏共享，配置/登录变更仍同步全部存活 agent。
- **FR-035**：必须维护「焦点分屏」：用户在某分屏内点击或输入即将其设为焦点，焦点分屏必须有可见标识，默认焦点为第一个分屏；点击侧边栏会话、点击侧边栏「新对话」均作用于焦点分屏（替换其展示的会话/切换为新会话状态），不得销毁其他分屏的 agent；关闭焦点分屏后焦点移至相邻分屏。
- **FR-036**：正在任一分屏展示的会话不得被 FR-031 的最久未使用驱逐；被删除会话所在分屏必须关闭（唯一分屏则回到新会话状态）；不在任何分屏展示的会话沿用 FR-031 的后台挂起与驱逐规则不变。
- **FR-037**：desktop 宿主下，聊天头部右上角的「更多」按钮及其菜单（设置、企业控制台、登录/退出登录）必须迁移至侧边栏头部右侧：菜单复用共享 MoreMenu 组件，菜单项与交互（点击外部/Esc 关闭、按登录态渲染登录/退出登录项）保持不变，弹出层锚定于侧边栏头部；未选择工作目录时菜单必须可用。该迁移仅作用于 desktop 宿主（按宿主类型分流渲染），VSCE/JetBrains 宿主的头部「更多」按钮与菜单保持现状。
- **FR-038**：desktop 必须提供「下一个会话」「上一个会话」快捷键（仅 desktop 宿主；VSCE/JetBrains 不提供，避免与 IDE 自身的 `Ctrl+Tab` 编辑器切换器冲突）：
    - **键位**（与 Claude Code Desktop 对齐）：下一个 `Ctrl+Tab`、上一个 `Ctrl+Shift+Tab`（全平台）；macOS 额外支持 `Cmd+Shift+]` / `Cmd+Shift+[`。
    - **循环顺序**：侧边栏会话树的展平顺序（分组顺序与组内顺序均与 FR-020 的派生规则一致），跨目录循环，到达边界回卷；折叠分组的会话照常参与循环。当前处于未入索引的新会话状态时，「下一个」激活树中第一条，「上一个」激活最末一条。
    - **切换语义**：与点击会话条目完全一致（FR-020 点击行为、FR-024 索引驱动），不中止任何后台生成中的会话（FR-031）。
    - **菜单入口**：应用菜单栏必须提供「下一个会话」「上一个会话」菜单项并显示快捷键（desktop 当前无自定义菜单，本特性引入自定义应用菜单，须保留平台默认菜单能力——macOS 应用菜单与编辑菜单的复制/粘贴等）；菜单项点击与快捷键等效。
- **FR-039**：desktop 勾选 worktree 创建新会话时，必须触发与 `wave -w` 和 EnterWorktree 工具一致的 WorktreeCreate 钩子：主进程在 stdio `createWorktree` 返回后，必须将 `worktreeName`（worktree 名）与 `isNewWorktree`（取自响应的 `isNew`）随 initialize 请求传给 CLI 子进程，由 Agent 初始化流程在 `isNew` 为 true 时触发钩子（在新 worktree 目录中执行、stdin JSON 含 `name` 字段，语义见 hooks 规格）；复用已存在 worktree（`isNew` 为 false）时不得触发。配置更新（updateConfig）重建 agent 时必须保留 `worktreeName` 上下文，但不得再次触发 WorktreeCreate 钩子。

### 关键实体 *（如果功能涉及数据则包含）*

- **HostSession**：宿主会话管理——多对话并行架构下为「agents 注册表 + 分屏列表 + 焦点分屏指针」。
    - `agents`：`sessionId → StdioAgent` 的存活 agent 注册表；每个 StdioAgent 包装 CLI 子进程内的一个会话，缓存其 `messages`/`tasks`/`queuedMessages`/`isStreaming` 等状态（作为派生数据源）。
    - `panes`：有序分屏列表（左→右），每项绑定一个 `sessionId` 或处于新会话状态（无 sessionId）；至少保留一项；分屏展示的会话不参与最久未使用驱逐。
    - `focusedPane`：焦点分屏指针，webview 单窗口内点击/输入所在分屏即为焦点；侧边栏点击会话、「新对话」均作用于焦点分屏。
    - `pendingConfirmations`：等待用户响应的确认请求映射（每条关联发起方 agent）。
    - `inputDrafts`：各会话的输入框草稿。
- **宿主配置**（`userData/wave-desktop.json`）：
    - 应用配置（apiKey/baseURL/model 等）、最近工作目录列表、会话索引。不持久化当前工作目录与当前 `sessionId`。
- **会话索引记录**（desktop 自维护，持久化）：
    - `sessionId`：会话 ID。
    - `title`：标题（首条用户消息截断）。
    - `workdir`：所属目录（worktree 会话为其原仓库目录，用于侧边栏分组）。
    - `cwd`：会话实际工作目录（worktree 会话为 worktree 路径，恢复会话时作为 agent 工作目录）。
    - `lastActiveAt`：最近活跃时间（排序依据）。
    - `worktree?`：worktree 信息——`path`（worktree 路径）、`branch`（临时分支名 `worktree-<name>`）、`baseBranch`（基础分支）、`repoRoot`（仓库根）。
- **会话历史树**（宿主由会话索引推导并推送 webview）：
    - 目录分组列表：由会话索引按 `workdir` 聚类派生，分组按组内最新会话 `lastActiveAt` 倒序；每个分组含 workdir、该目录最近 5 条会话（id、标题、`lastActiveAt`、是否 worktree 会话——供删除确认框文案使用，不渲染标识）、展开状态（webview 侧 UI 状态）。
    - 每条会话的 `running`（运行中）标识：由该会话对应 StdioAgent 的 `isStreaming` 派生（无存活 agent 的历史会话为 `false`）；多会话并行时可多条同时为 `true`。
    - 每条会话的 `waitingConfirmation`（待确认）标识：由宿主 `pendingConfirmations` 中是否存在关联该会话 agent 的确认请求派生（无存活 agent 或无待处理确认为 `false`）。
    - 分屏展示标识：正在分屏中展示的会话条目高亮（焦点分屏强标识、其余分屏弱标识），替代单视图时期的「当前活跃会话」高亮。
- **预览面板状态**（desktop 宿主维护）：
    - 当前预览 URL、加载状态（加载中/成功/失败）、面板开合与宽度、元素拾取模式开关。
- **元素评论上下文**（提交评论时随用户消息发送）：
    - 页面 URL、元素 CSS 选择器、元素摘要（标签名 + 文本摘要）、评论文本。

## 非目标（明确排除）

- **多窗口**：单窗口架构，会话在当前窗口内切换。
- **webview 内部逻辑修改**：不改写 ChatApp/useChat 等核心交互逻辑，仅做布局扩展与组件抽取；预览特性在共享 webview 侧仅新增链接点击委托，按宿主类型分流，IDE 宿主行为不变。
- **Linux 打包**：首版仅 macOS（arm64）与 Windows。
- **IDE 插件的预览与元素评论**：预览面板与元素拾取评论为 desktop 独有，VSCE/JetBrains 不提供。
- **按序号直跳会话**（如 `Cmd+1~9` 跳到第 N 条会话）：首版不做，仅顺序循环。
- **快捷键清单面板**（如 `Cmd+/` 弹出快捷键速查）：首版不做。
- **VSCE/JetBrains 宿主的会话切换快捷键**：IDE 自身占用 `Ctrl+Tab`（编辑器切换器），不提供。
- **URL 到源码文件的精确定位**（如通过构建工具插件注入源码位置信息）：首版不做，依赖 agent 会话上下文与元素评论上下文定位。
- **拾取模式的键盘快捷键**（Esc 退出等）：首版不做，仅通过开关按钮与提交后自动退出管理拾取状态。
- **元素截图**：首版评论消息不附带元素截图，仅携带页面 URL、CSS 选择器与元素摘要等文本上下文。
- **折叠分组头部的状态聚合提示**：运行中/待确认标识仅在会话条目上显示，分组折叠时不在分组头部做聚合上卷。
- **分屏宽度手动调节与分屏重排**：首版分屏等宽自动分配、仅右侧追加，不提供分隔条拖拽调宽，也不支持拖拽调整分屏左右顺序。
- **分屏布局跨重启持久化**：重启应用回到单分屏新会话状态（与 FR-009 每次全新开始一致）。
- **IDE 插件端分屏**：并排多对话为 desktop 独有，VSCE/JetBrains 维持单视图。
- **分屏内标签页**：一个分屏同一时刻只绑定一条会话，不做分屏内多标签。
