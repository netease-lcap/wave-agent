# 功能规格说明：会话管理

**规格文件**：`docs/specs/ui/session-management.md`
**创建日期**：2026-01-21

> **平台边界**：前三个用户故事及会话存储相关功能需求为 CLI/SDK 宿主；「IDE 插件聊天头部」用户故事适用于 IDE 插件 webview（VSCE / JB）。

## 用户场景与测试 *(必填)*

### 用户故事：基于项目的组织（优先级：P1）

作为处理多个项目的开发者，我希望我的代理会话按项目的工作目录组织，以便我能轻松找到和管理与当前工作相关的会话。

**优先级原因**：面向开发者的代理的核心组织需求。

**独立测试**：在不同目录中创建会话并验证它们存储在 `~/.wave/projects` 下的独立子目录中。

**验收场景**：

1. **假设** 有工作目录，**当** 创建会话时，**则** 它必须存储在以编码路径命名的子目录中。
2. **假设** 有较长或复杂的路径，**当** 编码时，**则** 它必须是文件系统安全的且限制为 200 个字符。

---

### 用户故事：高性能会话列表（优先级：P1）

作为拥有数百个历史会话的用户，我希望会话列表能快速加载，以便在启动或切换会话时不会体验到延迟。

**优先级原因**：随着会话数量增长，这对良好的用户体验至关重要。

**独立测试**：生成 100 个大会话文件并测量列出它们的时间；应该是近乎即时的，因为系统从单个 `sessions-index.json` 文件读取。

**验收场景**：

1. **假设** 有多个会话文件，**当** 列出会话时，**则** 系统必须从 `sessions-index.json` 读取以实现 O(1) 性能。
2. **假设** 索引缺失或损坏，**当** 列出会话时，**则** 系统必须回退到读取每个文件的最后一行并重建索引。

---

### 用户故事：子代理会话分离（优先级：P2）

作为使用子代理的开发者，我希望子代理会话被清楚地标识并与主代理会话分离，以避免污染主会话历史。

**优先级原因**：在处理复杂的多代理工作流时提高清晰度。

**独立测试**：启动子代理并验证其会话文件以 `subagent-` 为前缀。

**验收场景**：

1. **假设** 子代理已创建，**当** 其会话被保存时，**则** 文件名必须以 `subagent-` 开头。

---

### 用户故事：IDE 插件聊天头部（优先级：P2）

作为 IDE 插件用户，我希望聊天面板顶部显示当前会话标题和常用操作（新建会话、历史对话、更多菜单），以便快速切换会话和管理当前会话。

**为什么是这个优先级**：会话切换与新建是高频入口，但用户仍可通过清空输入重新开始，属于体验增强。

**独立测试**：发送一条消息后观察标题栏显示会话标题；点击"新建会话"验证新标签页开启全新会话且当前会话保留；点击"历史对话"选择一个会话验证消息恢复。

**验收场景**：

1. **假设**会话中已有消息，**当**标题栏渲染时，**则**显示由首条消息截断得到的会话标题（最多 30 字符）；无消息时显示"新会话"。
2. **假设**用户点击"新建会话"按钮（包括 AI 响应流式输出期间），**当**操作发生时，**则**宿主打开一个新标签页承载全新会话，当前会话在其标签页中保留且不被中断；按钮在流式输出期间保持可用。
3. **假设**用户点击"历史对话"按钮，**当**操作发生时，**则**弹出历史会话列表；选择其中一个会话后其消息被恢复到聊天面板。
4. **假设**用户点击"更多"按钮，**当**操作发生时，**则**弹出更多菜单（设置、企业控制台、登录/退出登录，见 sso-auth.md 的更多菜单条目）。
5. **假设**标题栏右侧显示上下文用量指示，**当**会话进行中时，**则**实时反映当前 token 使用情况（见 context-usage-indicator.md）。

---

### 边界情况

- **权限问题**：如果无法创建或写入会话目录，系统应优雅地失败并给出清晰的错误提示。
- **损坏的文件**：如果 JSONL 文件包含无效 JSON，在列出时应跳过，在加载时应视为不存在。
- **空会话**：没有消息的文件应使用文件的修改时间作为 `lastActiveAt` 时间戳。
- **路径编码冲突**：使用哈希后缀确保长路径即使被截断也具有唯一性。
- **会话标题为空**：IDE 插件会话首条消息缺失或为空时，标题回退为"新会话"。
- **流式期间新建会话**：IDE 插件"新建会话"按钮在 AI 响应流式输出期间保持可用——新会话在新标签页中进行，当前会话的生成不中断、保持可见。

## 需求 *(必填)*

### 功能需求

- 所有会话数据必须存储在 `~/.wave/projects` 中。
- 会话必须根据项目工作目录路径的编码版本分组到子目录中。
- 工作目录路径必须编码为文件系统安全的格式，解析符号链接并处理特殊字符。
- 编码的目录名必须限制为 200 个字符，对更长的路径使用哈希后缀。
- 会话必须以 JSONL（JSON Lines）格式存储，每行一个 JSON 对象表示一条消息。
- 主会话文件必须使用 UUID 命名。链中的第一个会话 ID 必须被指定为 `rootSessionId` 并持久化在 `SessionIndex` 中。
- `rootSessionId` 必须在消息压缩和会话恢复之间保留，以为会话范围内的资源（如计划文件和任务列表）提供稳定的标识符。
- 子代理会话文件必须以 `subagent-` 为前缀。
- 每条消息行必须包含 ISO 8601 格式的 `timestamp` 字段。
- 会话元数据必须从文件名、目录结构和最后一条消息行中派生。
- 会话列表必须优化为使用 `sessions-index.json` 以实现 O(1) 性能，最小化 I/O。
- 超过 14 天的会话必须自动清理。
- 清理期间必须移除空的项目目录。
- 每个项目目录必须维护一个 `sessions-index.json` 文件用于 O(1) 会话列表。
- 会话索引必须缓存 `firstMessage` 内容以实现即时 UI 显示。
- 如果会话索引缺失或损坏，系统必须能够从 `.jsonl` 文件重建。
- `firstMessage` 字段必须跳过元消息（`isMeta: true`）并捕获第一个非元消息内容用于会话列表显示。

以下 FR 仅适用于 IDE 插件 webview（VSCE / JB）的聊天头部：

- IDE 插件聊天面板必须显示头部栏，包含当前会话标题与操作按钮（新建会话、历史对话、更多）。
- 会话标题必须由首条消息截断得到（最多 30 字符）；首条消息缺失时显示"新会话"。
- 点击"新建会话"必须在宿主的新标签页中开启全新会话——VS Code 中为新的编辑器标签页（从侧边栏点击时同样打开编辑器标签页，侧边栏当前会话保留），JetBrains 中为工具窗口新标签页；当前会话必须保留且不被中断，AI 响应流式输出期间该按钮必须保持可用。
- IDE 插件中 `/clear` 斜杠命令必须保持原地清空当前会话（见 clear-command.md），与"新建会话"按钮的新开标签页行为相区分。
- 点击"历史对话"必须弹出历史会话列表，选择会话后其消息必须被恢复到聊天面板。
- 点击"更多"必须弹出更多菜单（设置、企业控制台、登录/退出登录），菜单项行为见 sso-auth.md 的更多菜单条目。
- 头部栏必须显示上下文用量指示（见 context-usage-indicator.md）。

### 关键实体

- **Session**：用户与代理之间对话的记录。
    - `id`：当前会话的 UUID。
    - `rootSessionId`：链中第一个会话的 UUID（跨压缩持久化）。
    - `type`：'main' 或 'subagent'。
    - `workdir`：与会话关联的项目目录。
    - `lastActiveAt`：最后一条消息的时间戳。
    - `messages`：消息对象列表。
    - `firstMessage`：（可选）会话中第一条消息的内容，用于显示目的。
- **SessionIndex**：
    - `sessions`：会话 ID 到元数据的映射。
    - `lastUpdated`：最后一次索引更新的时间戳。
- **项目目录**：属于特定路径的会话容器。
    - `path`：原始文件系统路径。
    - `encodedPath`：用于目录的文件系统安全名称。

## 假设

- 用户的家目录可访问且可写。
- JSONL 是一种高效的格式，可以在不重写整个文件的情况下追加消息。
