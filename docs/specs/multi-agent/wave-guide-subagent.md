# 功能规格说明：文档问答子代理（wave-guide）

**创建日期**：2026-10-29

> 背景：用户问「Wave 怎么配 hooks」「有没有 X 功能」这类问题时，主模型目前只能凭上下文里的零碎材料回答，容易给出不存在的设置项或过期的界面路径。Claude Code 的对位能力是内置 `claude-code-guide` 子代理：只读、`Read + WebFetch + WebSearch` 工具面、内嵌一份文档地图。
> 本规格的取舍：**不内嵌文档地图**，改为把文档站入口注入子代理提示词（`${WAVE_DOCS_URL}`），由子代理自己先读 `llms.txt` 目录、再取 1–3 页正文。理由：文档站已经产出 `llms.txt`（144 条、含每页 description）与每页同名 `.md`，地图本身是活文档；内嵌快照只会在页面增删后漂移。代价是每次多一次 WebFetch，换来的版本同源（内嵌内容跟 CLI 发版，站点跟文档站发版，两者都不保证与对方一致）。
> `WebSearch` 至今未实现，本规格不依赖它——文档站目录已覆盖全部产品页，未命中时的正确行为是「说清没找到并给出链接」，不是去搜网页。

## 用户场景与测试 _（必填）_

### 用户故事：把产品问答委托给读文档的子代理（优先级：P1）

作为用户，我希望问「Wave 怎么做 X」时，回答来自官方文档而不是模型的记忆，这样界面路径、命令名、配置字段都是真的。

**为什么是这个优先级**：这是子代理存在的唯一理由。主模型拿不到文档时凭印象作答，错的是「具体写法」这类最容易被当真照做的部分。

**独立测试**：加载内置子代理配置，断言存在名为 `wave-guide` 的配置、工具面不含写类工具、`model` 为 `fastModel`；用桩 WebFetch 返回一份 `llms.txt`，断言提示词引导它先取目录、再按目录里的链接取正文，且最终答复带上被引用页面的链接。

**验收场景**：

1. **假设** 内置子代理已加载，**当** 主代理查看可用子代理列表时，**则** `wave-guide` 出现且描述写明「回答 Wave 用法问题、先读文档」的触发条件
2. **假设** 用户问「桌面端怎么配置 MCP」，**当** `wave-guide` 执行时，**则** 它先取 `${WAVE_DOCS_URL}llms.txt`，再取目录中对应的一页正文作答，答复包含界面路径与文档链接
3. **假设** 问题跨越两个主题（如「权限模式和定时任务」），**当** `wave-guide` 执行时，**则** 最多取 3 页正文，不整站抓取
4. **假设** `llms.txt` 返回 404 或请求失败，**当** `wave-guide` 执行时，**则** 它明确写出「文档站不可达」、给出文档入口链接，并且只回答在本地文件里能验证的部分，不猜测设置项名称

---

### 用户故事：文档入口跟随部署而非写死（优先级：P2）

作为私有化部署的用户，我希望这个子代理读的是**我这套部署**的文档站，而不是生产环境的地址。

**为什么是这个优先级**：默认 `WAVE_SERVER_URL` 指生产，但企业/测试环境的文档站挂在各自的 `<serverUrl>/docs/` 下；写死 URL 会让私有化部署的问答全部指向外网。

**独立测试**：在 `env.WAVE_SERVER_URL` 设为测试环境地址时加载内置子代理，断言 `wave-guide` 的系统提示词里出现 `<该地址>/docs/`；未设置时断言使用 `DEFAULT_SERVER_URL`。

**验收场景**：

1. **假设** 会话环境变量 `WAVE_SERVER_URL` 为 `https://example.internal`，**当** 内置子代理被加载时，**则** 系统提示词里的文档入口为 `https://example.internal/docs/`
2. **假设** `WAVE_SERVER_URL` 未设置，**当** 内置子代理被加载时，**则** 文档入口为默认服务端地址下的 `/docs/`
3. **假设** `WAVE_SERVER_URL` 末尾带斜杠，**当** 替换进提示词时，**则** 拼出的入口只有一个斜杠，不出现 `//docs/`

---

### 用户故事：只读、轻量、不乱抓（优先级：P2）

作为用户，我希望这个子代理不碰我的工作区、也不把整站文档塞进上下文，这样它的每次调用都便宜且安全。

**为什么是这个优先级**：它是「查资料」角色，任何写操作都超出职责；而 `llms-full.txt` 是几百 KB 的合集，一次抓取会挤掉真正要读的内容。

**独立测试**：断言 `wave-guide` 的 `disallowedTools` 覆盖 `Edit`/`Write`/`Agent`/`Artifact`/`ExitPlanMode`/`Bash`；提示词中写明禁止整站抓取（尤其是 `llms-full.txt`）。

**验收场景**：

1. **假设** `wave-guide` 已在运行，**当** 它尝试编辑文件或创建文件时，**则** 对应工具不可用（不在它的工具池里）
2. **假设** 需要通读某一主题，**当** `wave-guide` 取正文时，**则** 它按页取 `.md`，不请求 `llms-full.txt`
3. **假设** 工作目录本身是 Wave 仓库（含 `docs/`），**当** 用户问的是实现细节，**则** 允许它用 `Grep`/`Read`/`Glob` 直接读本地文档与源码，并给出绝对路径

## 非功能需求

- 提示词与工具面必须是静态可复现的：除 `${WAVE_DOCS_URL}` 一处替换外，不依赖运行期额外注入
- 子代理必须只读：不得写文件、不得派生子代理
- 单次回答的文档抓取上限为 3 页（含目录页）
- 找不到答案时必须输出「未在文档中找到 + 文档入口链接」，禁止凭印象补全设置项名或界面路径
- 新增内置子代理会占用每轮 Agent 工具描述的位置，`description` 必须控制在 2 句话内
