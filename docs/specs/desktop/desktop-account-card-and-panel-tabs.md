## 方案总览（对应 zip §0）

账户卡片采用「**用量常驻 + 个人信息菜单 + 更新按钮**」三段式：

```
┌─────────────────────────────┐
│ 套餐用量     80%            │  ← 用量常驻区（可收起/展开）
│ ████████░░░░░░             │     收起后仅剩个人信息一行
│ API 余额          ¥8,846.86 ⓘ │
├─────────────────────────────┤
│ (A) alice      [更新] (icon) │  ← 个人信息行：头像+姓名热区
└─────────────────────────────┘      右侧：更新按钮 + 用量显隐按钮
```

**关键设计决策（zip 定稿）**：

1. 菜单为**纯功能菜单**，不再承载用量信息（用量只由常驻区负责）。
2. 菜单开合**不影响**用量常驻区显隐（两者解耦，显隐由 chevron 独立控制）。
3. 菜单**贴着个人信息行顶部弹出**，覆盖上方用量信息（不拉开距离）。
4. 菜单宽度与账户卡片**等宽**（右缘对齐），内容不超出面板。

**右侧面板形态**：从「每类型一个面板槽 + 多选并排 + 面板内多标签」改为「**右侧单槽位 + 一级 Tab 栏**」——每个打开的实例是一个外层 tab；preview 为多实例（每次打开都新增一个 tab），其余类型（plan/diff/terminal/file）为唯一实例（open-or-activate / 复用）。共享面板槽在折叠时保持挂载（`display:none`）以保全预览 guest 与终端 PTY。关闭最后一个 tab 后面板保持展开并显示空态引导（空态提供五能力入口，可直接换开其它面板）；面板整体收起仅由头部按钮触发（收起保留全部 tab 实例，再次展开原样恢复）。

**与当前 main 实现的差异点**（revert 后现状 → 本文档目标）：

| 维度           | 当前 main（revert 后，视觉基线）                    | 本文档目标（zip v3/v3.1 + 合并代码语义）                                                                                                                          |
| -------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 用量入口       | 点击账户热区弹「用量浮层」（`account-usage-popup`） | 用量**常驻区**直接展示在个人信息行上方，可 chevron 收起/展开                                                                                                      |
| 用量明细       | 浮层内直接并列展示                                  | 行内低信息密度：仅余额金额/状态短词，明细与预警收进 hover ⓘ 气泡                                                                                                  |
| 已登录菜单入口 | 独立「…」更多按钮（`account-card-more`）弹菜单      | 无独立更多按钮——点击头像/姓名热区 toggle 纯功能菜单（`aria-expanded`）                                                                                            |
| 用量与菜单耦合 | 用量浮层与菜单是两条入口                            | 常驻区显隐与菜单开合**解耦**，各自独立                                                                                                                            |

## 数据契约与命令（对应 zip §1）

### desktopAccountInfo（窗口级推送，无 paneId）

目标契约（在**当前 fixtures 基础上新增 `update?` 字段**）：

```ts
export interface AccountUpdateInfo {
  available: boolean; // 有新版本
  version?: string; // 新版本号（对话框/按钮 tooltip 文案使用）
  status?: "idle" | "downloading" | "ready"; // 更新过程状态
}

export interface DesktopAccountInfoMessage {
  // 现有字段不变
  command: "desktopAccountInfo";
  isAuthenticated: boolean;
  user?: { id: string; email?: string } | null;
  plan?: AccountPlanInfo | null; // { monthlyQuota, months, used }
  apiQuota?: AccountApiQuotaInfo | null; // { limit: number|null, used }
  update?: AccountUpdateInfo | null; // ← 目标新增
}
```

**下发规则**：

- 未登录：`isAuthenticated: false`，user/plan/apiQuota/update 可不带。
- 未配置套餐：不带 `plan`（用量区不渲染该块）；`plan` 与 `apiQuota` 均未下发时用量区整体不渲染、显隐按钮不显示。
- API 不限额：`apiQuota.limit: null`（共用团队余额）。
- 无更新：不带 `update` 或 `update.available: false`。
- 账户/余量/额度/更新状态变化时宿主主动推送新快照；轮询失败保留上次成功数据。

### 套餐余量计算（按余量计）

```
planTotal     = monthlyQuota × months
planPercent   = max(0, round((1 − used / planTotal) × 100))   // 余量百分比
planExhausted = used >= planTotal
```

- 100% = 满（未使用），0% = 用完（已用 ≥ 总量，0% 封底防负）。

### 命令契约

- `desktopUpdateDownload`（webview → host）：用户确认 S2 后通知宿主开始下载。
- `desktopUpdateRestart`（webview → host）：用户在 S4/S5 选择立即重启后通知宿主安装并重启。
- **实现状态（2026-09-03 裁决后已完成）**：webview 落地 S0–S6 状态机并调用上述两个命令；宿主（desktopHost.ts）把 electron-updater 事件映射为 `update.status` 随 `desktopAccountInfo` 推送、响应两命令；toast 更新链路已删除（`autoDownload=false`，下载仅在 S2 确认后启动；revert 前的 24d47cd5 宿主为「自动后台下载 + toast 提醒重启」）。降级边界见 [desktop-shell.md](./desktop-shell.md)「桌面端自动更新」故事场景 5（已同步改写）。

## 用户场景与测试 _（必填）_

### 用户故事：账户卡片 · 用量常驻区（套餐用量与 API 余额展示与明细气泡）（优先级：P1）

作为桌面端用户，我希望登录后账户卡片上部**常驻**展示用量信息（套餐进度条与 API 余额一行，明细与预警收进 hover ⓘ 气泡），以便随时了解账户用量与额度状态而不必点击任何入口。

**为什么是这个优先级**：账户卡片是桌面端侧边栏核心运营入口；v3/v3.1 将用量从「点击浮层」升级为「常驻可见」，是交互定稿的核心变化（P1）；hover 明细气泡是其中唯一的明细载体。

**独立测试**：desktop 登录态下发含 plan/apiQuota 的 `desktopAccountInfo`，验证常驻区渲染套餐 80% 进度条与 API 余额「¥8,846.86」+ ⓘ；hover ⓘ 弹明细气泡、移出自动收起、点击金额文本不触发；切换低余量/耗尽/不限额数据验证四态行内展示与气泡内容。

**验收场景**：

1. **假设**用户已登录且宿主下发了 plan 数据（余量 > 0%），**当**查看账户卡片，**则**用量常驻区显示「套餐用量」标签 + 蓝色进度条 + 余量百分比（按 `1 − used/(monthlyQuota×months)` 计算并 round、下限 0）；进度条带 `progressbar` role，`aria-valuenow` = 余量百分比。
2. **假设**套餐余量已用完（`used ≥ planTotal`），**当**查看套餐用量块，**则**进度条空、百分比显示红色 0%（不得显示负数），其下显示红色提示「套餐余量已用完，请联系销售人员充值」。
3. **假设**宿主未配置套餐（未下发 `plan` 字段），**当**查看账户卡片，**则**不渲染套餐用量块（进度条/标签/百分比均无）。
4. **假设**宿主下发了 `apiQuota`（限额数字、余额充足：剩余 ≥ 限额 20%），**当**查看 API 余额行，**则**行内展示标签「API 余额」+ 金额「¥N」（正常色）+ ⓘ；金额格式 = ¥ 前缀 + 两位小数 + 千位分隔；金额**不带「剩余」前缀**（label 已含「余额」语义），随账户消息实时刷新。
5. **假设**API 余额不足（剩余 < 限额 20% 且 > 0），**当**查看 API 余额行，**则**金额以预警色（琥珀，zip 参考 #d18616，最终色值以当前主题变量/视觉代码为准）展示，行内其余元素不变色。
6. **假设**API 余额用完（剩余 ≤ 0），**当**查看 API 余额行，**则**行内以错误警示色（主题变量，如 `--vscode-errorForeground`）显示「已用完」。
7. **假设**API 不限额（`apiQuota.limit = null`），**当**查看 API 余额行，**则**行内显示「不限额」（正常色）+ ⓘ，不显示金额。
8. **假设**API 余额行内容放得下，**当**查看其布局，**则**标签与「金额+ⓘ」同行；容器放不下时金额组**整体换行到下一行**（完整一行不拆两段、不溢出卡片、右对齐），不得把金额与 ⓘ 拆散。
9. **假设**用户 hover 或键盘 Tab 聚焦 API 余额行的 ⓘ 图标（`data-testid="api-quota-info"`，独立按钮，`aria-label="API 余额明细"`），**当**气泡弹出，**则**气泡标题「API 余额」+ 两行「已用 ¥n / 剩余 ¥N」，金额右对齐且等宽数字（便于比较）；气泡贴着「API 余额」行顶向上弹出（间距约 4px），宽度与卡片等宽，盖住上方套餐用量区。
10. **假设**API 不限额，**当**hover ⓘ 弹出气泡，**则**气泡两行显示「已用 ¥n」（本人累计）与剩余行「不限额」。
11. **假设**API 余额不足（剩余 < 限额 20%），**当**hover ⓘ 弹出气泡，**则**气泡内附加琥珀色提示「余额不足20%，建议及时充值」。
12. **假设**API 余额用完，**当**hover ⓘ 弹出气泡，**则**气泡内剩余金额红字 ¥0.00 + 红色提示「额度已用完，请联系管理员充值」。
13. **假设**气泡已展开，**当**鼠标移出 ⓘ 图标与气泡区域约 150ms，**则**气泡自动收起（防图标↔气泡间移动闪烁）；按 `Esc` 或点击其他区域则立即强制收起。
14. **假设**用户点击 API 余额行的**金额文本**，**当**点击发生，**则**不触发气泡（金额区域非热区，仅 ⓘ 为热区），也不触发其他行为。
15. **假设**宿主下发 `plan` 与 `apiQuota` 均为空/未下发，**当**查看账户卡片，**则**用量常驻区整体不渲染，个人信息行右侧也不显示用量显隐按钮。

### 用户故事：账户卡片 · 用量常驻区收起/展开（优先级：P2）

作为桌面端用户，我希望用量常驻区可以收起/展开，且显隐状态独立记忆、不受个人信息菜单开合影响，以便在只想看账户身份时把卡片收成一行。

**为什么是这个优先级**：空间收纳是常驻区的辅助能力，先保证常驻展示正确（P1 故事）后再谈收起；对密集使用多会话/远程主机的用户有用。

**独立测试**：登录态点显隐按钮收起用量区，验证按钮 icon 变仪表盘；再点展开恢复；收起状态下打开/关闭个人信息菜单验证用量区显隐不受影响；`plan`+`apiQuota` 均未下发时验证显隐按钮不渲染。

**验收场景**：

1. **假设**用量常驻区展开，**当**点击个人信息行右侧显隐按钮（icon：chevron-up，`aria-label="收起用量"`），**则**用量常驻区收起，卡片仅剩个人信息一行，按钮 icon 变为仪表盘（dashboard，`aria-label="展开用量"`）。
2. **假设**用量常驻区已收起，**当**再次点击显隐按钮，**则**用量常驻区展开恢复收起前的展示，按钮 icon 恢复为 chevron-up。
3. **假设**用量常驻区收起/展开状态确定，**当**打开或关闭个人信息菜单、切换会话、账户数据刷新，**则**显隐状态保持不变（独立记忆，不被菜单开合联动）。
4. **假设**用量区展开且个人信息菜单打开，**当**点击显隐按钮收起用量区，**则**仅收起用量区，个人信息菜单保持打开状态不受影响（显隐与菜单解耦）。

### 用户故事：账户卡片 · 个人信息行与纯功能菜单（优先级：P1）

作为桌面端用户，我希望点击头像/姓名热区弹出**纯功能菜单**（设置/企业控制台/帮助文档/退出登录），菜单贴着个人信息行向上弹出、与卡片等宽，再次点击热区或失焦/Esc 可收起，以便操作账户相关功能且不被用量信息干扰。

**为什么是这个优先级**：这是 24d47cd5/zip v3 对既有「更多按钮 + 用量浮层」双入口的**结构性替换**（已登录不再有独立「…」更多按钮），是重新实现的核心差异，必须最先明确（P1）。

**独立测试**：登录态验证热区点击开/关菜单、菜单含 4 项且无用量块、贴行弹出盖住用量区、与卡片等宽（右缘对齐）；点击外部与 Esc 收起；方向键/Enter/Space 键盘操作；未登录态验证整条登录按钮 + 更多按钮仍保留；远程主机标注。

**验收场景**：

### 用户故事：右侧面板 · 一级 Tab 栏与实例语义（优先级：P1）

作为桌面端用户，我希望右侧面板采用浏览器式一级 Tab 栏：每个打开的实例对应一个 tab，preview 可同时开多个（每次从链接/「＋」打开都新增一个），而计划/差异/终端/文件面板同一时刻至多一个实例（重复打开时激活已有 tab 而非新建），以便同时对照多个预览页面，又不让面板类型重复堆积。

**为什么是这个优先级**：这是 24d47cd5 面板改造的骨架语义。注意 zip 交付说明 §3 文字曾写「preview/diff/file 多实例」，但**合并实现已窄化为仅 preview 多实例**（`tryOpenPanel`：preview → `addTab`，其余 → `ensureUniqueTab`；文件面板另走路径切换复用），tests 与代码注释均以「仅 preview 多实例」为准——本故事以**合并实现语义**为准，作为重新实现目标。

**独立测试**：preview 连续从两条消息 localhost 链接打开验证新增两个 tab 且各自独立加载、tab 标签用页面标题；plan/diff/terminal/file 重复打开验证激活已有 tab 不新增；点击 tab 切换；关闭激活 tab 落到左侧邻居；关闭最后一个 tab 显示空态引导（可立即换开其它面板）；键盘 ←/→ 在 tab 间移动；tab 溢出可横向滚动；tab 标签不显示文件路径/文件名细节。

**验收场景**：

1. **假设**本地会话中点击消息中的 localhost 链接，**当**预览面板打开，**则**每次点击都在 tab 栏**新增**一个 preview tab（`data-panel-tab`）并激活，新页面在槽位加载；再次点击同一链接或不同链接均新增（多实例语义），不覆盖既有 tab。
2. **假设**远程会话中点击 localhost 链接，**当**预览面板打开，**则**若该链接的规范化 URL（同一 origin/路径、任意回环主机拼写）已有建立隧道的 preview tab 且隧道无错误，则激活该既有 tab、不新建（隧道复用、不重建）；路径/来源不同或隧道失败则新增 tab。
3. **假设**preview tab 打开中，**当**查看 tab 标签，**则**显示 guest 页面标题（页面 title 更新事件驱动），无标题时回退「host+path」，空地址回退「新预览」；不显示完整 URL。
4. **假设**用户通过「＋」菜单/空态入口/面板头菜单打开 plan/diff/terminal/file，**当**该类面板已有打开实例，**则**只激活既有 tab（`ensureUniqueTab`），不新增重复实例；无实例时才新建。
5. **假设**消息中出现文件路径点击（desktop 宿主），**当**文件面板未打开，**则**新增唯一 file tab 并立即显示 loading 桩，宿主读取后回填内容（`desktopFileContent` 链路）。
6. **假设**file tab 已打开且显示文件 A，**当**点击另一条消息的文件 B 路径，**则**激活既有 file tab（不新建），切换其路径为 B 并软刷新（旧内容保留至宿主回复落地）；再次点击当前文件路径则重新读取刷新。
7. **假设**file tab 存在，**当**查看一级 tab 栏标签，**则**file tab 标签只显示面板名「文件」——**不泄露具体文件名**（文件名只在 FilePane 次级工具栏展示）。
8. **假设**存在多个 tab，**当**点击某个 tab，**则**切换激活并展示对应面板内容；被切换走的 tab 保持挂载（`display:none`），其 preview guest / 终端 PTY / 文件内容不销毁。
9. **假设**存在多个 tab，**当**关闭非激活 tab，**则**仅移除该实例（browser-tab 语义：实例销毁，重开是全新实例）；关闭激活 tab 时激活其**左侧相邻** tab。
10. **假设**用户关闭最后一个 tab，**当**关闭完成，**则**右侧面板保持展开并显示空态引导（可直接点击入口换开其它面板类型）；preview 全屏状态同时退出；面板整体收起仅由头部按钮触发。
11. **假设**tab 栏存在，**当**按 `←`/`→` 方向键，**则**焦点在 tab 间循环移动（roving tabindex，Enter/Space 激活）；tab 栏聚焦时不与其它快捷键冲突。
12. **假设**tab 总宽超出槽位宽度，**当**查看 tab 栏，**则**可横向滚动浏览全部 tab（「＋」按钮粘在可视右缘）；新增 tab 后滚动到新 tab 可见。
13. **假设**preview tab 处于激活且用户点击 tab 栏全屏按钮，**当**进入全屏，**则**右侧面板占满内容区、聊天列隐藏；再次点击或按 Esc 退出全屏恢复（全屏语义见 [desktop-preview.md](./desktop-preview.md)「预览面板全屏」，本故事只规定全屏按钮位于 tab 栏右端、作用于整个槽位）。
14. **假设**某会话的 preview tab 内曾通过**地址栏手动输入** URL 或 guest **页面内导航**到达新地址，**当**切换到其它会话再切回该会话（或该 tab 所在面板分屏移动重建），**则**预览必须恢复该会话最后实际浏览的地址并自动加载——地址栏输入与页内跳转后的地址与链接打开/转发回复的地址同级持久（随会话面板记忆保存，含 preview 空 tab 首次手动输入的场景），不得回到最初请求的 URL、清空或显示空白，避免用户每次切回都要重新输入。

6. **假设**欢迎页（新对话空态）显示且用户打开面板，**当**查看布局，**则**聊天主列与右侧面板在同一行内正常分配（主列 `flex:1; min-width:0`），欢迎内容不左偏/不溢出、输入卡不被面板盖住（既有欢迎页与面板并存的布局语义，PR #2018 修复后保持不回归）。
7. **假设**某会话的面板槽位从未被手动拖宽过（[desktop-panels.md](./desktop-panels.md)「面板自动铺满剩余空间」语义，2026-09-03 拍板适配单槽位模型），**当**用户展开面板（从收起态/空态展开，或打开任意新 tab），**则**槽位宽度自动设为「容器宽 − 对话列最小宽度（360px）」，铺满消息列之外的剩余空间，不再停留 420px 固定默认宽度。
8. **假设**槽位宽度曾自动铺满或处于默认宽度，**当**用户手动拖拽槽位边缘调整宽度，**则**该会话转为「手动宽度」：此后折叠再展开、关闭再打开、加新 tab、窗口尺寸变化，均不再自动铺满，保持用户设定宽度（钳制范围 [320, 容器 − 360] 不变，随会话记忆保留见场景 5）；应用重启后随「面板宽度不跨重启」规则回到自动铺满默认行为。
9. **假设**从未手动拖宽过的会话所在窗口尺寸变化，**当**再次展开或打开面板，**则**按当前可用空间重新铺满（跟随窗口实时剩余空间）；已手动拖宽的会话不受影响。

### 用户故事：文件面板 · tab 内主动搜索入口（优先级：P2）

作为桌面端用户，我希望唯一 file tab 内提供**主动打开文件**的搜索入口（输入文件名片段 → 建议下拉 → 选中即在 file tab 打开），以便不依赖消息中的文件路径也能查看任意工作区文件。

**为什么是这个优先级**：文件面板「搜索→打开」数据流与语义已由 [desktop-file-panel.md](./desktop-file-panel.md)「文件面板文件搜索」故事定义（`requestFileSuggestions` → `fileSuggestionsResponse`，锚定会话根目录，本地/远端通用）；本文档只规定其在 file-tab 模型下的载体语义。zip/24d47cd5 曾把入口 UI 从「面板顶部常驻搜索行」改为「工具栏搜索触发器 + 浮层」，**视觉以当前代码为准**——重新实现时沿用当前 main 的搜索 UI 基线（常驻搜索行），把 v3 浮层形态作为可选演进另行评审，不作为本规格验收项。

**独立测试**：在 file tab 未打开任何文件（占位态）与已打开文件两种状态下使用搜索入口，验证建议下拉、键盘/点击选中打开（走 file tab 路径切换软刷新语义）、Esc/失焦关闭、无结果空态、远端会话打开远端文件。

**验收场景**：

1. **假设**file tab 处于占位态（尚未打开任何文件），**当**用户使用面板搜索入口输入文件名片段，**则**按 [desktop-file-panel.md](./desktop-file-panel.md)「文件面板文件搜索」既有语义请求建议并展示匹配文件（目录项不展示），选中后在**该 file tab** 中打开文件（激活 file tab、先 loading 后回填）。
2. **假设**file tab 已显示文件 A，**当**用户在搜索入口选中文件 B，**则**在既有 file tab 中切换为 B（路径切换软刷新语义，不新增第二个 file tab）。
3. **假设**建议下拉已展示，**当**按 ↓/↑ + Enter 或点击建议项，**则**打开对应文件并复位搜索状态；按 Esc 或点击外部则下拉关闭、搜索状态复位；无匹配时显示「未找到匹配的文件」空态。
4. **假设**处于远端主机会话，**当**在 file tab 搜索并选中文件，**则**从该远端主机读取并展示（与既有远端 file 面板语义一致，搜索建议锚定该会话工作目录）。
5. **假设**分屏中存在多个会话各自有 file tab，**当**某一分屏内搜索，**则**请求/响应按各自会话锚定与隔离，broadcast 响应不串扰（与 [desktop-file-panel.md](./desktop-file-panel.md) 既有隔离语义一致）。

## 边界与异常态（对应 zip §6 + 面板差异）

1. **未登录**：账户卡片仅登录按钮 + 更多按钮；无用量区、无个人信息行、无更新提示（用量区不渲染时显隐按钮也不显示）。
2. **未配置套餐 / 均未下发**：套餐块不渲染；`plan` 与 `apiQuota` 均未下发时用量区整体不渲染。
3. **余量 0% / 超限**：0% 封底（不显示负数），红色警示 + 充值引导。
4. **API 余额**：行内默认仅余额金额或状态短词，明细/预警收进 ⓘ 气泡；剩余 < 限额 20% 金额预警色；剩余 ≤ 0 显示「已用完」错误色；`limit = null` 显示「不限额」。
5. **下载中**：更新按钮 disabled，点击无反应。
6. **对话框**：S2 仅 Esc 关闭；S4 稍后后可再次弹确认；均不自动关闭/不自动重启。
7. **远程主机**：个人信息菜单「设置 / 退出登录」标注主机名；用量与登录态跟随聚焦分屏所属主机（沿用既有账户卡片跟随语义）。
8. **用量轮询失败**：保留上次成功显示。
9. **面板空间不足**：拒绝开启 + 轻量提示，不关闭既有任何 tab（tab 化后无「自动替换旧面板」语义——该旧语义属于已废弃的多选并排模型，见文末冲突表）。
10. **preview 唯一实例边界**：`planContent` 路由（ExitPlanMode）打开 plan tab 时走唯一实例语义（已有则激活并更新内容）。
11. **面板关闭销毁**：关闭 tab 即销毁该实例（preview guest / 终端 PTY 不保留；关闭最后一个 tab 后空态接管、面板保持展开）；折叠（头部按钮）才隐藏槽位并保留全部实例。
