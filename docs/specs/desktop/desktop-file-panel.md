# 功能规格说明：桌面端文件面板

> 本面板为「源码/文本」视图：`.html`/`.htm` 路径的点击在桌面端**优先**进入预览面板渲染（见 [desktop-preview.md](./desktop-preview.md)「本地 HTML 文件预览」），该预览失败时回退本面板；本面板自身不因该故事改变行为。

## 用户场景与测试

### 用户故事：文件面板（优先级：P1）

作为 CodeWave IDE 桌面端用户，我希望点击 read/edit/write 工具中的文件路径时在应用内打开一个文件面板查看文件内容（默认只读，面板内改文件见「文件面板内编辑与保存」），以便无需离开对话即可核对 agent 读写过的文件。远程 SSH 会话是引入该面板的契机——远程路径无法在本地打开（当前会报「打开文件失败」，甚至误打开同名文件）；面板统一承载本地与远程的文件查看，本地会话额外提供「在默认应用中打开」以便跳出到外部编辑器。

**为什么是这个优先级**：远程会话点击工具路径当前会在本地尝试打开而报「打开文件失败」，是远程会话体验的直接缺陷；文件面板补齐该缺口，并统一本地/远程的文件查看入口。

**独立测试**：远程会话中点击 read 工具路径，验证 file 面板从远端读取并展示内容（行号、长行水平滚动、代码高亮）；本地会话点击同一路径验证 file 面板从本地读取并展示，且「在默认应用中打开」按钮可用；点击另一条消息的路径验证在该 file tab 内新增/激活对应的文件标签并显示；通过空态入口/「＋」菜单/菜单栏「面板 → 文件」打开 file tab（未加载文件时显示占位），菜单栏项再次触发即关闭；点击含 `.` / `..` 段的相对路径，验证按规范绝对路径读取、回填路径与面板标题均无冗余 `..` 残留。

**验收场景**：

1. **假设**用户处于远程主机会话（host 非 local），**当**点击 read 工具的文件路径，**则**在右上角打开 file 面板，从远端读取该文件并显示内容，且不得出现「打开文件失败」系统消息。
2. **假设**用户处于本地主机会话，**当**点击 read 工具的文件路径，**则**在右上角打开 file 面板，从本地读取该文件并显示内容。
3. **假设**用户处于任意主机会话，**当**点击 edit/write 工具的文件路径，**则** file 面板展示该文件的内容（edit 展示新版本）。
4. **假设**用户处于任意主机会话，**当**点击带起止行信息的文件提及/ContextTag，**则** file 面板打开后滚动定位到对应行区间。
5. **假设**本地 file 面板已打开，**当**点击标题栏的「在默认应用中打开」按钮，**则**通过系统默认应用打开该本地文件（远程会话隐藏该按钮）。
6. **假设**file 面板已打开并显示文件 A，**当**用户点击另一条消息的文件 B 路径，**则**在该 file tab 内按「文件面板已打开文件的标签」打开 B（新增文件标签或激活已打开的同名标签），A 的标签保留；面板保持原位（不得因再次点击而移动行/位置）。
7. **假设**file 面板已打开，**当**再次点击当前已显示文件的路径，**则**重新读取并刷新内容。
8. **假设**file 面板已打开，**当**点击标题栏的复制按钮，**则**将完整文件路径（远程为远端路径）复制到剪贴板。
9. **假设**file 面板已打开，**当**用户关闭 file tab，**则**该文件查看视图关闭，不残留读取进程或端口转发资源；折叠（头部按钮）仅隐藏槽位并保留 tab（见 [desktop-right-panel.md](./desktop-right-panel.md)「右侧面板 · 展开/折叠、空间守卫与欢迎页共存」）。
10. **假设**分屏中有多个会话，**当**切换分屏焦点，**则**各分屏的 file 面板打开状态与文件内容相互独立（复用面板组按会话隔离规则）。
11. **假设**file 面板宽度较窄，**当**文件行超出面板宽度，**则**内容水平滚动而非折行，行号列固定不随水平滚动。
12. **假设**打开的是 markdown 文件，**当**面板加载完成，**则**按渲染后的 markdown 展示（复用现有 marked 渲染管线），而非纯文本。
13. **假设**打开的是代码文件，**当**面板加载完成，**则**按扩展名匹配进行轻量语法高亮；未知扩展名回退纯文本。
14. **假设**文件过大或为二进制，**当**面板读取该文件，**则**截断/拒读并给出提示，不得阻塞渲染或乱码展示。
15. **假设**打开的是图片（本地或远端，如 `previewImage`），**当**面板加载完成，**则**在面板内联展示图片预览（渲染后的图片，而非 base64 文本或裂图）。
16. **假设**文件不存在或不可读（远端或本地），**当**面板读取失败，**则**在面板内显示错误提示，不弹「打开文件失败」系统消息。
17. **假设**用户通过空态入口/「＋」菜单打开 file tab（file 为唯一实例入口，open-or-activate：已有 file tab 只激活不新建），**当**file tab 已打开但尚未加载任何文件且当前对话没有文件，**则**显示「点击消息中的文件路径查看」占位；对话中已有文件时改为展示文件清单（见「文件面板列出当前对话的文件」）。
18. **假设**file 面板已打开或未打开，**当**用户点击菜单栏「面板 → 文件」菜单项，**则**按 [desktop-right-panel.md](./desktop-right-panel.md)「边界情况 · 菜单栏『面板』项与快捷键」的开/关切换语义处理：无 file tab 时打开/激活唯一 file tab（未加载过文件时显示文件清单或占位提示），已有 file tab 时关闭；行为与预览/差异/终端面板菜单项一致。文件面板不设快捷键（与 Claude Code Desktop 一致，且 `Ctrl+Shift+F` 与 Windows 输入法简繁切换冲突）。
19. **假设**远端主机的 MIME 类型识别不可用（如缺少 `file` 命令或版本不支持常用探测参数），**当**面板打开扩展名为常见图片格式（png/jpg/jpeg/gif/webp/bmp/ico/svg）的远端文件，**则**仍按扩展名识别为图片并内联展示，不得误报「二进制文件无法在面板中显示」。
20. **假设**file 面板内联展示图片（本地或远端，含消息中的图片），**当**右键点击图片并选择「复制图片」，**则**图片被复制到系统剪贴板，可在其他应用或聊天输入框直接粘贴。
21. **假设**打开请求携带的路径含 `.` / `..` 段（如消息中 `` `../sibling-repo/src/a.ts` `` 按会话 workdir 归并后），**当**面板读取并回填，**则**宿主按**规范绝对路径**（折叠 `.` 与 `..`、无残留冗余段）读取，且回填给面板的 `fileView.path` 同为规范路径——面板标题显示规范路径（而非 `…/proj/../sibling-repo/src/a.ts` 这类含 `..` 的串），复制路径、标题相对化、自动刷新比对均基于该规范路径；本地与远端会话行为一致，路径不存在时仍按场景 16 在面板内提示错误。归一化为纯词法折叠，不解析符号链接。

### 用户故事：文件面板列出当前对话的文件（优先级：P1）

作为 CodeWave IDE 桌面端用户，我希望打开文件面板时先看到这次对话读写过哪些文件，以便不必翻回消息流去找文件路径——在对话场景下打开文件面板，意图大概率就是看这次对话里的文件。

**为什么是这个优先级**：面板原先只能靠点击消息里的路径打开文件，主动打开是一个空面板。清单直接从消息流派生（成功的 read/write/edit 工具调用），不新增宿主协议，因此对本地与远端会话同样成立；点开仍在同一个 file tab 内，交互与点消息里的路径一致。

**独立测试**：在一个读写过若干文件的对话中通过「＋」菜单打开 file tab，验证正文列出这些文件、最近的在前、点任一行即在面板中打开；点工具条「返回文件列表」回到清单；再点同一文件仍切回文件内容；在一个还没读写过文件的对话中打开 file tab，验证仍是占位提示；让 agent 读写一个新文件，验证它出现在清单最前。

**验收场景**：

1. **假设**当前对话还没有任何成功的文件读写、也还没打开过文件，**当**用户打开 file tab，**则**正文显示空态提示「打开的文件会显示在这里」（面板为空），不出现空清单与清单标题；空态文案与引导见「文件面板已打开文件的标签」场景 14。
2. **假设**当前对话已成功 read/write/edit 过文件，**当**用户通过「＋」菜单、菜单栏「面板 → 文件」或空态入口打开 file tab，**则**正文直接列出这些文件（一行一个、只显示文件名，最近的在前），不再显示占位提示。
3. **假设**清单已展示，**当**用户点击某一行，**则**在同一个 file tab 内打开该文件的内层文件标签（与点击消息里的文件路径同一套语义：`.html` 进预览面板、其余进源码/文本视图，先显示加载中）。
4. **假设**file 面板正在显示某个文件且当前对话有文件清单，**当**用户点击工具条上的「返回文件列表」，**则**正文回到清单、工具条回到「文件」标题；此时若之前那次读取的回复还在路上，落下来也不得把视图从清单拽回文件。
5. **假设**用户从清单退回到文件清单后再点开**同一个**文件，**则**仍正常切回该文件内容（列表态由独立的视图标志表示，不靠「没有已打开文件」来推导，也不清空已打开的文件标签）。
6. **假设**同一个文件在对话中被多次读取或改写，**当**清单展示，**则**该文件只占一行，位置取最近一次命中；文件名保持最近一次调用的写法。
7. **假设**工具的调用仍在执行中（streaming/running）或已失败，**当**清单展示，**则**该文件不出现在清单里（清单只反映已成功落地的读写）。
8. **假设**两个不同目录下的文件同名，**当**清单展示，**则**这两行改用相对路径显示以区分，其余唯一文件名仍显示文件名；每行悬浮提示给完整相对路径。
9. **假设**清单里没有用户想看的文件，**当**用户使用目录树顶部的过滤框，**则**按「文件面板按名字查找」在工作区内查找并打开文件——清单不承担跨目录浏览的职责。
10. **假设**对话中发布了创作集（artifact），**当**清单展示，**则**不列出该 artifact：artifact 是服务端 URL，本机没有对应文件；发布它的本地源文件若被 read/write/edit 过，仍作为普通文件出现。
11. **假设**清单已展示，**当**agent 在对话中成功读写一个新文件，**则**该文件出现在清单最前，无需关闭再打开面板。
12. **假设**用户切换到另一个会话（或分屏中的另一个 pane），**当**其 file tab 展示清单，**则**清单按该会话自己的消息派生，不残留上一个会话的文件。
13. **假设**处于远端主机会话，**当**清单展示并点开某行，**则**列出与本地同样成立，文件按远端读取与展示（清单本身是前端从消息流派生，不依赖本地文件系统）。

### 用户故事：文件面板自动刷新（优先级：P1）

作为 CodeWave IDE 桌面端用户，我希望 agent 对面板当前显示的文件执行 write/edit 工具且成功后，面板自动重新读取该文件并展示最新内容，以便在 agent 修改文件后无需手动再次点击路径即可核对最新结果。

**为什么是这个优先级**：agent 修改文件是高频操作；若面板停留在旧内容，用户核对时会误以为修改未生效，反复手动点击路径既打断流程也容易遗漏。自动刷新让「工具完成 → 面板即最新」无需额外操作，与 diff 面板的已读/最新语义一致。

**独立测试**：打开 file 面板显示文件 A → 在对话中让 agent 对文件 A 执行 write/edit 并成功 → 面板自动更新为最新内容且不滚动跳位；agent 对文件 B 执行 write/edit 或对文件 A 执行失败 → 面板保持不变；以含 `../` 的相对路径打开文件 A 后触发 write/edit，验证仍能自动刷新。

**验收场景**：

1. **假设**file 面板已打开显示文件 A，**当**agent 对文件 A 执行 write 工具且成功完成，**则**面板自动重新读取文件 A 并展示最新内容，用户无需再次点击路径。
2. **假设**file 面板已打开显示文件 A，**当**agent 对文件 A 执行 edit 工具且成功完成（含同一文件多次 edit），**则**面板自动刷新为最新内容。
3. **假设**file 面板已打开显示文件 A，**当**agent 对文件 B（非当前显示文件）执行 write/edit 并成功，**则**面板保持文件 A 不变，不因其他文件的写操作而刷新。
4. **假设**file 面板已打开显示文件 A，**当**agent 对文件 A 的 write/edit 执行失败或被权限拒绝，**则**面板不刷新，保持失败前的内容。
5. **假设**file 面板已打开显示文件 A，**当**write/edit 工具仍在执行中（streaming/running 阶段），**则**面板不提前刷新，仅在工具完成（end）后刷新一次。
6. **假设**file 面板已打开显示文件 A 且自动刷新触发，**当**刷新完成，**则**面板内容替换为最新内容，滚动位置不产生明显跳动（软刷新语义，与再次点击同一路径一致）。
7. **假设**用户通过含 `.` / `..` 段的路径打开文件 A（如 `` `../sibling-repo/src/a.ts` ``），**当** agent 随后对同一文件 A 执行 write/edit 并成功，**则**面板照常自动刷新：面板的打开路径与工具的`displayPath`/绝对路径都按同一套规范折叠（工具侧已由 `path.resolve` 归一）后可比对命中，不得因一侧是 `…/proj/../sibling-repo/src/a.ts`、另一侧是 `…/sibling-repo/src/a.ts` 而比对失败导致不刷新。

### 用户故事：文件面板按名字查找（目录树的过滤框，优先级：P2）

作为 CodeWave IDE 桌面端用户，我希望在目录树顶部的输入框里打几个字就能把工作区里匹配的文件列出来、点一条即打开，以便不必沿着目录一层层展开去找。过滤走输入框 `@` 文件搜索的既有数据流（`requestFileSuggestions` → `fileSuggestionsResponse`），范围与 `@` 一致（锚定会话工作根，本地与远端通用），并同样排除依赖与构建产物目录（`node_modules`、`dist`、`.next` 等，按目录名判定），与目录树、差异面板同一口径——因为它覆盖整个工作区、不依赖树展开到哪一层，所以它同时承担「按名字打开任意文件」的职责，面板里只保留这一个查找入口。

**为什么是这个优先级**：有了目录树之后，「按名字找文件」若还留着独立的搜索弹层就是两条并行路径；把过滤放进树顶部，输入一次同时满足「浏览时快速定位」和「知道名字直接打开」。数据流与去重逻辑均已存在可复用，宿主零改动，改动集中在共享 webview 侧；`@` 提及继续用同一数据流与原来的建议下拉组件，行为不变。

**独立测试**：打开 file tab（目录树已展示），在树顶部输入框打文件名片段，验证树区域切换为匹配结果列表、点击与键盘选中后打开该文件、清空输入后目录树恢复且展开状态不变；输入无匹配片段验证「未找到匹配的文件」；隐藏文件树后再显示验证过滤框随之回来；回归输入框 `@` 文件搜索验证行为不变。

**验收场景**：

1. **假设**file 面板已打开且目录树已展示，**当**用户查看目录树顶部，**则**有一个过滤输入框（占位提示「筛选文件…」，本产品不做文件内容搜索故不带 `?` 前缀说明），空输入时下方仍是正常目录树。
2. **假设**用户在过滤框输入至少 1 个字符，**当**停止输入约 200ms，**则**发送 `requestFileSuggestions` 请求，树区域切换为匹配文件的结果列表（目录项不展示——目录走树浏览），每项显示文件名与其所在相对目录，同名文件可区分。
3. **假设**过滤框已有输入，**当**用户清空内容或按 Esc，**则**结果列表消失、目录树恢复，且恢复的是过滤前的展开状态（不重置为全部折叠）。
4. **假设**结果列表已展示，**当**按 ↓/↑ 移动选中项并按 Enter 确认，**则**在面板中打开该文件（按「文件面板已打开文件的标签」新增或激活文件标签，先显示加载中、带行定位），过滤框清空、区域回到目录树。
5. **假设**结果列表已展示，**当**点击某个结果项，**则**等效于键盘 Enter 选中（打开文件并清空过滤）。
6. **假设**搜索请求尚未返回，**当**用户继续输入，**则**过期请求的响应被忽略（按 requestId 去重），仅最新关键字的结果生效，不出现结果闪烁覆盖。
7. **假设**输入的关键字无匹配，**当**结果区域展示，**则**显示「未找到匹配的文件」空态提示，过滤框保持可编辑。
8. **假设**处于远端主机会话，**当**在过滤框选中远端文件，**则**面板从该远端主机读取并展示文件内容（打开请求携带会话对应的 host，路径为远端路径）。
9. **假设**分屏中存在多个会话，**当**在某一分屏的面板中过滤，**则**结果锚定该分屏所属会话的工作目录；各分屏面板的过滤状态相互独立，broadcast 响应按各自 requestId 隔离，不串扰。

### 用户故事：文件面板内编辑与保存（优先级：P1）

作为 CodeWave IDE 桌面端用户，我希望在文件面板里直接修改并保存本地会话的文件，以便改一行配置、改一句文案这类小事不必跳出到编辑器、再回到对话里让 agent 代改——面板先把文件「看」全了，接着就该能「改」。对齐 Claude 桌面端 Code 标签页的文件查看器：查看器本身可编辑，保存按内容哈希做乐观并发校验，磁盘上的文件被别人改过时拒绝覆盖，把「覆盖 / 重新加载」交给用户。

**为什么是这个优先级**：面板目前只读，用户改一个文件的成本是「切到外部编辑器 → 找到路径 → 改 → 回来」，或者「发一条消息让 agent 改 → 等一轮工具调用」；前者打断对话上下文，后者把一次人工改动写成对话历史。本故事复用既有读取链路（`openFile` → `desktopFileContent`）加一条写回链路即可闭合，不引入新的目录浏览能力。

**独立测试**：本地会话打开一个工作目录内的 `.ts` 文件 → 点「编辑」→ 改内容 → Cmd/Ctrl+S 保存 → 验证正文回到只读且为新内容、磁盘文件确已修改；再次进入编辑改内容后点「取消」→ 验证弹「放弃未保存的修改？」、选「继续编辑」草稿还在、选「放弃」回到磁盘内容；编辑中点击另一条消息的文件路径 → 验证先被确认框拦下；编辑中让 agent 对该文件执行 edit 并成功 → 验证草稿不被自动刷新覆盖、保存时提示冲突并可选择覆盖或重新加载；远端会话与工作目录外的文件 → 验证没有编辑入口。

**验收场景**：

1. **假设**当前分屏处于**本地**会话、面板显示的文件位于该会话工作目录内、且内容为完整的文本（未被截断、非二进制、非图片），**当**用户点击工具条的「编辑」按钮，**则**面板进入编辑态：正文变为可编辑的文本区（保留等宽字体与行号），工具条右端换成「取消」与「保存」，焦点进入正文，用户可直接修改内容。
2. **假设**文件不满足场景 1 的条件（远端 SSH 会话、路径在工作目录之外、内容被截断、二进制、图片、读取失败、空内容），**当**用户查看工具条，**则**不出现「编辑」按钮，面板保持只读——编辑不为这些文件开特例，也不给「改了却存不回去」的入口。
3. **假设**面板处于只读态，**当**用户点击或双击正文，**则**不得进入编辑：进入编辑是显式动作（工具条按钮），避免误触把浏览态变成草稿态。
4. **假设**面板处于编辑态且内容已被修改，**当**用户点击「保存」或按 Cmd/Ctrl+S，**则**把当前草稿写回该文件：成功后退出编辑态、正文回到只读形态并展示刚写入的内容（高亮与行号照常），并给出一次「已保存」的轻量反馈；内容与磁盘一致（未做修改）时保存直接退出编辑态、不写盘。
5. **假设**面板处于编辑态且有未保存修改，**当**用户点击「取消」，**则**弹出确认（标题「放弃未保存的修改？」，按钮「继续编辑」/「放弃」）：选「继续编辑」回到编辑态且草稿原样保留，选「放弃」丢弃草稿、正文回到磁盘上的当前内容。
6. **假设**面板处于编辑态且有未保存修改，**当**用户试图离开该文件——点击消息里的另一个文件路径、从文件清单或工具条搜索里打开另一个文件、关闭 file tab、切换到另一个会话或分屏、切换工作目录——**则**必须先弹出场景 5 的同一个确认：选「放弃」才执行原操作，选「继续编辑」则什么都不变（既不静默丢弃草稿，也不静默吞掉用户的离开操作）。
7. **假设**面板处于编辑态且磁盘上的该文件已被他人改动（agent 的 write/edit 工具成功、或用户在外部编辑器保存），**当**用户保存，**则**不得覆盖磁盘内容：面板提示「文件已在磁盘上更新」，并给出「覆盖（写入我的版本）」与「重新加载（丢弃我的修改）」两个动作；选覆盖则磁盘变为用户草稿，选重新加载则草稿丢弃、正文为磁盘最新内容。
8. **假设**面板处于编辑态且有未保存修改，**当**agent 对同一文件执行 write/edit 并成功（即触发「文件面板自动刷新」的同一时机），**则**自动刷新不得覆盖草稿、不得把用户踢出编辑态；面板按场景 7 的提示告知文件已在磁盘上更新，由用户决定覆盖或重新加载。
9. **假设**面板处于只读态，**当**agent 对当前显示的文件执行 write/edit 并成功，**则**沿用「文件面板自动刷新」的既有语义自动重读并展示最新内容，行为不变。
10. **假设**用户在编辑态保存，**当**写盘失败（文件不可写、权限不足、目录已被删除、磁盘已满等），**则**面板显示可读的失败原因、草稿完整保留且仍处于编辑态，用户可重试或取消；不得静默丢弃修改，也不得在写盘失败时显示「已保存」。
11. **假设**面板处于只读态且文件是 markdown（当前展示的是渲染结果），**当**用户点击「编辑」，**则**进入 markdown 源文本的编辑，保存成功后回到既有的渲染态并展示最新渲染结果（渲染态本身不可编辑）。
12. **假设**面板处于编辑态，**当**用户查看正文，**则**不提供行评论 / markdown 块评论入口（评论锚定的是只读正文的行区间）；退出编辑态后评论入口按原样恢复。
13. **假设**分屏中有多个分屏/会话，**当**它们分别进入编辑态，**则**各分屏的草稿相互独立：切换分屏焦点、切换一级 tab 不丢草稿、不串台。
14. **假设**用户在面板里保存成功，**则**该写入对 agent 侧等价于外部修改（与用户在外部编辑器保存一致），后续工具调用按既有陈旧性校验处理，不由面板代为保证；面板自己的后续读取按「文件面板自动刷新」与「再次点击同一路径即重读」的既有语义拿到最新内容。
15. **假设**应用重载或退出，**则**不承诺草稿持久化：未保存的修改不跨重载/重启保留，重载后面板回到磁盘内容。

### 用户故事：文件面板已打开文件的标签（优先级：P1）

作为 CodeWave IDE 桌面端用户，我希望文件面板顶部有一条「已打开文件」的标签栏，打开新文件是新增一个标签而不是顶掉当前文件，以便在两个文件之间来回对照（比如改完 A 去核对 B），而不必反复回到清单里点。

**为什么是这个优先级**：现有语义是单文件替换（点另一个路径即顶掉当前文件），一次只能看一个文件；一旦有了目录树，浏览行为会连续打开多个文件，替换语义会让「刚看的那个」随手消失。对齐 Claude 桌面端 Code 标签页：文件在面板内部有独立标签栏（`Open files`），与一级 tab 栏（面板类型维度）分开——**一级 tab 仍然只有唯一一个 file tab，标签只显示面板名「文件」**。

**独立测试**：依次从目录树打开两个文件，验证出现两个标签且都能点回；在一级 tab 栏验证 file tab 仍只有「文件」一个、标签不显示文件名；关闭当前标签验证落到左邻、全部关闭后回到文件清单/占位；打开超过面板宽度的文件数验证标签栏先横向滚动、再收进「更多文件」下拉；同名不同目录的两个文件验证标签用相对路径区分；从消息里点同一文件验证激活既有标签而非新增；右键标签验证「关闭/关闭其他/关闭右侧/全部关闭」；删掉一个已打开的文件验证标签带「已删除」标记；分别验证「一个文件都没打开」与「有标签但未激活」两种空态文案；点击已激活标签验证重读刷新。

**验收场景**：

1. **假设**面板未打开任何文件，**当**用户从目录树、搜索框或消息里的文件路径打开文件 A，**则**面板顶部出现文件标签栏并新增标签 A 并激活，正文显示 A；再次打开文件 B **则**标签栏新增 B（A 的标签保留），不替换 A。
2. **假设**标签栏已有 A，**当**用户再次打开 A（从树、面包屑或消息路径），**则**激活既有标签并重新读取刷新内容，不新增重复标签。
3. **假设**标签栏存在，**当**用户查看一级 tab 栏，**则**一级 tab 仍只有唯一一个 file tab、标签文案仍为「文件」——具体文件名只出现在面板内部的标签栏，不上浮到一级 tab（与 [desktop-right-panel.md](./desktop-right-panel.md)「一级 Tab 栏与实例语义」场景 7 一致）。
4. **假设**标签栏存在，**当**用户查看某个标签，**则**标签由「文件类型图标 + 文件名」组成，目录部分不占据标签宽度（悬浮给完整路径）；同名文件来自不同目录时这两个标签改用各自相对路径区分（其余唯一文件名仍只显示文件名）。
5. **假设**标签栏存在，**当**用户查看标签的可用动作，**则**提供关闭当前、关闭其他、关闭右侧、全部关闭；关闭当前标签后激活其左邻，`Delete`/`Backspace` 关闭当前标签，`Ctrl+Shift+←/→` 左右移动标签。
6. **假设**已打开文件的总宽在面板宽度内放不下，**当**用户查看标签栏，**则**标签栏先横向滚动、新打开的标签自动滚入可视区；仍不足以容纳时，超出可视范围的标签收进标签栏右端的「更多文件」下拉，菜单按顺序列出被收起文件的标签名，点选即激活对应标签。
7. **假设**用户关闭了全部文件标签，**当**关闭完成，**则**面板回到文件清单（对话有文件时）或占位提示（无文件时），一级 file tab 保持打开、不因此关闭面板。
8. **假设**面板处于编辑态且有未保存修改，**当**用户点击另一个文件标签，**则**先按「文件面板内编辑与保存」场景 6 的确认处理，选「继续编辑」则停留在原标签。
9. **假设**面板有多个标签，**当**用户切换标签，**则**每个标签各自保留自己的滚动位置与最近一次的行定位；切换不丢失、不串到其它标签。
10. **假设**分屏中有多个会话，**当**各自打开文件，**则**标签列表按会话隔离，切换分屏焦点不共享标签。
11. **假设**标签栏存在，**当**用户右键某个标签（或点标签上的更多操作），**则**菜单提供「关闭」「关闭其他」「关闭右侧」「全部关闭」，其语义与场景 5 一致。
12. **假设**用户点击**当前已激活**的标签，**当**点击发生，**则**该文件重新读取刷新（相当于再次打开），不清空标签、不切走焦点。
13. **假设**某个已打开文件在磁盘上被删除（用户或 agent 操作），**当**用户查看标签栏与内容区，**则**该标签带「已删除」标记，激活它时内容区提示「文件已不存在」并提供「关闭标签」动作，不静默把标签移除、也不把它当作空内容展示。
14. **假设**面板处于无激活文件的状态，**当**用户查看内容区，**则**按两种空态区分文案——**一个文件都没打开**时提示「打开的文件会显示在这里」并引导「点击左侧目录树中的文件，或点击消息里的文件路径」；**有标签但都没有激活**时提示「未选择文件」并引导「点击上方的文件标签，或点击消息里的文件路径」。

### 用户故事：文件面板内查找与跳行（优先级：P2）

作为 CodeWave IDE 桌面端用户，我希望在面板里按 `Ctrl/Cmd+F` 就地搜索当前文件、按行号直接跳转，以便在大文件里定位，不必为了找一处而跳出到外部编辑器。

**为什么是这个优先级**：面板读的是源码，动辄上千行（截断上限 2000 行）；现在只能靠肉眼滚动或离开面板。对齐 Claude 桌面端文件查看器：查找条支持大小写、整词、正则，带匹配计数与上一个/下一个，另有跳行输入。

**独立测试**：打开一个多行文件，按快捷键打开查找条、输入片段验证计数与高亮、按 Enter/Shift+Enter 在匹配间移动、切换大小写/整词/正则验证结果随之变化、无匹配验证提示；关闭查找条验证高亮清除；输入行号跳转验证滚动定位、越界验证提示；进入编辑态验证同一快捷键在编辑器内可用。

**验收场景**：

1. **假设**面板显示某个文本文件（只读态或编辑态），**当**用户按 `Ctrl/Cmd+F`，**则**就地打开查找条并把焦点放进输入框，不打开新的面板或对话框。
2. **假设**查找条已打开且用户输入关键字，**当**停止输入，**则**显示匹配计数（当前第几个 / 共几个）并高亮全部匹配，当前匹配滚动到可视区；再次按 `Enter` 或点击「下一个」前进、`Shift+Enter` 或「上一个」后退，到末尾时循环。
3. **假设**查找条已打开，**当**用户切换「区分大小写」「整词匹配」「正则表达式」，**则**结果与计数即时更新；正则非法时给出可读提示且不匹配任何内容。
4. **假设**查找条已打开且关键字无匹配，**当**查看查找条，**则**显示「无匹配结果」且计数为 0，不隐藏查找条。
5. **假设**查找条已打开，**当**用户按 `Esc` 或点击关闭，**则**查找条关闭、全部匹配高亮清除、焦点回到正文，滚动位置停留在当前匹配。
6. **假设**面板显示的是 markdown 渲染结果或图片，**当**用户按 `Ctrl/Cmd+F`，**则**沿用渲染/图片视图的既有行为（不把整份文件切回纯文本去找）。
7. **假设**查找条已打开，**当**用户输入行号（纯数字）或「行:列」，**则**滚动定位到该处并高亮该行；输入超出范围时提示有效范围，不移动视图。
8. **假设**文件被截断展示（超过 2000 行）或存在超长行，**当**查找执行，**则**只在已加载的内容内匹配，并在结果区提示「超长行未参与搜索」这类说明，不静默漏报。
9. **假设**面板切换标签或换文件，**当**查找条仍打开，**则**查找条保持打开但对新文件重新计数，高亮不残留到内容之外。
10. **假设**面板处于编辑态，**当**用户使用查找或跳行，**则**编辑态复用编辑器自带的能力，光标与选区随跳转更新，不破坏撤销历史。

### 用户故事：文件面板评论（优先级：P3）

作为用户，我希望在文件面板里用与差异面板完全相同的方式评论：右键某行（或选中若干连续行、点选区末尾浮出的评论按钮）展开输入框写下评论，评论连同文件路径、行号（或行区间）与该处内容一起追加到消息输入框，以便我对一个已存在的文件（不限于本次改动）也能精准指出「要改哪一处」，连续评论多处后统一发给 agent。代码/文本文件按**行 / 行区间**评论；markdown 文件渲染成 HTML 后没有行号，因此按**块**（标题、段落、列表项、引用块、表格单元格、围栏代码块）评论，两者是同一份追加格式、同一套评论框。

**为什么是这个优先级**：把评论从「看改动」扩展到「读文件」——差异面板只能评论本次改动过的行，而用户常常要在长文件里指出问题，那一处并不在本次 diff 中；追加格式与无痕语义沿用差异面板的既有约定，不引入新模型（P3）。入口与 Claude 桌面端的文件查看器一致（右键 `添加评论` + 选中浮出的按钮）：行号列因此不必为评论按钮预留常驻槽位，行号贴左缘，窄面板下正文的可用宽度也一并回来。markdown 按块补上是同一入口的自然延伸：它恰恰是「让 agent 改这份文档的这一段」最常见的对象，而渲染后没有行号可用。

**独立测试**：点击消息中的文件路径打开文件面板 → 右键某行验证在指针位置弹出「添加评论」→ 点击在行下展开评论框 → 输入评论并添加 → 验证评论连同行号与该行内容追加到消息输入框（不直接发送、面板上不留痕）→ 在另一行重复添加第二条 → 验证两条评论都在输入框中 → 再选中连续若干行、点选区末尾浮出的评论按钮，验证追加内容按行区间（`第 N–M 行`）表达；再把同一面板切到 markdown 文件，悬停某个标题与某个段落验证块外侧出现评论按钮 → 点击在块下展开评论框 → 提交后验证追加内容含文件路径与该块文本片段、且不出现行号；切到图片文件验证不出现任何评论入口。

**验收场景**：

1. **假设**文件面板已打开一个代码/文本文件（非 markdown、非图片），**当**用户在代码区右键某行，**则**在指针位置弹出菜单，其中一项为「添加评论」；点击后在该行下方展开行内评论框（含文本输入框与添加按钮），被评论行保持可见。行号列不为评论按钮预留常驻槽位，行号紧贴面板左缘。
2. **假设**用户在代码区选中连续的若干行文本（跨行选区），**当**松开鼠标，**则**在选区末尾浮出评论按钮（不遮挡被选中的文字，滚动时跟着选区走），点击后按选区首末行展开评论框；选区被清除或点击别处后按钮消失。行号列宽度随该文件实际行数自适应（不按固定位数预留），同一文件内各行宽度一致、正文左缘是一条直线；行数变多时列才随之变宽。
3. **假设**用户不确定右键入口，**当**查看代码区工具条，**则**工具条上有「评论」按钮：点击时若存在选区则评论选区首末行，否则评论最近一次点击（或右键）的那一行；两者都没有时按钮呈不可用态并说明「点击代码行后可在此评论」，而不是点击后毫无反应。
4. **假设**用户在评论框输入评论并点击添加按钮（或回车），**则**不得直接发送给 agent，必须将评论追加到消息输入框中，追加内容包含：文件路径、行号或行区间、该处内容（或片段）、评论文本；输入框已有内容时必须保留并在其后追加；评论框关闭；**不得**在文件面板内留存或回显该评论（无痕，与差异面板一致）；追加文本的标签与差异面板统一为「代码评论」，两个面板共用同一份追加格式，仅位置描述不同（差异面板带增删前缀与行内容片段，文件面板带单侧行号/行区间与行内容片段）。
5. **假设**文件面板打开的是图片，**当**查看该文件，**则**不提供任何评论入口（图片既没有行也没有块），文件本身的只读查看行为不受影响。
6. **假设**评论框已展开，**当**用户按 Esc 或点击取消，**则**评论框关闭且不提交；用户可继续右键或选中其他行添加评论，无需开关任何模式即可连续评论多行。
7. **假设**面板发生文件切换（同一 tab 换路径）、内容刷新、会话/工作目录切换或文件读取失败，**则**展开中的评论框必须关闭、未提交的草稿丢弃，防止行内容变化后界面状态不一致。
8. **假设**文件内容被截断（超过单文件行数上限，只显示前 N 行），**当**用户评论，**则**评论只能落在已显示的行上，行号以面板当前显示的行号为准；截断提示与评论入口共存，不互相遮挡。
9. **假设**文件面板处于空态（未打开文件）、加载中、读取失败或只显示图片，**当**渲染这些状态，**则**不得出现评论入口、评论框或工具条上的「评论」按钮。
10. **假设**文件面板打开的是 markdown 文件，**当**用户鼠标悬停某个块（标题、段落、列表项、引用块、表格单元格、围栏代码块），**则**该块外侧（内容左缘之外）必须出现评论按钮（markdown 没有行号，沿用的是悬停块浮出按钮的形态，不跟随代码区的右键/选区入口）；悬停另一块时按钮跟随到新块，移出内容区则按钮消失，但鼠标从块移向该按钮的整段路径（含两者之间的空隙）上按钮不得消失——否则永远点不到；点击必须在该块**下方**展开同一个行内评论框，块内容保持可见、不被遮挡。提交后追加内容包含文件路径与该块**渲染后的文本**（截断到可读长度）而**不含行号**——渲染块与源行不对应，不得按块反推行号。嵌套时以**最外层块**为准（列表项里的段落、引用块里的标题都归该列表项 / 引用块），同一时刻只存在一个展开中的评论框；应用内连续评论多块、输入框既有内容保留、不在面板留存评论等语义与场景 4/6 完全一致。

## 非目标（明确排除）

- **远端会话的编辑**：远端 SSH 会话的 file 面板继续保持只读（写能力不跨 SSH 桥），要改远端文件仍走 agent 工具或 IDE 的远端能力——对齐 Claude 桌面端「远端会话不可保存」。
- **创作集（artifact）的展示与操作**：artifact 是服务端 URL，本机没有对应文件，故 file 面板不列它；仅当发布它的本地源文件被对话读写过时，才以普通文件出现在清单里。
- **本地会话的 file 面板不替代编辑器**：本地会话的轻量修改由面板内的编辑态承载，但它是「顺手改一处」的入口而非编辑器替代品：多光标、格式化、代码折叠、重构等能力不做，重活仍通过「在默认应用中打开」跳出到外部编辑器/IDE（面板内的「查找与跳行」见「文件面板内查找与跳行」，不含替换）。
- **自动保存**：保存一律是显式动作（工具条「保存」/ Cmd-Ctrl+S），不做输入即落盘的自动保存与后台写盘——写盘时机必须由用户决定，否则会与 agent 的写入、外部编辑器的保存互相踩踏。
- **面板内的文件管理**：不做新建、重命名、删除、移动文件（目录树只读浏览）；面板内的写操作只有「把当前文件的草稿写回该文件」，且只写工作目录内的路径（工作目录之外的路径即便能打开也只读）。
- **多文件同时编辑与草稿持久化**：面板可以同时打开多个文件（各占一个文件标签），但同一时刻只编辑一个文件（切到别的文件即需放弃草稿）；草稿不落盘、不跨重载/重启恢复，不做「每个打开的文件各留一份草稿」的模型。
- **IDE 插件的 file 面板**：VSCE/JetBrains 不提供该面板，其 `openFile` 由 IDE 自身处理（含 IDE 的 Remote-SSH 能力）。
- **语法高亮的语言覆盖**：仅覆盖常用语言子集（highlight.js common 集），未覆盖语言纯文本展示。
- **跨文件全文检索**：目录树与查找条都只服务「浏览与看某一个文件」；不做工作区级的内容搜索（按文件内容在整仓范围内找命中），该需求仍由外部编辑器/IDE 承担。
- **编辑器显示设置**：不提供 word wrap / tab 宽度 / 显示空白字符 / 滚动越界等的可配置项——折行与缩进外观固定（与只读视图一致），需要这些设置请跳出到外部编辑器。
- **符号跳转与大纲**：不做符号列表、跳转定义、引用查找等语言级导航。
