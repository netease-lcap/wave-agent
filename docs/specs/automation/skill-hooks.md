# 功能规格说明：技能级钩子

**创建日期**：2026-11-25

## 用户场景与测试 _（必填）_

### 用户故事：技能自带 hooks，证据采集变成技能的固有动作（优先级：P1）

技能作者希望把「调用这个技能时要顺手做的事」写在技能里，而不是指望模型每次都记得。典型例子是 `/verify`：技能自带的 `PostToolUse` hook（matcher 为 `Bash`）把每次命令与输出抄进证据目录；`/code-review` 自带的 `Stop` hook 跑一次 lint。作者在 `SKILL.md` 的 frontmatter 里用 `hooks` 声明，形状与 `settings.json` 的 `hooks` 完全同形。

**为什么是这个优先级**：没有这条，技能只能在正文里写「记得截图/记得跑 lint」这类劝告，全靠模型自觉；hook 把它变成机制。

**独立测试**：写一个 `SKILL.md`，frontmatter 声明 `hooks.PostToolUse`（matcher `Bash`）指向技能目录里的一个脚本，脚本把 stdin 落盘。调用该技能后随便跑一次 Bash，检查落盘文件里有该次调用的 JSON 输入；对照组（不调用技能）确认脚本不执行。

**验收场景**：

1. **假设**技能 `demo` 的 `SKILL.md` 声明了 `hooks.PostToolUse`（matcher `Bash`），**当**用户调用 `/demo` 之后发生一次 Bash 工具调用，**则**该 hook 被执行，且它收到的 JSON 输入里 `hook_event_name` 为 `PostToolUse`、`tool_name` 为 `Bash`
2. **假设**技能从未在本会话被调用过，**当**发生任何工具调用时，**则**该技能的 hooks 不执行
3. **假设**hook 的 `command` 里用了 `${WAVE_SKILL_DIR}` 占位符，**当**hook 执行时，**则**占位符已替换为该技能目录的绝对路径（与技能正文、`allowed-tools` 用同一套替换规则）
4. **假设**技能的 `hooks` 字段**结构**不合法（不是对象 / 事件名不合法 / 条目缺 `command` / 占位符解析不了），**当**该技能被加载时，**则**技能本身照常可用（正文能调用），只是不合法的那部分 hook 不注册，并给出可见提示（`warnings`）。**YAML 语法**错误则整块 frontmatter 失效、技能判为无效——真解析器是全有或全无，这一条不为了保住 hooks 去抢救半块 YAML

### 用户故事：会话级生效，重复调用不叠加（优先级：P1）

技能被调用后，它的 hooks 在**本会话剩下的时间里**继续生效；同一技能被重复调用不会把 hook 注册两遍。换到另一个会话不带过去。

**为什么是这个优先级**：这是与参照物（Claude Code 2.1.325）对齐的那条决策——它没有「技能跑完就撤」的路径，撤下只有三条：`once` 执行成功、技能消失、会话结束。做回合级撤回要先定义「技能跑完」的边界（`context: fork` 子代理、用户中断、一次技能跨多轮），成本远高于收益；一次性需求由 hook 的 `once: true` 覆盖。

**独立测试**：调用一次声明了 `PostToolUse` hook 的技能，在后续**多个**回合里各跑一次 Bash，确认 hook 每次都执行；再把同一个技能调用第二次，确认注册表里该 `matcher + skillRoot` 只有一份、hook 只执行一次；最后新建会话，确认不执行。

**验收场景**：

1. **假设**技能已在本会话被调用过，**当**之后某一轮无关对话里发生匹配的工具调用，**则**该技能的 hook 仍然执行（会话级，不随回合结束失效）
2. **假设**同一技能在同一会话内被调用两次，**当**第二次调用完成时，**则**注册表里该 `matcher + 技能` 组合只有一份，后续匹配只执行一次
3. **假设**用户新建会话（或恢复另一个会话），**当**发生匹配的工具调用时，**则**上一个会话注册的技能 hooks 不执行（注册表按会话隔离）
4. **假设**技能 hook 声明了 `once: true`，**当**它成功执行一次之后，**则**后续匹配不再触发它，且它在注册表里已被移除；此后技能热更新或设置重载触发的重新注册不得让它复活
5. **假设**作者在会话进行中改掉了该 `once` hook 的命令文本，**当**技能重新加载后匹配再次发生，**则**改过的命令按一条新 hook 执行一次（已执行的身份按「来源 + 事件 + matcher + 命令文本」记）
6. **假设**注册时传入的是另一个会话的 sessionId，**当**在当前会话发生工具调用时，**则**那条注册不参与匹配（作用域就是注册时所在的 sessionId）

### 用户故事：来源可追溯，跨来源不合并（优先级：P1）

hook 失败时用户看到的提示要能说清「这条来自哪个技能」；同一条 hook 同时出现在 `settings.json` 和技能里时，两条都执行，不做跨来源去重。

**为什么是这个优先级**：来源是用户判断「这个 hook 该不该放行」的唯一依据；而把 `settings` 的一条和技能的一条悄悄合并成一条，会让作者以为自己的 hook 生效了、实际跑的是另一份配置。

**独立测试**：在 `settings.json` 与某技能的 frontmatter 里写**内容完全相同**的 `PostToolUse` hook（同一条命令、同 matcher），跑一次匹配的工具调用，确认命令被执行两次；技能那条失败时的用户可见提示带 `skill:<技能名>` 前缀，`settings` 那条不带前缀（默认来源不标注）；然后在技能里重复写两条相同 hook，确认只执行一次。

**验收场景**：

1. **假设** `settings.json` 与技能声明了内容完全相同的 hook，**当**匹配的工具调用完成时，**则**两条都执行（跨来源不合并）；技能那条失败时，用户可见的错误提示带 `skill:<技能名>` 前缀
2. **假设**同一个技能的 `hooks` 里重复写了内容相同的 hook，**当**匹配的工具调用完成时，**则**只执行一次（同来源内去重）
3. **假设** `settings.json` 与技能都对同一事件声明了 hook，**当**该事件发生时，**则**执行顺序按来源拼接顺序（settings 在前、技能在后），而不是随机或按字母序
4. **假设**某条 hook 来自技能 `demo` 且执行失败，**当**查看用户可见的错误提示时，**则**提示带 `[skill:demo]` 前缀，且该名字按纯文本展示（不当 Markdown、不做链接、不因它改变提示的措辞）；模型侧的错误文本保持与 Claude Code 逐字一致（不因来源前缀改措辞）

### 用户故事：每来源预算，超限时可见且不静默降级（优先级：P2）

一个来源（技能）在一次会话里能注册的 hook 数量与 matcher 总字符数有上限。超限时这些 hooks 一条都不注册、该技能的 `allowed-tools` 授权也不生效，并且要告诉模型发生了什么——因为如果技能靠 hook 做拦截，现在等于没拦。

**为什么是这个优先级**：这是参照物的硬约束（每来源每会话 1024 条 hook / 16384 字符 matcher），防的是「技能把自己的 hooks 写爆内存/拖慢每次工具调用」。超限必须可见：静默少注册会让用户以为拦截还在。

**独立测试**：构造一个声明了超过上限条数（或 matcher 总字符超限）hook 的技能，调用它，确认 hook 一条都没执行、`allowed-tools` 放行的命令仍然要用户确认，且模型收到了那句说明。

**验收场景**：

1. **假设**某技能的 hooks 合计超过每来源上限（1024 条，或 matcher 总字符超过 16384），**当**该技能被调用时，**则**这些 hooks 一条都不注册，该技能的 `allowed-tools` 也不生效
2. **假设**发生了上述超限，**当**技能调用完成后，**则**模型收到一句说明（原因、hooks 未注册、工具授权未授予），并要求它告诉用户
3. **假设** hooks 未超限，**当**技能被调用时，**则**hooks 正常注册、`allowed-tools` 正常生效（对照组，避免把预算做成常态降级）

## 边界情况

- **撤下的三条路径只有这些**：`once: true` 执行成功；技能从磁盘/清单消失（含热更新删除）；会话结束。不按回合撤下。
- **技能热更新**：重塑后按 `skillRoot` 重建这份注册，旧条目不得残留（用注册表快照断言）。
- **只读/预加载的技能不注册 hooks**：技能内容被预载（没真正被用户或模型调用）时，只有正文进上下文，hooks 不注册。
- **删除/禁用技能不执行它的 hooks**：注册表中的条目随技能消失清理，之后的工具调用不再命中。
- **与 `SessionStart` / `SessionEnd` 互不影响**：会话生命周期钩子不走技能注册表（见 `session-hooks.md`），两条链路各自独立。
- **hook 的语义沿用 `settings.json` 的那一套**（退出码、stdout 约定、`async` / `asyncRewake` / `timeout`），本规格不新增 hook 类型，只新增「来源」维度与生命周期；唯一的语义增补是 `once: true`——成功执行一次后从所属来源撤下该条（我方此前没有这个字段，本次与技能 hooks 一起落地，对所有来源生效）。**`once` 是按会话算一次**：执行成功的记录按「来源 + 事件 + matcher + 命令文本」记在会话内存里，重新注册（技能热更新、设置重载）不得让它复活；作者改过命令文本就是一条尚未执行过的新 hook；新会话从头开始（不落盘）。过滤发生在所有来源合并的那一处，因此每条重新注册的路径自动被覆盖。
- **来源名不可信**：技能名来自技能作者，展示时按纯文本处理（不转 Markdown、不拼 URL、不因为它隐藏或改写提示）。
- **不做来源优先级**：`settings` / 技能之间没有「谁覆盖谁」，只有拼接顺序与上面第 1 条的去重规则。

## 非目标

- 不做回合级撤下（见「用户故事：会话级生效」里的理由）。
- 不做插件清单级的 hooks（插件自己声明 hooks 是另一件事，另案）。
- 不给技能 hooks 任何优先级/覆盖语义。

### 测试验证需求

- 必须用**真实文件系统**的集成测试：技能目录里放一个把 stdin 落盘的 hook 脚本，调用技能后跑一次 Bash，断言文件里出现该次调用；对照组（技能未调用）断言文件不存在。
- 必须断言「后续回合仍然生效」（会话级）与「换会话不生效」两件事，而不是只测调用当轮。
- 必须断言幂等：同一技能调用两次后，注册表里该 `matcher + 技能` 只有一份，且 hook 只执行一次。
- 必须断言跨来源重复会执行两次、同来源重复只执行一次（用计数而非只判有无）。
- 必须断言来源拼接顺序（settings 在技能之前），用两个各写一行日志的 hook 验证先后。
- 必须断言预算边界：恰好等于上限可注册，超一条即全部不注册；并断言 `allowed-tools` 同时失效、说明文本进入模型上下文。
- 必须断言技能删除/热更新后注册表无残留（直接读注册表快照，不只看行为）。
